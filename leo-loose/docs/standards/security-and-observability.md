# 权限、日志与追踪

性质：认证拦截器、权限注解、日志切面和独立日志执行器为实践提炼；完整覆盖与追踪链路为建议基线。

## 认证与授权分开

认证确定调用者，功能授权判断能否执行动作，数据授权判断能否访问指定对象或范围。登录成功不自动获得所有操作权限。

受保护接口必须明确权限；公开接口进入显式清单并说明理由。跨对象读取、修改、附件访问和导出均校验数据范围。列表过滤与按 ID 访问采用一致策略。

客户端权限只用于交互。服务端使用可信身份上下文，不能接受客户端提供的用户 ID 作为授权依据。内部任务以明确的系统身份执行；公共服务不应隐式依赖一定存在 HTTP 会话。

空实现的权限检查视为未实现。自动检查可以发现遗漏声明，集成测试需要证明允许与拒绝的行为都正确。

## 审计与诊断日志

| 类型 | 目的 | 典型信息 |
|---|---|---|
| 审计日志 | 追溯谁对什么做了什么 | 操作者、动作、对象标识、结果、时间 |
| 应用诊断日志 | 定位故障与性能问题 | requestId、异常、耗时、依赖调用结果 |
| 安全事件 | 识别异常访问与权限变化 | 身份、来源、拒绝原因、配置变更 |

公共日志能力接收结构化上下文，避免通过跨模块 SQL 猜测对象归属。记录成功的时机应符合事务提交结果；审计失败是否阻断操作，由项目对相应操作的要求确定。

日志参数采用允许字段清单或明确过滤；不记录密码、访问令牌、连接密钥或完整敏感文档。异常响应不暴露 SQL、内部路径和堆栈。

异步日志执行器需要队列上限、饱和策略与失败监控。CallerRuns 类策略会增加请求耗时，也不能保证进程崩溃时日志不丢失；高可靠审计需另行设计持久化保障。

## 三类关联标识

- requestId：一次 HTTP 请求的关联标识，在入口建立并随响应返回。
- traceId：一次分布式或异步调用链的追踪标识，在启用追踪机制时按其协议传播。
- correlationId / objectId：应用对象或长流程关联标识，可以贯穿多次请求。

不要让一个字段同时承担上述三种不同生命周期。

入口过滤器负责上下文建立和 finally 清理；异步执行显式传递必要上下文；下游调用按选定协议传播。接收外部提供的标识时限制长度和字符，避免日志污染。

## 可观测性最小集合

新项目至少能够回答：服务是否可用、哪些接口失败、耗时在哪里、数据库连接池是否饱和、后台工作是否积压。按实际运行模式选择健康检查、指标和告警。

健康检查区分进程存活与可接流量。高基数字段如用户 ID、对象 ID 不用作无界指标标签。日志保存期限、访问范围与删除方式写入项目约定。

## 验证

覆盖未登录、缺功能权限、缺对象权限、系统任务身份等场景。验证正常和异常请求都能关联日志、线程复用时上下文不串号、异步日志不携带敏感字段。基础能力故障时，响应和告警符合事先约定。
