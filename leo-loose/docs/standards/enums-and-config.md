# 枚举、字典与配置

性质：集中枚举、命名成员、展示元数据与增量门禁为实践提炼；跨端同步和配置生命周期为建议基线。

## 先选择正确的表达方式

| 表达 | 适用情况 | 维护方式 |
|---|---|---|
| 枚举 | 代码需要穷举、具有固定语义的值集合 | 随代码审查与发布 |
| 字典 | 用户可维护的选项和标签 | 管理接口、权限和变更记录 |
| 配置 | 控制系统行为的参数 | 类型校验、默认值、作用范围与生效策略 |

固定代码语义不能因字典改名而变化。字典标签不作为判断条件；配置也不应绕过系统必须保持的约束。

## 枚举的唯一声明

推荐同时提供命名成员、稳定值和展示元数据。以下仅是通用结构示意：

```ts
const ResourceState = {
  ENABLED: { value: 'enabled', label: '启用', tone: 'positive' },
  DISABLED: { value: 'disabled', label: '停用', tone: 'neutral' },
} as const

type ResourceStateValue =
  (typeof ResourceState)[keyof typeof ResourceState]['value']
```

判断使用命名成员，选择器和标签从同一声明生成。tone 映射到 UI 库样式放在展示适配层；不要让纯协议类型依赖 UI 库。

枚举工具可提供 getLabel、getOptions、isKnownValue 等。成员存在性检查不能命名成容易被误解为操作授权的 canDo；可否执行动作需要独立判定。

未知值的读展示提供可识别兜底，写入未知值应拒绝。显示兜底不能把未知值转换成一个合法状态。

## 前后端同步

确定一个协议值真源，通过生成或契约测试同步两端。前端可以维护本地化文本和样式，但不能自行改变协议值。来源系统已有前后端枚举，不代表已实现自动同步。

值的删除或语义变化要检查历史数据、外部客户端和持久化约束。不能仅改 UI 标签就声称完成状态迁移。

## 字典与配置的生命周期

字典采用稳定代码与可变标签分离；缓存按字典键管理，并明确主动失效、版本刷新或有效期。禁用选项时说明历史数据如何展示。

每项配置登记键、类型、默认值、校验范围、作用域、生效时机和是否敏感。敏感配置不进入前端或日志。缺失或非法配置按事先约定报错或使用安全默认值，不能静默接受任意字符串。

多实例环境下，本地事件只能刷新当前实例。配置传播与缓存失效需要符合实际部署方式；单实例项目可先使用简单方案。

## 自动门禁

- 检查命名成员使用、重复映射和协议值漂移。
- 存量项目可登记经审核的基线，只允许减少；新项目从零违规开始。
- 迁移和专用测试夹具的字面量例外应按目录或明确标记处理。
- 修改检查器时增加能证明误报修复或漏报修复的用例，不通过扩大基线消除失败。
