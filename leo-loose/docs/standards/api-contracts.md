# API 与类型契约

性质：统一响应、分页、集中请求处理为实践提炼；以下完整契约为建议基线。

## 输入、输出与持久化分离

- Request DTO 只包含客户端允许提交的字段，并声明必填、长度、格式和数量范围。
- Response VO 只包含客户端需要的字段；不直接暴露持久化实体、内部标记或凭据。
- Entity 表示持久化模型；字段变化不应自动成为 API 变化。
- 固定结构不使用任意 Map 或 any。扩展字段必须说明允许键、值类型、大小限制和版本策略。
- 校验器只校验其明确职责。结构格式校验与需要事务保护的状态校验分别安排。

DTO / VO 的价值是稳定边界，转换可以使用显式函数或映射工具；简单字段不必制造复杂转换框架。

## 推荐响应示例

以下是新项目可选的统一方案，采用时在项目约定中确认：

```json
{
  "code": "OK",
  "message": "操作成功",
  "data": { "id": "1234567890123456789" },
  "requestId": "example-request-id"
}
```

```json
{
  "code": "VALIDATION_FAILED",
  "message": "参数不符合要求",
  "data": null,
  "requestId": "example-request-id",
  "errors": [{ "field": "name", "code": "REQUIRED", "message": "不能为空" }]
}
```

业务错误码使用稳定符号，界面不能通过匹配 message 文案判断逻辑。内部异常细节留在服务端日志，响应提供安全提示和可查询的 requestId。

| HTTP 状态 | 用途 |
|---|---|
| 200 / 201 | 请求已成功完成；201 用于创建资源 |
| 202 | 已接收但尚未完成，需返回可查询的操作标识 |
| 400 | 参数或请求格式错误 |
| 401 / 403 | 未认证 / 权限不足 |
| 404 | 资源不存在，或按已确定策略隐藏其存在性 |
| 409 | 状态、版本或幂等键冲突 |
| 429 | 请求受到限流，可说明重试等待时间 |
| 500 / 503 | 内部错误 / 服务暂时不可用 |

文件下载、流式响应和无响应体接口单独声明，不强制塞入 JSON 包装。JSON 接口必须保持声明与真实响应一致。来源系统的数值 code 与上述符号方案不同，不能未经适配直接混用。

## 数据表示

- 标识符：默认以字符串传输，避免 JavaScript 大整数精度损失；算法用数字还是字符串由内部实现决定。
- 精确小数：需要精确语义的量以十进制字符串传输，并定义精度、舍入方式与边界。
- 时间点：明确时区，建议使用带时区的 ISO 8601；纯日期使用 YYYY-MM-DD，不能隐式转换为午夜时间点。
- 缺失、null、空字符串与空数组分别定义。PATCH 中“未传不改”与“传 null 清空”必须写入契约。
- 分页：统一 pageNum、pageSize、records、total；服务端限制单页上限，并对排序字段使用白名单。
- 列表排序包含稳定的次排序键，避免相同主排序值导致翻页不稳定。大规模列表可另行选择游标分页。

## 客户端与兼容性

选择一个权威接口定义源：服务端声明生成 OpenAPI，或契约文件驱动两端实现。类型生成方式、产物是否入库、生成检查命令在新项目确认。生成客户端不能替代运行时验证。

集中客户端负责认证头、超时、错误转换、requestId 和响应解包；是否解包必须在全项目统一。错误提示由约定的一层负责，避免重复弹窗。不同请求可声明超时等级，不依赖 URL 字符串猜测接口耗时。

新增字段要保持兼容；删除、改名、改变类型或含义需制定迁移窗口。重复提交与写接口重试遵循[事务与副作用标准](transactions-and-effects.md)。

## 验证

选取代表性接口验证真实 HTTP 状态、响应结构、非法参数、权限拒绝、分页边界和大整数 ID。CI 比较契约与客户端生成产物，发现不兼容变更需明确批准。
