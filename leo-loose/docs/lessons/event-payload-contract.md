# 事件 payload 必须有稳定契约

来源任务：`dev-20260930-028`。证据状态：已交付待复核。类别：接口／事件。

## 现象

本地事件监听器按事件名条件匹配，但发布的 Map 没有携带事件名，导致监听器静默不执行。外层业务可以成功提交，后续联动没有发生。

## 根因与遗漏

事件名称只存在于发布方法参数，payload 没有强制结构；监听器条件依赖字符串，编译器无法发现缺字段。原有测试验证了发布调用，却没有验证真实 payload 能命中监听条件。

## 处理与原则

事件应有稳定的事件类型和 payload 契约。发布端、监听端和测试使用同一契约；关键字段缺失应在发布或消费边界明确失败。事件测试至少验证：事件名称、关键字段、不可变输入、监听器实际命中。

## 自动检查与边界

可以用强类型事件对象、schema 或契约测试实现。Map 不是绝对禁止，但使用 Map 时必须有字段校验和覆盖所有消费者的测试。事件契约解决消息形状，不自动解决投递可靠性；可靠性见[联动失败不能只靠日志](side-effect-recovery.md)。

来源业务事件名和单据字段不应复制到新项目。
