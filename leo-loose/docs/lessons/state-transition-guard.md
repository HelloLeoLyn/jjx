# 状态动作必须同时保护上下文与版本

来源任务：`dev-20260827-009`。证据状态：已完成。类别：并发／状态。

## 现象

子对象可以进入执行状态，但所属父对象仍处在不允许执行的阶段；不同入口对状态的判断不一致，导致流程顺序被绕过。

## 根因与遗漏

动作只检查了当前行的状态，没有把父子上下文、允许动作和并发版本放在同一个服务端入口校验。页面按钮状态不能保证直接 API 调用的安全。

## 处理与原则

状态字段不是完整状态机。每个动作应声明前置状态、主体范围、父子上下文、版本条件和副作用；服务端在事务中重读并校验，条件更新检查影响行数。前端枚举只用于展示和交互提示。

## 自动检查与边界

为状态动作建立转移表和正反例测试，覆盖旧版本、重复点击、直接 API、父对象不匹配和并发冲突。简单资源可以省略复杂状态机，但不能省略服务端前置条件。
