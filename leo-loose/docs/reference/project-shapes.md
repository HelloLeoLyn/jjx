# 项目类型与标准选用矩阵

性质：建议基线。复用工程方法，同时尊重不同项目的自然结构。

所有项目都明确目标与边界、公开输入输出、错误与配置、依赖方向、验证命令和授权。语言、数据库、界面与部署单元不预设。

| 项目 | 最小职责结构示意 | 按需采用 | 通常无需先建 |
|---|---|---|---|
| Web 全栈 | 前端、服务端、测试、文档 | HTTP、组件、权限、持久化 | 微服务和消息平台 |
| 独立 API | 源码、契约、测试、文档 | 参数响应、授权、可观测性 | 前端组件库 |
| CLI / 自动化 | 入口、核心、适配、测试 | 参数、退出码、幂等 | Controller/Service/Mapper 三层 |
| 库 / SDK | 包源码、测试、示例、文档 | 公共 API、兼容、打包 | 数据库和登录模块 |
| 桌面 / 移动端 | 界面、核心、平台适配、测试 | UI 状态、平台权限、离线数据 | 独立服务端 |
| 数据处理 | 转换、配置、样本夹具、测试 | 输入模式、可重复性、恢复 | 在线 HTTP 服务 |

实际目录名遵循语言与框架；单文件工具也可满足工程要求，复杂度随实际需求增长。

## 裁剪原则

API 标准的 HTTP 和分页仅用于网络接口；库与 CLI 采用公开函数或命令契约。前端标准用于有交互界面的项目。数据库事务只用于持久化操作，外部副作用原则同样适用于脚本工具。

权限按实际信任边界选择，不给纯函数库增加登录。枚举示例可换语言，唯一声明与校验原则保留。

共享稳定方法，不共享环境事实。每个项目独立维护工具版本、命令、数据策略和发布方式。公共代码只有在多个项目语义一致且维护边界明确时，才提炼为版本化公共包。
