📦 产品(成品)库存需求定义

2026-08-04 定 · 业务规则：HelloLeoLyn · 梳理补充：大黄 · 关联任务：DEV-576 / DEV-572

一、业务规则

客户下产品订单 → 优先考虑库存：有库存先发库存，不够的部分再生产（先库存后生产，MTS/MTO 混合）

二、核心流程

订单确认(CONFIRMED, 4→6) └─ 按订单产品明细逐行检查成品可用库存 ├─ 库存充足 → 该行锁定库存，直接发货 ├─ 库存不足 → 拆成两部分： │ ① 库存部分：锁定并直接发货 │ ② 缺货部分(订单量-库存量) → 进生产 └─ 无库存档案/新产品 → 视为 0 库存，全量生产

关键：生产工单数量 = 缺货数量（不是整单数量）

全库存满足 → 不生成生产工单，直接发货

三、库存处理规则

  • 预留：订单确认时锁定库存（reserved+），防止被其他订单抢走，先到先得
  • 取消：订单取消 → 释放预留库存
  • 扣减：发货出库确认时扣减库存，预留同步释放
  • 补充：生产完成 → 自动成品入库，补回库存

四、两层预警

层级检查内容输出任务
第一层成品库存够不够决定生产数量（缺货量）DEV-576 方案落地后
第二层需生产部分的原材料够不够order_shortage 缺料预警 → 触发采购DEV-572（已登记）

提示销售：哪些产品有现货、哪些要生产、原材料是否够

五、状态流转

  • 全库存满足 确认后跳过生产，直接发货
  • 部分/全缺货 确认 → 开始生产（缺货量）→ 生产完成入库 → 发货

六、边界

  • 样品单：不查库存（打样流程）
  • 多订单抢同一产品库存：按确认时间先到先得（预留机制）
  • 库存不足：销售需告知客户交期（参考生产周期 lead_time）

七、方案选型：成品库存怎么建（A vs B）

现状：库存体系（inventory_stock + 入库/出库/盘点/转移全部单据）按 material_id 跑，产品表 product 与物料体系完全独立，无关联字段。

方案 A：产品建物料档案（✅ 已选定 2026-08-04）

  • 产品发布时自动在 inventory_material 建一条记录（material_type 新增 P=成品，产品编码即物料编码）
  • 库存表/单据/扣减逻辑/预警/报表 全部复用现有体系，几乎零改动
  • ✅ 改动小、体系统一、预警/报表/盘点全自动支持
  • ⚠️ 产品↔物料双写同步（改名/停用需同步）；物料列表会被成品“污染”（选择器需按类型过滤）；物料字段（规格/供应商）对产品意义不大
  • 工作量：小（发布联动 + 选择器过滤）

方案 B：库存表支持 product_id 双维度（❌ 未选）

  • inventory_stock + 4~5 张单据明细表加 product_id 列（与 material_id 二选一）
  • 后端库存增减逻辑按维度分支；前端物料选择器支持选产品
  • ✅ 语义清晰、产品和物料完全独立、无同步问题
  • ⚠️ 改动面大：表结构 + 后端逻辑 + 前端选择器全部改造，现有代码大量按 material_id 写死
  • 工作量：大
对比项方案A 产品建物料方案B 库存双维度
改动范围小（发布联动+过滤）大（表+后端+前端全改）
数据一致性需双写同步天然一致
体系复用全部复用需扩展
灵活性够用更高
风险低中

⚠️ 业务提醒：薄膜开关以按单生产（MTO）为主，成品库存价值有限，主要服务于标准品/常备品。方案A 成本低、随时可加，已定为首选。

八、决策拍板结果（2026-08-04）

决策点结论
1. 方案选型方案A：产品建物料档案（material_type 新增 P=成品，产品编码即物料编码，库存体系全复用）
2. 订单明细行拆分展示不用：界面不拆两列展示（库存满足数/需生产数），内部仍按缺货量生成生产工单
3. 全库存满足订单流转手动确认：确认后仍需手动操作进入发货流程，不自动跳转
4. 生产完成入库触发点成品入库单：生产工单完成 → 自动生成成品入库单（走入库流程）
5. 预留机制要做：订单确认时预留库存（reserved+），取消释放，出库扣减同步释放
