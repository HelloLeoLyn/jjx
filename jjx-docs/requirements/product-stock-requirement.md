# 产品(成品)库存需求定义

> 2026-08-04 由 HelloLeoLyn 提出业务规则，大黄梳理补充
> 关联任务：DEV-576（需求分析）、DEV-572（订单齐套检查）

## 一、业务规则（用户原话）

> **如果客户有下这个产品订单，优先考虑库存。**
> 有库存 → 先发库存；库存不够的部分 → 再生产。

即 **先库存后生产（MTS/MTO 混合）**：
- 订单确认时按产品检查**成品库存**
- 库存充足 → 订单由库存满足，直接走发货
- 库存不足 → 不足部分进入生产流程，补足后发货

## 二、需求全貌（大黄补充）

### 1. 成品库存建档（前置）
- 产品发布时自动同步建立库存档案（方案A：产品建物料档案，material_type=P 成品）
- 库存体系（inventory_stock + 入库/出库/盘点/转移）全复用
- product_id ↔ material_id 建立映射（方案细节由 DEV-576 分析拍板）

### 2. 订单确认时的库存处理（核心流程）
```
订单确认(CONFIRMED, 4→6)
  └─ 按订单产品明细逐行检查成品可用库存(available_quantity)
      ├─ 库存充足 → 该行「库存满足」，预留库存(reserved + 数量)
      ├─ 库存不足 → 该行拆为两部分：
      │    ① 库存部分：预留并直接发货
      │    ② 缺货部分：数量 = 订单量 - 库存量 → 进入生产
      └─ 无库存档案/新发布产品 → 视为 0 库存，全量生产
```

### 3. 生产数量规则（关键变化）
- **生产工单数量 = 缺货数量**（不是整单数量！）
- 全库存满足的订单行 → 不生成生产工单
- 部分满足 → 工单只生产缺货部分
- 全部缺货 → 工单 = 整单数量（现状行为）

### 4. 库存预留与扣减
- 订单确认时预留（reserved+）：防止其他订单抢库存（先到先得）
- 订单取消 → 释放预留
- 发货单生成/出库确认 → 实际扣减（total-），预留同步释放

### 5. 两层预警（与 DEV-572 衔接）
- **第一层：成品库存检查** → 订单确认时自动判断，缺货部分数量确定
- **第二层：原材料齐套检查**（DEV-572）→ 对「缺货需生产的数量」按 BOM 算料，原材料不足 → order_shortage 预警 → 触发采购
- 提示销售：哪些产品有现货、哪些要生产、原材料是否够

### 6. 状态流转影响
- 全库存满足订单：确认后可跳过生产，直接发货（SHIPPED）
- 部分/全缺货：确认 → 开始生产（生产缺货量）→ 生产完成入库 → 发货
- 生产完成 → **自动成品入库**（补库存，支持后续订单）

### 7. 边界
- 样品单：不查库存（打样流程）
- 多个订单抢库存：按确认时间先到先得（预留机制）
- 库存不足：销售需告知客户交期（生产周期 lead_time）

## 三、决策拍板结果（2026-08-04）
1. 方案选型：**方案A 产品建物料档案**（material_type 新增 P=成品，产品编码即物料编码，库存体系全复用）
2. 订单明细行拆分展示：**不用**（界面不拆两列，内部仍按缺货量生成生产工单）
3. 全库存满足订单流转：**手动确认**（确认后仍需手动操作进入发货流程，不自动跳转）
4. 生产完成入库触发点：**成品入库单**（工单完成 → 自动生成成品入库单，走入库流程）
5. 预留机制：**要做**（订单确认时预留 reserved+，取消释放，出库扣减同步释放）

## 三.5、方案选型（A vs B）

### 方案 A：产品建物料档案（✅ 已选定 2026-08-04）
- 产品发布时自动在 inventory_material 建一条记录（material_type 新增 P=成品，产品编码即物料编码）
- 库存表/单据/扣减逻辑/预警/报表全部复用现有体系，几乎零改动
- ✅ 改动小、体系统一、预警/报表/盘点全自动支持
- ⚠️ 产品↔物料双写同步（改名/停用需同步）；物料列表会被成品“污染”（选择器需按类型过滤）；物料字段对产品意义不大
- 工作量：小（发布联动 + 选择器过滤）

### 方案 B：库存表支持 product_id 双维度（❌ 未选）
- inventory_stock + 4~5 张单据明细表加 product_id 列（与 material_id 二选一）
- 后端库存增减逻辑按维度分支；前端物料选择器支持选产品
- ✅ 语义清晰、产品和物料完全独立、无同步问题
- ⚠️ 改动面大：表结构 + 后端逻辑 + 前端选择器全部改造，现有代码大量按 material_id 写死
- 工作量：大

| 对比项 | 方案A 产品建物料 | 方案B 库存双维度 |
|---|---|---|
| 改动范围 | 小（发布联动+过滤） | 大（表+后端+前端全改） |
| 数据一致性 | 需双写同步 | 天然一致 |
| 体系复用 | 全部复用 | 需扩展 |
| 灵活性 | 够用 | 更高 |
| 风险 | 低 | 中 |

⚠️ 业务提醒：薄膜开关以按单生产（MTO）为主，成品库存价值有限，主要服务于标准品/常备品。方案A 成本低、随时可加，已定为首选。
