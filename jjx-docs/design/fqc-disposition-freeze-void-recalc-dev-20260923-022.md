## 2. 业内口径

1. **处置结论=一次性使用决策（UD）**：做出后冻结；要改只能"撤销/重置"，且需**权限 + 原因 + 审计**（SAP QM）；
2. **批被后继版本取代 → 该批一切未完成动作随之失效**（未完成处置不得再生效）；
3. **数量守恒**：任何影响"有效批集合/有效合格"的变化，都必须**同步重算下游口径**（工单完工、入库净额）；
4. 违规动作要**挡在入口**（fail-closed），而不是事后对账发现。

## 10. 【提案·待拍板】完成度与状态解耦（A+）—— 消灭「重开」（2026-09-24）

> 任务：dev-20260924-012｜提案人：大黄(OpenClaw)｜状态：**待拍板，未实施**
> 性质：**只提案，不改本文任何已实现口径**（§1–§9 全部保持现状）。若采纳，需与 022 实施者**一次性替换，不留两套**。
> 来源：2026-09-24 11:44–11:51 与 Leo 的讨论（"不能为不合理买单" → "业内怎么做" → "哪个更合理"）。

### 10.1 问题（现状证据）

| 证据 | 位置 |
|---|---|
| CLOSED 由系统**自动**到达（判定 + 入库齐 + 处置齐） | `QualityLotServiceImpl.closeIfSettled()` |
| 批动作表：JUDGED→只有复检；**CLOSED→只有重开** | `AllowedActionResolver.forLot()` |
| 纠错要**两级台阶**：CLOSED→(重开)→JUDGED→(复检) | `LotWorkbench.vue:150-159`；`ncr/index.vue` 撤销弹窗提示「若批已结，需先「重开」」 |
| 本文 §9 末句已把「先重开再复检」写进口径 | 本文 §9「残留（下一步）」 |

**根因一句话**：**拿「不可逆的状态」表达「会变的完成度」**。完成度（数量收齐）会被复检换代 / 红冲 / 补产改回去，一旦写成终态，就必然要配一个反向动作 —— 于是长出「重开」，再长出「先重开再撤销」。

### 10.2 业内口径（依据）

1. **审核 ↔ 反审核**是成对的一等动作（金蝶/用友全系：反审核/弃审、结账↔反结账、关账↔反关账、生产订单结案↔反结案）；**系统不会「你什么都没做，它自己审了」**。
2. **SAP QM**：使用决策（UD）做出即冻结，要改只能**重置 UD** —— 这是**一个动作**（带权限 + 变更历史），不是一个状态台阶；批的 `CLOSD` 属收尾/归档性质，不是业务动作总闸。
3. **ISA-88 / ISA-95**：批状态转移都是**显式命令**（start/stop/abort/clear），控制器不会自动把批推进到不可逆终态；要重来是「重新下发一个批」。
4. **合规**：ISO 9001:2015 §8.7（处置动作固定 + 授权批准 + 留记录）—— 与本仓库 `-045` 总方案所引一致。

### 10.3 A+ 方案（三条）

| # | 做法 | 落点（若采纳） | 效果 |
|---|---|---|---|
| ① | **完成度派生化**：收齐 → 派生字段（如 `settled` / `inboundComplete`），只驱动「待结案」提示与统计，**不阻断任何业务动作** | 批列表/详情展示；`closeIfSettled` 退化为「置派生标记」 | 数量怎么变都不再需要动状态机 |
| ② | **结案显式化 + 系统提醒**：收齐后系统生成「待结案」待办/角标，人**一键结案**（谁结谁负责，留痕） | 新动作 `LOT_CLOSE`（权限点归属待定） | 既没有「系统替人做决定」，也不指望人自己想起来 |
| ③ | **复检自带「退结案」**：批只要是最新版本且无未处置不良即允许复检；若已结案，复检**自动退回判定态 + 留痕** | `LOT_REINSPECT` 守卫内隐式回退 | **用户永远只做一个动作 →「重开」消失** |

**目标状态机（改前 → 改后）**

| 状态 | 现在允许的动作 | 采纳 A+ 后 |
|---|---|---|
| PENDING / INSPECTING | 录入、判定 | 不变 |
| JUDGED | 复检 | 复检、**结案** |
| CLOSED | **只有重开** | 复检（自动退结案）、撤销结案（受控） |
| 已被新版本取代 | 无（只读） | 不变 |
| 有未处置不良 | 无（去不良台账） | 不变 |
