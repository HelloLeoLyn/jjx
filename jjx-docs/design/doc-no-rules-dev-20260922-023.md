## 0. 结论先行

1. 现状是**四套规则混用**：号段服务（配置驱动）／手写拼装／时间戳拼号／复用他单号。
2. 最该修的三处：**工单号两套并存**、**时间戳式单号（IQC 四处置 + CAPA）**、**采购入库单号 = 采购单号**。
3. 合规面：业内 8 条原则里我们**已满足 4 条半**（唯一约束、单调递增、不重用、可配置重置），缺的是**定长统一、统一服务生成、前缀登记、无语义冗余**——本文正是补这四条。
4. 用户口径（3 位流水 + 溢出进位）在业内属"可变长"的少数派，**可采用**，但必须配三条约束（见 §5.3），否则会破坏"按号排序≈按时间排序"。

## 2. 七个不满意点（按严重度）

1. **工单号两套并存**：`WPO260922001`（转量产路径）与 `WO-PL2609220001-01`（订单流转路径）——同一条链两种工单号。
2. **时间戳当单号**：IQC 四类处置单（IQD/IQR/IQW/IQS + 17 位）与 CAPA（毫秒取模）→ 超长、不可读、非号段。
3. **日期格式混用**：yyMMdd（SO/QT/PL/WR…）vs yyyyMMdd（PO/IN/OUT/PROD）。
4. **流水位数混用**：3（SO/SP/DL/RTN/WPO）／4（多数）／5~6（客户/物料/供应商）。
5. **前缀风格混用**：纯前缀 vs 带横线（WR-、WO-、PICK-、FINISH-、BATCH-）。
6. **配置形同虚设**：`biz_no_rule` 配了 `inbound=IN+yyyyMMdd+4`、`outbound=OUT+…`、`production_order=WPO…`，实际入库是 PO/FINISH、出库是 PICK 等。
7. **一码两义**：采购入库单号 = 采购单号（同一字符串两个含义）。

## 4. 新规则总则

**三轨**
1. **独立单据**（有独立生命周期、需跨单据引用）→ 一律走号段服务，格式 `<前缀><yyMMdd><流水>`（前缀 2~4 个大写字母、无分隔符）。
2. **从属单据**（依附父单）→ `<父单号>-<2 位类型码><2 位序号>`：`<工单号>-PK01`（领料）、`<工单号>-FI01`（完工入库）、任务保持 `<工单号>-P01-T001`；不占号段、天然不撞。
   - ⚠️ **2026-09-23 实况订正（看板 2250 复核）**：① 红冲单实际是**独立后缀 `-R`**（如 `...-FI03-R`），不是本文原写的 `-FI01R`；② FI 序号**超过 99 自动进位到 3 位**（`-FI100`），因此**解析必须按全量数字**（切忌 `\d{2}` 定长过滤 + `substring(len-2)`，会静默不出单——该定长隐患已由 dev-20260923-032 修掉，并由门禁 `check:lot:strict` ⑨ 兜底）；③ 同一族风险：`<工单号>-P%02d-T%03d`（ProductionTaskServiceImpl:1046 / QualityNcrServiceImpl:594）序号超 99/999 后位数变长，待复查消费方是否定长解析。
3. **批次号例外**：`BATCH-<工单号>[-<批号>]` 保留可读格式（贴标/追溯要用），不受"短号"约束。

**禁止**：时间戳/随机数拼号；复用他实体单号；同一实体两种格式；单号内嵌业务语义（工单号/批号走字段）。

## 5. 口径细节

### 5.1 日期
统一 **yyMMdd**（短、多数已在用）。存量老号不追改；新数据一律 yyMMdd（含采购/入库/出库，把原来的 yyyyMMdd 收口）。

### 5.2 流水位数的容量测算
实测今日产量：报工 5、检验批 7、报价/样品/工单/采购/调拨各 1。
· 3 位 = **999 张/天/类型**：低频类型（报价/样品/发货/退货/采购/主单/工单/CAPA/IQC 处置）绰绰有余；检验批/不良台账属中频，旺季数百也够。
· **报工是唯一高频**（一人一天多条，50 人×20 条≈1000）→ 建议报工单独配 4 位，其余默认 3 位。

### 5.3 溢出策略：自动进位 + 告警（用户口径）与配套三条
现状机制：号段服务 digits 固定，超上限**抛错**「序列号已达到最大值」→ 当天该类型建不了单（RedisSequenceService.java:271-272）。改为：**溢出时自动进位（digits+1）并告警**。
**业内主流是"报错 + 设足位数 + 监控"**，我们选"自动进位"属可变长的少数派，因此必须配三条，否则违反顺序性：
1. **排序口径**：单号一律按「前缀 + 日期 + 流水数值」解析排序；**禁止字符串排序**（否则 999 会排在 1000 之后）。
2. **告警通道**：进位时写日志 + 发通知/待办（含类型、当天用量、新位数），并进巡检（见 §7）。
3. **列宽与约束**：单号列宽 ≥ 24，唯一索引 + 作废不回收（不重用）。
（可选替代：报工等高频类型直接配 4~5 位，减少进位出现频率。）

## 7. 巡检与验收
- 巡检脚本（建议新增 `scripts/check-doc-no.sh`，可进 validate）：① 各类型当天用量/容量占比（>80% 告警）；② 是否存在长度/前缀偏离登记表的单号；③ 单号列唯一索引存在性（按本文 §3 表逐列核）。
- 验收：新单据全部符合 §4 登记表；时间戳式单号不再新增；同一实体只有一种格式；进位告警可见；报表按"数值解析"排序正确。

## 8. 风险
1. 工单号统一（第 5 批）涉及历史工单与所有引用它的派生号（任务/领料/入库/批次）→ 必须单独立项。
2. 日期/位数统一后**新旧长度并存**，凡"定长假设"的报表/打印/对接（如按位数截取）都要复核。
3. 自动进位破坏定长 → 依赖 §5.3 三条配套；若将来对接外部系统（EDI/条码）要求严格定长，需改回"报错 + 设足位数"。
4. IQC 四类处置单改号段时，历史 17 位时间戳号仍在库 → 唯一约束与检索要兼容两种形态。
