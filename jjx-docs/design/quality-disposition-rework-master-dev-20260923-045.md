## 1. 业务口径（无歧义定义）

### 1.1 术语表（**唯一口径，其他文档与本表冲突时以本表为准**）

| 术语 | 定义 | 来源（系统字段） |
|---|---|---|
| **计划量 Planned** | 工单要求交付的良品数量 | `production_order.planned_quantity` |
| **报工投入 Reported** | 工序实际报工的数量（含合格与不良） | `production_work_report.qualified+defective`（APPROVED 合计） |
| **良品 Good** | 检验**判定为合格**的数量（含返工/让步回收后的合格量） | 有效检验批 `pass_quantity` 合计 |
| **报废 Scrap** | 处置为报废、**永久不可用**的数量（不良品从未进良品库，故不产生库存扣减） | `quality_ncr_action(SCRAP, DONE)` |
| **返工在制 ReworkWIP** | 已登记返工、尚未复检合格的数量 | `quality_ncr_action(REWORK, PROCESSING)` |
| **返工回收 Recovered** | 返工复检合格并入库的数量 | 返工复检批 `pass_quantity` |
| **让步接收集 Conceded** | 客户确认后转良品的数量（特采） | `quality_ncr_action(CONCESSION, DONE)` + `customer_confirmed` |
| **在制 WIP** | 已报工但尚未判定/未入库的数量 | 有效批中未判定部分 |
| **缺口 Shortfall** | `计划量 − 良品`，下限 0；**>0 表示还差这么多良品** | 派生（`OrderCompletionStatusVO.shortfall_quantity`） |
| **补产 Supplement-Production** | 为补上缺口**新做**的数量（走报工 → 建批 → 判定 → 入库） | 报工记录 + 新检验批 |
| **补料 Material-Supplement** | 返工**额外消耗**的物料（不占原工单 BOM 定额），必须关联不良单 | `inventory_outbound_order(source_type='quality_ncr')` |
| **退料 Material-Return** | 返工结束**剩余料退回**仓库，冲减补料消耗 | 退料单（待建，dev-20260923-043） |
| **净耗 Net-Consumption** | `补料 − 退料`（返工的额外料耗） | 派生（对账栏物料侧） |
| **有效批 Effective Lot** | 该工单下**没有后继复检版本**的 FQC 批 | 派生（无子批） |
| **失效批 Superseded Lot** | 已有后继复检版本的批 → **只读**，不得录入/判定/复检/重开 | 派生（有子批） |
| **工单完成** | = **良品等于计划量**且所有工序已完成/已跳过（不是"报了 200 就算完"） | 派生（完工门禁） |

### 1.2 数量守恒（门禁断言，全 0 才算健康）

- 批级：`检验数量 = 合格 + 不良`
- 台账级：`批不良 = 台账不良合计`；`未作废处置量 ≤ 不良量`
- 判定级：`合格 ≤ 批量 − 链上已报废未回收 − 让步未客户确认`（**可判合格上界**）
- 工单级：`工单完成数 = 有效批良品合计`；`计划量 − 良品 = 缺口`
- 库存级：`结存 = 累计入库 − 累计出库 ± 盘点调整`（三本账一致）
- 物料级：`应领(BOM) / 已领 / 补料 / 退料 / 净耗` 可逐单下钻

### 1.3 处置决策模型（业内 UD 对齐）

1. 不良进入台账（一验批一张台账，自动生成）。
2. 处置是**一次性使用决策**：返工 / 让步接收 / 报废，**做出即冻结**；要改必须走**撤销**（带权限 + 原因 + 审计）。
3. 三种处置的账务影响**必须互斥、不重复计账**：

| 处置 | 库存影响 | 良品影响 | 后续动作 |
|---|---|---|---|
| 报废 | 不扣（口径 A：不良从未进良品库） | 不计入良品 | 缺口由**补产**或**返工回收**填 |
| 让步接收 | 转良品 +（需客户确认） | 计入良品 | 无 |
| 返工 | 不直接动库存 | 复检合格后计入良品（= 回收） | 报工 → 建"返工复检"批 → 判定 → 确认入库 |

### 1.4 补产 / 补料 / 退料 的边界（**别混**）

| 场景 | 走什么 | 说明 |
|---|---|---|
| 报废/不良造成良品不足，要**多做几件** | **补产**（报工补报） | 数量按**缺口**预填；上限 = 计划量×(1+损耗率) − 已合格 |
| 返工时要**多用物料**（换料/补件） | **补料** | 独立出库单，不占 BOM 定额，必关联不良单 |
| 返工结束**剩余料** | **退料** | 退库，冲减补料；净耗 = 补料 − 退料 |

## 2. 对象与状态机

### 2.1 四类对象状态

| 对象 | 状态 | 派生属性 |
|---|---|---|
| 检验批 | PENDING 待检 / INSPECTING 检验中 / JUDGED 已判定 / CLOSED 已关闭 | **失效**（有子批）、来源批号、工单号 |
| 不良单 | PENDING 待处置 / DISPOSING 处置中 / CLOSED 已结 / VOID 已作废 | 来源批是否已失效 |
| 处置动作 | PENDING / PROCESSING 执行中 / DONE 已完成 / VOID 已作废 | 关联返工工序、关联复检批 |
| 返工工序 | 8 值（ExecutionStatusEnum：待执行/准备中/执行中/已暂停/已完成/已跳过/已取消/异常） | 来源不良单、返工件数、报工量、回收量 |

### 2.2 状态 × 动作总表（**唯一出处**，详见 039 方案）

**检验批**：待检/检验中（未失效）→ 录入、判定；已判定（未失效）→ 复检；已关闭（未失效）→ 重开；**已失效 → 仅查看/打印**。
**不良单**：待处置/处置中（来源批未失效）→ 处置；来源批已失效 → 仅查看（提示对最新版本操作）；已结/已作废 → 仅查看；动作 DONE 且为报废 → 撤销（`quality:ncr:revoke`）。
**返工链**：登记返工必须有责任人（默认工单一级负责人）→ 派工 → 开工 → 报工 → 审批（自动建"返工复检"批）→ 判定（自动收口处置动作 + 回写复检批）。
**工单**：生产中 → 报工/补报；待补产（有缺口且无未处置不良）→ 补产；待不良处置 → 去台账处置；待完工确认 → 完成工单（要求所有工序已完成/已跳过）；待入库处理 → 重试入库。

### 2.3 守卫与唯一出处

- 后端 `AllowedActionResolver` 按"对象 × 状态 × 链路有效性"算出 `allowedActions`，**列表与详情接口统一下发**。
- 接口入口守卫与下发**同源**（同一个 Resolver），不再各写 if。
- 前端**只按 `allowedActions` 渲染**，页面里不出现状态条件；对象不存在/无权限时给出明确文案（见 §3.4）。

## 3. 页面与操作（要求 2：清晰、简单）

### 3.1 页面地图（一页一职责）

| 页面 | 菜单 | 职责（一句话） |
|---|---|---|
| 成品检验 | 质量管理 → 成品检验 | 录入、判定、复检、重开；**看批的账**（有效/失效、合格/不良、已入库） |
| 产品不良台账 | 质量管理 → 产品不良台账 | 不良的**处置决策与留痕**（返工/让步/报废/撤销/补料/退料），以及**返工进度** |
| 工序执行 | 生产管理 → 工序执行 | 报工/补报、开工完成、看工序与工单缺口；**返工工序在这里执行** |
| 派工管理 | 生产管理 → 派工管理 | **上工单、下派工**：选工单后只列该工单任务，返工任务置顶标红 |
| 报工审批 | 生产管理 → 报工审批 | 报工审批（通过后**自动建复检批**） |
| 入库作业 | 库存管理 → 入库作业 | **确认入库**（含红冲单、返工回收批） |
| 出库作业 | 库存管理 → 出库作业 | 发料（含**返工补料单**、退料单） |

**原则：动作只放在它所属域的页面** —— 处置类动作只在质量页、派工只在派工页、过账只在库存页。**跨域只给提示，不给按钮**（例：质量台账提示"待派工：到生产管理 → 派工管理"，不提供派工按钮）。

### 3.3 三条典型路径（照着点即可）

**路径 ① 检验发现不良 → 返工回收**（本案 A1 实测已通）
1. 成品检验：判定 `检验100 / 合格98 / 不良2` → 自动生成不良台账 + 应入 98 的入库单（待确认）。
2. 产品不良台账：对 NCR → 处置 → **返工** → 选返工工序 + 填返工要求（生成返工工序，**自动派给工单一级负责人**）。
3. 派工管理：选该工单 → 返工任务（置顶标红）→ 派给工人。
4. 工序执行：工人开工 → 报工 2 件（或补报）。
5. 报工审批：通过 → **自动生成「返工复检」批**。
6. 成品检验：判定该批 `2 / 0` → 自动回写复检批 + **收口处置动作**（台账变"已结"）。
7. 入库作业：确认入库 → 良品 +2（回收完成）；工单缺口随之归零。

**路径 ② 报废后补产**
1. 台账：处置 → 报废（只记台账，不动库存）。
2. 工序执行：工单面板显示「待补产 · 还缺 2 件（报废 2 件）」→ 责任人点「补报」→ 数量**已按缺口预填 2**。
3. 报工审批 → 自动建批 → 判定 → 确认入库 → 工单归零。

**路径 ③ 返工缺料 → 补料 / 退料**
1. 台账：返工那行 → 「补料」→ 选物料 + 数量 + **原因码** + 审批人（≠提交人）→ 生成 `SUPP-…` 出库单（待仓库发料）。
2. 出库作业：仓库存发料 → 实发确认（消耗计入返工料耗）。
3. 返工完成若有剩余：台账同入口 → 「退料」→ 生成退料单 → 退库。
4. 对账：工单物料栏显示 `应领 / 已领 / 补料 / 退料 / 净耗`，可按不良单下钻。

### 3.4 信息呈现原则（避免"看不懂"）

1. **不出现裸 ID**：一律给单号（工单号、批号、不良单号、任务号）。
2. **数字旁一句人话**：凡是"还要做什么"的地方给一句原因与去处（例："检验报废 2 件已处置，良品 198/计划 200，还缺 2 件 → 到末道工序「补报」补产"）。
3. **颜色即状态**：可操作=蓝/绿，阻塞=橙，禁止/失效=灰，危险动作=红且需二次确认。
4. **一个动作一个入口**：同一动作不在两个页面出现（避免"该在哪点"的歧义）。
5. **失败必说原因与下一步**：所有守卫拒绝都带"当前状态 + 为什么 + 该怎么做"。

### 4.2 权限点定稿（**2026-09-23 已定，不再征询**）

**归属原则（两条线，避免以后纠结）**：
- **发起类动作**放在**业务域页面**（质量 / 生产）——例：在不良台账就地发起补料（业内一致：SAP 在返工单上做组件增补，库存只是过账）。
- **过账类动作**只在**库存域页面**（入库作业 / 出库作业）。
- **权限点按动作所属域命名**：补料/退料产生的是出库单 → 权限点归 `inventory:outbound:*`（即使按钮画在质量页）。这是**唯一允许的"按钮在 A 域、权限在 B 域"**，本方案明确授权，避免以后被当成违规。

| `production:work-report:approve`（现有） | 报工审批 | 生产 | 一级负责人 |
| `production:operation-execution:edit`（现有） | 开工 / 完成工序 | 生产 | 工人（本人任务）、一级负责人 |

> 三个新增权限点随 **039** 一起落库（动作枚举与权限点同批定义，避免"先加权限、后改动作"返工）。

### 4.3 角色 × 权限矩阵

| 角色 | 成品检验 | 不良台账 | 工序执行/报工 | 派工 | 报工审批 | 入库/出库 |
|---|---|---|---|---|---|---|
| 质检员 | 录入 | 查看 | — | — | — | — |
| 品质主管 | 录入+判定+复检+重开 | 处置+撤销+随批作废 | — | — | — | — |
| 一级负责人 | — | 查看 | 报工/补报/开工完成 | 派工/收回 | 审批 | — |
| 工人 | — | — | 报工/补报 | — | — | — |
| 库管 | — | 查看 | — | — | — | 确认入库 / 发料 / 退料收货 |
| 超管 | 全部 | 全部 | 全部 | 全部 | 全部 | 全部 |

### 4.4 职责分离（SoD）定稿 —— **分离服从角色层级：主管可兼**

原则：**分离不是"必须两个人"，而是"两手活不能落在同一层级"** —— 低层级不得兼，主管层级（`品质主管` / `一级负责人`）作为责任人可以兼，并且**兼了必须留痕**。

| 规则 | 定稿 | 说明 |
|---|---|---|
| 录入 ≠ 判定 | **默认同层级分离**：质检员只能录入，判定/复检需 `quality:lot:judge`；**品质主管可一人完成录入+判定**（留痕记录判定人） | 小厂常态一人多岗，硬性两人会堵死流程；用权限层级表达"更高级别可兼" |
| 处置 ≠ 撤销 | **不强制不同人**：撤销是纠错，要求 **持 `quality:ncr:revoke`（品质主管）+ 必填原因 + 审计留痕** | 纠错常由同一人发现，强制换人反而制造假操作 |
| 补料申请 ≠ 审批 | **强制不同人**（审批人 ≠ 提交人）；**例外开关** `sys_config.quality.rework-supplement.self-approve`（默认 `false`，仅超管可开）并留痕 | 补料是"超 BOM 定额"的资金风险动作，业内要求授权；极端当班只有一人时由超管开例外 |
| 发料 ≠ 领用 | **强制**：补料单必须由仓库在**出库作业**发料确认；同一账号同时具备质量+库存权限（超管）可兼，但留痕 | 实物与账同步 |
| 判定 ≠ 工单收口 | **强制**：工单收口属生产域权限（一级负责人），品质账号默认不给 | 品质只维护质量事实 |

## 5. 数据链与留痕

### 5.1 动作 → 产生什么（钩子表）

| 动作 | 单据 | 流水 | 台账/批变化 |
|---|---|---|---|
| 判定（成品） | 生成/更新「应入」入库单（一验批一单） | 判定本身不动库存 | 批合格/不良；不良进台账 |
| 确认入库 | 入库单 → 已入库 | INBOUND + | 批已入库；工单完工回写 |
| 复检换代 | 原单作废/红冲单（-R） | ADJUST − | 原批失效；被取代批未处置不良**随批作废** |
| 处置-报废 | 无 | 无（口径 A） | 台账已处置 +；动作 DONE |
| 处置-让步 | 良品入库单 | INBOUND + | 台账已处置 +；需客户确认 |
| 处置-返工 | 返工工序 + 任务 | 补料时才出库 | 动作 PROCESSING → 复检合格后 DONE + 回写复检批 |
| 补产（补报） | 报工单 → 新批 → 入库单 | INBOUND + | 良品 +；缺口 − |
| 补料 | 出库单 `SUPP-…`（source_type=quality_ncr） | OUTBOUND − | 物料净耗 + |
| 退料 | 退料单（待建） | INBOUND/冲减 + | 物料净耗 − |

### 5.2 禁止事项（硬约束）

1. 单据**只能红冲**，不得改数改状态（入库/出库单）。
2. 库存变动**只能**走 `InventoryStockMutationService.applyDelta`；流水 append-only。
3. **禁止裸 SQL 改台账**（`quality_ncr` / `quality_ncr_action`）——一切走动作（块 3）。
4. 禁止跨域放动作按钮（质量页不放派工、生产页不放过账）。

### 5.3 门禁（自动校验，已在 `npm run validate`）

- 三本账一致 + 入库单/检验批维度 + 数量守恒八查（023 已扩）。
- 新增：**状态×动作一致性断言**——对失效/作废对象，接口返回的 `allowedActions` 必须为空（块 1 的验收）。

## 6. 实施顺序（**2026-09-23 定稿：避免埋坑的排序**）

| 序 | 内容 | 卡 | 前置 | 为什么必须在这个位置 |
|---|---|---|---|---|
| 1 | **状态×动作唯一出处**（`AllowedActionResolver` + `allowedActions` 下发 + 守卫同源 + 前端零状态条件）**+ 三个新权限点同批落库** | 039 | — | 它是后面所有块的地基：动作集合定了，权限点才有意义。**先加权限点、后改动作集合 = 返工一次**，所以权限点与动作枚举**同批**做 |
| 2 | **台账变更走动作**（随批作废正式入口 + 权限点 + 存量订正） | 040 | 039 | 有了"允许动作"的口径，作废才是**动作**而不是 SQL；同时把今晚的裸 SQL 订正补成合法路径 |
| 3 | **前端状态枚举 + 门禁扩规则**（字符串状态比较纳入 `check:status-enums`） | 041 | 039 | 必须等 039 把前端状态条件清干净再做，否则**基线要重建两遍** |
| 4 | **返工补料补课**（原因码 / 量额上限 / 审批人≠提交人 / 替代料留痕） | 025 | 039 | 它的守卫与权限要走 039 的统一出处，不能再造第三套判断 |
| 5 | **返工退料**（净耗 = 补料 − 退料） | 043 | 025 | 退料单的口径必须与补料一致（原因码/权限点/审批规则同源） |
| 6 | **对账栏两栏**：先数量（计划/报工/良品/报废/返工在制/让步/在制/差数），后物料（应领/已领/补料/退料/净耗，可按不良单下钻） | 024 → 027 | 025/043（物料侧） | 同一页面族，**一次做完两栏**或明确先数量后物料，避免同页改两次 |
| 7 | **022 遗留**：撤销流扩展（现在只支持"报废"撤销；"让步接收/返工"的撤销需要**反向库存/返工冲销**） | 022 二期 | 039 | ⚠️ **不许临时补丁**：让步已转良品库存、返工已建批，撤销必须先设计反向动作（反向库存 + 返工批作废 + 上界回归），设计稿先行 |
| 8 | 上线前回归 | 019 | 全部 | 重启后按场景 A/B/C 走一遍 |

**这条顺序排除的坑**（逐条对照）：
1. 若先做 025（补料）再做 039 → 补料的守卫/权限会先自成一套，随后 039 又要重构它 → **返工**。
2. 若先做 041（门禁）再做 039 → 基线把"将被删掉的状态条件"记进债务，还要重建 → **做两遍**。
3. 若 043（退料）不先定 025 的口径 → 补料/退料两套规则 → **口径分叉**。
4. 若 022 的撤销扩展直接上（不做反向库存设计）→ 会出现"台账撤销了、库存没回来" → **账实不符**。
5. 若 024/027 分两次改同一页面 → 每次都要回归 → **重复回归**。

## 7. 验收（端到端，含期望数字）

**场景 A（本案实测数字，作为基准）**：工单计划 200、报工 200（两道工序各 100）、批1 100 良、批2 100（98 良 + 2 不良）→ 处置返工 2 件 → 返工复检 2/0 → 回收。
期望终态：**良品 200 / 缺口 0 / 库存 200 / 台账该条"已结"+返工进度"已回收 2/2" / 三本账门禁全 0**。

**场景 B（报废+补产）**：报废 2 件 → 面板显示「待补产 · 还缺 2 件（报废 2 件）」→ 补报 2 → 新批判定 2/0 → 入库 → 良品 200、缺口 0。

**场景 C（补料/退料）**：返工缺料 → 补料 5 件（原因码 + 审批人≠提交人）→ 出库单 `SUPP-…` 已过账 → 剩余 2 件退料 → 净耗 3 件，对账栏可见。

**通用失败判据**：出现裸 ID、需要人工算数、状态与可操作动作矛盾、门禁非 0、账实不符（实物与库存差）——任一出现即不通过。

## 8. 明确不做

不引入工作流引擎；不改库存口径与状态机本身；**本期不把入库/出库单纳入 allowedActions**（并行会话在制，避免撞车）；不做 SAP 级字段密度（页面只加"一句话 + 一个可下钻点"）；**不做"录入必须换人"的硬性两人强制**（按 §4.4 用权限层级表达，主管可兼）；**022 撤销扩展不许临时补丁**（先出反向库存设计稿）。
