# 返工可见化：把返工变成页面上一条能跟到底的链（dev-20260923-031）

> 任务：dev-20260923-031（P1，方案 + 一期实施）
> 起草：Hermes（2026-09-23）｜触发：用户实测「工序执行页看不懂、返工没有体现」，要求按业内标准对齐
> 关联：dev-20260923-028（补产驱动）、dev-20260923-022（处置冻结 / 撤销流，二期，并行会话在飞）、dev-20260923-024（数量对账栏）、dev-20260923-023（守恒门禁）

## 0. 一句话结论

返工在系统里**已经是一条完整的链**（不良单 → 返工工序 → 报工 → 复检 → 回收良品），但**页面上没有身份**：工序列表不区分返工、不良台账只给一个裸 ID。
本方案 = 把这条链投影成一个只读接口，在 3 个页面贴出「身份 + 进度 + 一句人话」；**不新建单据类型、不改库存口径、不做 SAP 级字段密度**。

## 1. 问题（实测证据，2026-09-23）

1. 工序执行页（PC）全文检索没有 `REWORK` / 「返工」字样 → 返工工序与正常工序外观完全一致，看不出这是"返修"，也不知道复检才算回收。
2. 不良台账页「处置记录」的「返工/复检关联」列只渲染 `工序 #{{reworkExecutionId}}` → 看不到工序名、状态、修了几件、回收几件；点进去也无处可跳。
3. 工单缺口只有数字（合格 198/200），没有因果。dev-20260923-028 已补「报废 2 件、还缺 2 件 → 去补产」那一句，但缺另一半：**返工在制 / 已回收**。

## 2. 业内口径与我们的对照

| 业内（SAP QM / ISO 9001:2015 §8.7） | 我们现状 |
|---|---|
| 质量通知单（QM Notification）登记不良 | 不良台账 `quality_ncr` ✅ |
| 检验批挂在批次上、全检 | `quality_lot` ✅ |
| 使用决策（UD）一次性、做出即冻结、要改必须撤销并留痕 | 三种处置（返工/让步/报废）已有；**冻结 + 撤销流 = 022 二期（在飞）** |
| 返工是一张独立单据（rework order），挂在原批次 | 口径已有：返工工序 `execution_type=REWORK` + 来源不良单（`source_inspection_id` / `quality_ncr_action.rework_execution_id`）；**页面无身份 ✗** |
| 返工完工后重新检验，合格才回流 | 返工报工 → 复检 → 复检合格置 DONE ✅ |
| 报废独立凭证；数量守恒（投入 = 良品 + 报废 + 返工在制 + 在制） | 报废只记台账（口径 A）；上界闸门 = 021 ✅；守恒门禁 = 023 |
| 每个数字都能下钻到单据/凭证 | 部分位置只有裸 ID ✗ |

**结论：口径基本对齐（021~024 那批卡就是补课），差距集中在"页面上的身份与下钻"。**

## 3. 方案总则

1. **一条链一路看得见**：不良单 → 返工工序 → 报工 → 复检 → 回收，每处都带来源单号与数量，从任一页面都能看出整链进度。
2. **每个数字旁一句人话**：写清"谁在办、下一步做什么"，不让操作人自己算。
3. **缺口两条路都可见**：工单差 N 件时，同时显示「补产」与「返工在制/已回收」，让人知道该走哪条。
4. 边界：不新建表 / 不新建单据类型 / 不改库存口径 / 不照抄 SAP 的一屏几十字段（信息密度克制，只加"一句话 + 一个可下钻点"）。

## 4. 唯一新增后端能力：返工链投影（只读）

`GET /production/rework/trace`，参数 `orderId` / `executionId` / `ncrId`（三者取其一），返回数组：

| 字段 | 含义 |
|---|---|
| `ncrId` / `ncrNo` | 不良单 |
| `defectQuantity` / `disposedQuantity` | 不良量 / 已处置量 |
| `actionId` / `actionStatus` | 处置动作与状态（`PROCESSING` = 返工在制，`DONE` = 已完工） |
| `executionId` / `processName` / `executionStatus` | 返工工序（工序名直接给人看，不再给 ID） |
| `reworkRequirement` | 返工要求 / 作业说明（取自 `execution.custom_process_params`） |
| `reportedQuantity` | 返工已报工（APPROVED 合计） |
| `reinspectionLotId` / `reinspectionLotNo` | 复检批 |
| `recoveredQuantity` | 已回收良品（复检批 `pass_quantity`） |
| `statusText` | 一句人话（模板见 §5.3） |

## 5. 页面改动（每条：现在 → 改成）

### 5.1 工序执行页 · 工序列表 / 抽屉（一期）
- 现在：返工工序与正常工序外观一致。
- 改成：红色「**返工**」标签 + 来源「来自 NCR260923001（不良 2 件）」+ 悬停一句话。

### 5.2 不良台账页 · 处置记录（一期）
- 现在：`工序 #12`。
- 改成：「返工 · 面板冲形 · 进行中 · 已报 0/2 · 未复检」；完工复检后变「已回收 2/2」。

### 5.3 一句话模板（`statusText`）
| 状态 | 一句话 |
|---|---|
| 待开工 | 把报废/不良的 N 件修回来——先开工这道返工工序 |
| 进行中 | 返工进行中，已报 X/N 件 |
| 待审批 | 返工已报工，等审批 |
| 已完工待复检 | 返工已完工，去成品检验判定并复检 |
| 已回收 | 返工复检合格 Z/N 件，已回收良品 |
| 部分回收 | 返工复检合格 Z/N 件，还差 N−Z 件（走让步接收或报废） |

### 5.4 工单面板（二期，并入 024）
加「返工在制 X 件 · 已回收 Y 件」，与 028 的「还缺 N 件（报废 M 件）」并列，让缺口的两条路同时可见。

### 5.5 报工弹窗（二期）
返工工序报工时顶部显示来源不良单 + 返工件数 + 作业说明（工序质量标准 / 返工要求），数量按返工件数预填。

### 5.6 成品检验批页（并入 022 ④）
复检批批头标「返工复检（源自 NCR260923001，返工 2 件）」，判定默认只填不良量（上界校验 021 已做）。

## 7. 验收

1. 接口：`orderId=2` → 返回空数组（本案只有报废、无返工）且不报错；造一条真实返工后返回 1 条含全部字段（工序名 / 状态 / 已报件数 / 复检批 / 回收数）。
2. 工序执行页该返工工序带「返工」标签与来源不良单；不良台账该行显示返工进度，**页面上不再出现裸 ID**。
3. `mvn` 全量测试绿；`npm run validate` 绿。
4. 生效需重启（新增接口）。

**失败判据**：接口 500 或返回结构缺字段 / 前端标签不出现 / 页面仍有裸 ID。

## 8. 边界与风险

- 不动库存、不动单据、不做撤销流（022 在飞，避免撞车）。
- `jjx-web/src/views/quality/ncr/index.vue` 有并行会话在制改动 → 本卡改动用 **hunk 级拆分**提交，不混提交。
- 返工工序目前在 `production_operation_execution`，与"单据"不同层；本方案用「返工工序 + 来源不良单」表达业界的"返工单"，不新建单据类型。
