# 返工可见化：把返工变成页面上一条能跟到底的链（dev-20260923-031）

> 任务：dev-20260923-031（P1，方案 + 一期实施）
> 起草：Hermes（2026-09-23）｜触发：用户实测「工序执行页看不懂、返工没有体现」，要求按业内标准对齐
> 关联：dev-20260923-028（补产驱动）、dev-20260923-022（处置冻结 / 撤销流，二期，并行会话在飞）、dev-20260923-024（数量对账栏）、dev-20260923-023（守恒门禁）

## 0. 一句话结论

返工在系统里**已经是一条完整的链**（不良单 → 返工工序 → 报工 → 复检 → 回收良品），但**页面上没有身份**：工序列表不区分返工、不良台账只给一个裸 ID。
本方案 = 把这条链投影成一个只读接口，在 3 个页面贴出「身份 + 进度 + 一句人话」；**不新建单据类型、不改库存口径、不做 SAP 级字段密度**。

## 1. 问题（实测证据，2026-09-23）

1. 工序执行页（PC）全文检索没有 `REWORK` / 「返工」字样 → 返工工序与正常工序外观完全一致，看不出这是"返修"，也不知道复检才算回收。
2. 不良台账页「处置记录」的「返工/复检关联」列只渲染 `工序 #{{reworkExecutionId}}` → 看不到工序名、状态、修了几件、回收几件；点进去也无处可跳。
3. 工单缺口只有数字（合格 198/200），没有因果。dev-20260923-028 已补「报废 2 件、还缺 2 件 → 去补产」那一句，但缺另一半：**返工在制 / 已回收**。

## 2. 业内口径与我们的对照

| 业内（SAP QM / ISO 9001:2015 §8.7） | 我们现状 |
|---|---|
| 质量通知单（QM Notification）登记不良 | 不良台账 `quality_ncr` ✅ |
| 检验批挂在批次上、全检 | `quality_lot` ✅ |
| 使用决策（UD）一次性、做出即冻结、要改必须撤销并留痕 | 三种处置（返工/让步/报废）已有；**冻结 + 撤销流 = 022 二期（在飞）** |
| 返工是一张独立单据（rework order），挂在原批次 | 口径已有：返工工序 `execution_type=REWORK` + 来源不良单（`source_inspection_id` / `quality_ncr_action.rework_execution_id`）；**页面无身份 ✗** |
| 返工完工后重新检验，合格才回流 | 返工报工 → 复检 → 复检合格置 DONE ✅ |
| 报废独立凭证；数量守恒（投入 = 良品 + 报废 + 返工在制 + 在制） | 报废只记台账（口径 A）；上界闸门 = 021 ✅；守恒门禁 = 023 |
| 每个数字都能下钻到单据/凭证 | 部分位置只有裸 ID ✗ |

**结论：口径基本对齐（021~024 那批卡就是补课），差距集中在"页面上的身份与下钻"。**

## 3. 方案总则

1. **一条链一路看得见**：不良单 → 返工工序 → 报工 → 复检 → 回收，每处都带来源单号与数量，从任一页面都能看出整链进度。
2. **每个数字旁一句人话**：写清"谁在办、下一步做什么"，不让操作人自己算。
3. **缺口两条路都可见**：工单差 N 件时，同时显示「补产」与「返工在制/已回收」，让人知道该走哪条。
4. 边界：不新建表 / 不新建单据类型 / 不改库存口径 / 不照抄 SAP 的一屏几十字段（信息密度克制，只加"一句话 + 一个可下钻点"）。

## 4. 唯一新增后端能力：返工链投影（只读）

## 9. 返工补料（2026-09-23 追加：业内口径 / 我们现状 / 缺口清单）

> 起因：用户问"返工如果要补料要怎么做"，要求参考业内标准。本节是**补齐内容**，不改变第 3~8 章的结论。

### 9.1 业内怎么做（SAP QM / MM + ISO 9001:2015 §8.7 + MES 通行做法）

1. **返工是独立的一次生产（返工单/rework order），物料从它自己的组件领出**（SAP 261 记在返工单上）—— **不占原工单的投料定额**，因为原工单的计划已经消耗完了，返工是额外消耗。
2. **领料必须挂原因与授权**：返工单的组件增补要 reason code + 审批；ISO 8.7 要求不合格输出的处置"经授权批准、保留记录"。
3. **消耗要能归集**：按返工单/不良单结算，报表能单独筛出"返工导致的额外材料消耗"（否则成本混进正常料耗）。
4. **不是没有上限**：常见两种控制——按「返工件数 × 单件用量（含损耗率）」给参考上限、超限走授权；或每笔都人工批准并记原因码。**没有原因码/上限的"可以随便领"是业内明确要避免的后门。**
5. **剩余料要能退**：返工完成后多余料退库（SAP 262 退料），账上要有对应动作，否则料耗虚高、成本失真。
6. **替代料要留痕**：用替代料要记录物料 + 原因，避免"补料"变成绕开 BOM 的通道。
7. **实物移动才走出库单**：补料是真实出库（实物离开仓库）→ 走出库单，不是红冲。

### 9.2 我们现状（2026-09-23 实测）

- 入口：**产品不良台账 →「处置记录」→ 返工那一行 →「补料」** → 选物料/数量 + 填审批人 → 生成出库单（`InventoryOutboundServiceImpl.createReworkSupplement`）。
- 单号 `SUPP-<工单号>-<NCR号>-<序号>`；出库类型=生产；**`source_type='quality_ncr'`**；状态直接=**已批准**；备注「返工补料，已明确越过 BOM 定额校验；NCR=…」；审批人=页面填的人。
- **已对齐业内的**：不占 BOM 定额 ✅、必须关联不良单 ✅、有审批人字段 ✅、可按 `source_type='quality_ncr'` 筛选 ✅、实物出库走正规出库单 ✅。
- **缺口（4 条）**：① 无量额控制、无原因码（数量可任意填，只要填个审批人）；② 审批人可以就是提交人（应"审批人非提交人"）；③ **无退料入口**（剩余料退不回）；④ 无「返工料耗」专门视图（报表口径靠手筛 `source_type`）。

### 9.3 补齐清单（对应卡片）

| 缺口 | 补齐做法 | 归属 |
|---|---|---|
| 无量额/原因码 | 补料弹窗加「**原因码**（必填下拉）」；参考上限 = 返工件数 × 单件用量 ×(1+损耗率)，超限须显式勾选"超限授权"并填理由 | dev-20260923-025（补料泛化，预留） |
| 审批人=提交人 | 审批人必须与提交人不同（超管可配例外），否则拒绝提交 | dev-20260923-025 |
| 无退料 | 新增「**返工退料**」：同一入口选退料 → 生成退库/退料单（或领料红冲），冲减该 NCR 的补料消耗 | 需新增卡片（待登记） |
| 无料耗视图 | 工单物料对账栏加「补料 / 退料 / **净耗**」三列，可按不良单下钻 | dev-20260923-027（对账栏物料侧） |

**一句话**：业内的核心是「**返工料单独记账 + 有原因/授权 + 能退料 + 能按不良单归集**」。我们前四项（独立单号、不占定额、关联不良单、可筛）已经对齐，缺的是**量额与原因码、审批人独立、退料、料耗视图**——分别挂在 025 / 027，退料需要新登记一张卡。
