## 一、039 发货流程

### 1. 分批发货（一单多批）
**问题**：`sales_delivery` 只有汇总、无明细；`shipOrder` 把订单全部明细求和一次发完，订单直接 7生产中→8已发货；出库按「订单量−已发量」自动推（073 的旧注释），但**发货单本身不知道发了哪些行、多少** → 对不了行、打不了准确的送货单。

**方案（已落地）**：
| 层 | 改动 |
|---|---|
| DB | 新增 `sales_delivery_item`（迁移 169）：delivery_id / order_product_id / 产品冗余字段 / quantity / unit_price / amount |
| 后端 | `shipOrder` 接受本次发货明细（`items`，缺省=未发数量全发，向后兼容）；校验「本次 ≤ 未发」；发货单只记本次数量/金额；**全部发完才置 8 已发货**，部分发货保持 7 生产中 |
| 出库 | 新增 `createFromSalesByDelivery(deliveryId)`（出库单按发货单明细数量出库，库存不足直接报错，不再静默少发）；`order.delivering` payload 补 `deliveryId`，桥接优先按明细出库 |
| 回写 | `shipped_quantity` 由出库确认累加（073 已有），依赖 dev-20260921-037 的 `OrderMapper.updateById` 白名单修复才真正落库 |
| 前端 | 发货弹窗改 860px，带出「订单数量 / 已发 / 未发 / 本次发货数量」（默认未发，可改）；订单列表状态列显示「已发 x/y」；发货单详情按**本次发货明细**展示；送货单打印只打本次明细（无明细的历史单回退订单明细） |

**顺带修掉一个隐藏 bug**：手写 payload 改造（013）后 `order.delivering` 丢了 `salesOrderId` 键，桥接取不到订单 → 销售发货会走兜底路径建不出明细行。已在 `publishOrderEvent` 统一补回。

### 2. 状态机收敛（运输中退场）
`3 运输中` 全链路无写入点（枚举里有、没人写），但对账页与销售工作台 SQL 都在统计它。
处理：前端枚举删除该项、`SalesWorkbenchMapper` 改 `IN (2)`、注释同步；数值 4/5 保持不变（历史数据不可重编号）；现网 `sales_delivery` 为空表，无迁移成本。

### 3. 拒收回流（自动为主，少人工）
**问题**：状态 5 已拒收没有任何写入路径；拒收后订单 shipped_quantity 不减、出库扣掉的库存不回来、也没有原因/时间/经办人记录和通知。

**方案（已落地）**：
1. `sales_delivery` 补 `reject_reason / reject_time / reject_by / reject_name`（迁移 170）
2. 新增接口 `POST /sales/deliveries/{id}/reject`：仅「已发货(2)」可拒收（已签收请走退货流程），原因必填
3. 自动回冲：`InventoryInboundService.createSalesRejectInbound(deliveryId)` 按发货明细生成「拒收回库单」（`REJECT-{发货单号}`，source_type=SALES_RETURN）并自动审批 + 过账 → 数量回成品库存，仓库不用手工建单
4. 订单自动收口：重算 `shipped_quantity`（排除已拒收发货单），若因此不满发且订单在「已发货」，回退「生产中」以便重新发货
5. 事件 `sales.delivery.rejected` 已注册（通知+派任务，收件人 销售业务操作(20) + 销售审核员(21)）
6. 前端：发货单列表加「拒收登记」按钮（弹窗带出发货单/客户/明细/数量，只填原因）；详情显示拒收原因/时间/经办人

**口径（写在配置与本文）**：拒收回库按「可再售」处理；已拆封/损坏请走退货或报废流程。
