## 0. 一句话结论

**你的直觉是对的**：批次必须能看到"入库了多少、出库了多少、还剩多少"，而且**原始入库量绝不能丢、数量也不该被"随手改"**。
我们的问题不是数据错，而是：**原始量记在别处（入库单明细 + 库存流水），页面只给你看了"还剩多少"这一栏，而且没有"看流水"的入口。**
本方案：**以流水为唯一真源**，页面上把「入库 / 已出库 / 结存」三栏一起显示 + 加「变动流水」抽屉，并把口径写进规范。

## 1. 你看不懂的三个地方（逐条解释）

### 1.1 "这个不是看库存变化的依据吗？"
**不是。** 批次明细现在显示的是**批次结存快照**（表 `inventory_stock_item`），只回答"这一批现在还剩多少"。
"看变化"的依据是**库存流水**（表 `inventory_transaction`，每笔带 `变动前/变动后`）——但它**目前没有页面**：
- 菜单里的「库存流水」只是个**按钮权限**（`inventory:transaction:view`），没有对应页面；
- 只有从**入库单详情 / 出库单详情**里才能看到该单据自己那几笔流水。

→ 所以你"找不到依据"是**产品缺口**，不是数据错。

### 1.2 "物料只入库？"
因为这个弹窗**只列批次结存行，不列出库记录**（只有"最后出库"一列时间）。
出库（领料）把批次余量扣小了，看着就像"只有入库记录、没有出库记录"。

### 1.3 "入库的数据会变？"
页面那一列「数量」其实是**实时结存**，出库后就会变小。用你今天这批料（RM001585，共收 200 件分两次）：

| 批次号 | 10:48 | 10:51 | 页面"数量" |
|---|---|---|---|
| PO260923001-1 | 入库 +100 | 领料出库 −100 | 从 **100** 变 **0** |

**变的不是入库记录，是"剩余"**。入库 100 这个事实被记在 **入库单明细**（`inventory_inbound_item.quantity=100`）和 **流水**（`+100，变动前 0 → 变动后 100`）里，页面没展示。

## 2. 业内标准做法：三层结构 + 「收发存」

| 层 | 业内名称 | 职责 | 可改性 |
|---|---|---|---|
| ① 单据层 | 入库单/出库单（凭证） | 记录"这批入了/出了多少"，**原始量就在这里** | **不可改**，错了只能开**红字/冲销单** |
| ② 流水层 | 库存流水 / 物料凭证（SAP: MSEG；WMS: inventory transaction；金蝶用友: 出入库流水） | 每一次变动一条，带 **变动前 → 变动后** | **只增不改**（append-only），这是唯一审计依据 |
| ③ 余额层 | 批次/物料结存（SAP: MCHB 批次库存） | 只回答"还剩多少" | **派生值**，随时可由 ①② 重算 |

界面上，业内统一叫 **「收发存台账」**：**期初 + 收 − 发 = 结存**，并且**入库量、出库量、结存量三栏一起显示**（不是只显示结存）。
- SAP：物料凭证 + 批次库存表（批次维度有收货量/发货量）；
- 金蝶/用友：出入库流水 + 收发存汇总；
- WMS：库存事务 + 批次台账 + 批次追溯。

**五条业内铁律**（我们目前只做到了其中 1 条半）：
1. 原始凭证不可改，只能红冲；
2. 流水只增不改，冲销用**反向凭证**（不做 UPDATE）；
3. 余额是派生值，可由流水重算，且**必须能重算一致**；
4. 任何库存变动都必须**同时写流水**（不允许"只改余额不写流水"）；
5. 批次可追溯：批次 → 入库单 → 供应商/来料检验 → 出库单 → 成品。

## 3. 与我们的现状逐条对照

| 层 | 业内要求 | JJX 现状 | 差距 |
|---|---|---|---|
| ① 单据 | 原始入库量保留 | ✅ **已保留**：`inventory_inbound_item.quantity`（如 100/210） | 页面没入口，看不到 |
| ② 流水 | 每笔变动留痕、只增不改 | ✅ **已有**：`inventory_transaction`（10 笔，带 before/after、来源单据、操作人） | **没有页面入口**（只能进单据详情看） |
| ③ 余额 | 派生值 + 能重算 | ✅ 批次表 `inventory_stock_item.quantity` = 结存；汇总表可重算（`check-stock-summary` 全绿） | ⚠️ 批次表**只有结存一列**，没有"累计收/累计发" |
| ④ 变动唯一入口 | 只允许走受控入口 | ✅ 已有 `InventoryStockMutationService.applyDelta()`（09-22 收口）：强制带流水类型、不允许为负、改动即写流水 | ⚠️ 但批次表**无原始值/无版本/无审计列**，事后看不出原值 |
| ⑤ 页面口径 | 收发存三栏 | ❌ 只显示结存 | **这就是"看不懂"的根因** |

> 结论：**底子（单据 + 流水 + 唯一入口）其实都在**，缺的是**展示层与追溯入口**，加上**口径没写下来**。

## 4. 方案总览（改哪里、改成什么样）

```
        ┌─────────────── 单据层（不可改） ───────────────┐
        │  入库单 PO260923001 明细：RM001585 收 100      │
        │  出库单 PICK-…-1    明细：RM001585 发 100      │
        └───────────────────┬───────────────────────────┘
                            │ 每次动作都写一笔
        ┌───────────────────▼───────────────────────────┐
        │  流水层 inventory_transaction（只增不改）      │
        │  +100（前 0→后 100）  −100（前 100→后 0）       │
        └───────────────────┬───────────────────────────┘
                            │ 聚合 / 重算
        ┌───────────────────▼───────────────────────────┐
        │  余额层 批次结存 inventory_stock_item.quantity │
        └───────────────────────────────────────────────┘
                            │
        ┌───────────────────▼───────────────────────────┐
        │  页面：批次明细 = 收发存三栏 + 变动流水抽屉     │  ← 本次改造
        └───────────────────────────────────────────────┘
```

### 4.1 批次明细表格改造后长这样（列头）
| 批次号 | 仓库 | 库位 | **入库数量** | **已出库** | **结存数量** | 预留 | 可用 | 单位成本 | 状态 | 最后入库 | 最后出库 | 操作 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| PO260923001-1 | 原料仓 | - | **100** | **100** | **0** | 0 | 0 | 5.00 | 已用尽 | 10:48 | 10:51 | 变动流水 |

改动点（就是解决你"看不懂"的地方）：
1. **三栏一起显示**：`入库数量`（累计收）、`已出库`（累计发）、`结存数量`（= 收 − 发 ± 调整）；
2. **列名改清楚**：原来的「数量」→「**结存数量**」；顶部加一行黄条说明"结存 = 入库 − 已出库 ± 盘点调整，入库原始量请点「变动流水」"；
3. **0 结存不要再假装"生效"**：状态显示「**已用尽**」（灰色），并提供 **「隐藏 0 结存」** 开关（默认关）；
4. **每行加「变动流水」** → 右侧抽屉：`时间 / 类型(入/出/调拨/盘盈盘亏) / 数量 / 变动前 / 变动后 / 来源单据号 / 仓库 / 操作人 / 备注`，单据号可点跳原单（追溯）；
5. **顶部汇总卡片**补三栏：`累计入库 / 累计出库 / 结存`（与批次合计一致）；
6. 保留现有的 批次号/仓库/库位/状态 筛选，另加 `仅看有结存` 复选。

### 4.2 数据从哪来（字段来源映射，避免"第二真源"）
| 显示列 | 来源 | 说明 |
|---|---|---|
| 入库数量 | 流水正数合计 `SUM(quantity>0)`（等价于 入库单明细按批次合计） | 两处天然一致，**以流水为准** |
| 已出库 | 流水负数合计 `SUM(-quantity<0)` | 含领料/报废/调拨出 |
| 结存数量 | 批次表 `inventory_stock_item.quantity`（或 `收 − 发`） | **两者必须一致**，不一致就是 bug（可做巡检） |
| 变动明细 | `inventory_transaction` 按 `batch_no` 查（索引 `idx_batch_no` 已有） | 直接展示，不改 |

## 5. 为什么不给批次表加「入库数量/已出数量」两列？

业内两种流派，我们选**不加列**：

| | 流派 A：余额表只存结存（**我们选这个**） | 流派 B：批次表存 收/发/结存 三列 |
|---|---|---|
| 真源 | 流水（唯一） | 批次表三列 |
| 优点 | 无第二真源、不会不一致；数据量小聚合即可（有 `idx_batch_no`）；跟 SAP 的 MCHB+凭证一致 | 查询快、页面不用聚合 |
| 缺点 | 每次要看收/发得聚合流水 | **要维护两套数，一旦漏写就"两本账不一致"**；要改写入侧 + 存量回填 |

**关键理由**：我们已经有"唯一写入口 + 流水"，再加两列就等于**引入第二真源**（今天仓库那条 bug 就是"三处口径打架"造成的）。等到批次流水量真的很大（百万级）再考虑物化，现在没必要。

## 9. 风险与注意
1. **性能**：批次多时聚合要按 `inventory_item_id` 收窄（别全表扫）；抽屉分页 20 条；
2. **历史数据**：目前只有 INBOUND/OUTBOUND 两类流水（枚举里还有 TRANSFER_IN/OUT、ADJUST），页面要按枚举**通用**渲染，别写死两类；
3. **权限**：流水读权限是 `inventory:transaction:view`，与批次明细的 `inventory:stock:view` 不同 → 无流水权限时不显示抽屉按钮（或只显示汇总）；
4. **不改现有结构**：本方案**不加表字段、不改写入侧、不动数据**（因此不会引入新的"两本账"风险）；
5. 顺带（不在本方案内，另议）：成品批次 `unit_cost` 为空、`location_id` 全空——见任务 2199 第 ③④ 条。
