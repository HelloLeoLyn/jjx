# 状态 × 动作唯一出处（根治四块）—— dev-20260923-039

> 任务：dev-20260923-039（P1）｜起草：Hermes 2026-09-23
> 触发：2026-09-23 连续出现同一类缺陷（失效批可复检、作废单可处置、台账裸 ID、返工无责任人），
> 用户判定"在打补丁"，要求**成本不计、根治**，且方案必须给**最规范**的而不是最快的。
> 关联：dev-20260923-031（返工可见化）／033（返工回收通道）／034（失效批复检）／036（台账去派工+显示）／038（作废单处置守卫）；并行会话：dev-20260923-022（处置冻结/撤销）、023（守恒门禁）、024（对账栏）

## 0. 一句话结论

**问题不在"少写了一个 if"，而在"什么状态下允许什么动作"这件事系统里没有唯一出处**：后端守卫分散三处、前端每个页面各写一套条件、台账变更还能绕过流程用 SQL 改。
本方案把它收敛成**一个后端投影（allowedActions）**，四块按 1 → 3 → 2 → 4 实施；四块之间是依赖关系，不冲突。

## 1. 问题清单（今晚实测，全部真实发生）

| 现象 | 出处 | 本质 |
|---|---|---|
| 已失效批（被后继版本取代）仍显示「复检/录入/判定/重开」 | 成品检验页 | 前端条件漏 `superseded` |
| 已作废不良单仍显示「处置」、还能算出"待处置 2 件" | 产品不良台账 | 前端只看数量、不看状态 |
| 后端处置入口对作废单/失效批不设防（022⑥ 只落一半） | QualityNcrServiceImpl.dispose | 守卫分散、无唯一出处 |
| 台账显示「工单 #2 / 批 #11」裸 ID | 产品不良台账 | 投影缺字段 |
| 返工工序无人可执行（任务无责任人）、报工后不建复检批 | 返工链路 | 流程缺环（已由 033 补） |
| 随批作废、复检批回写等台账变更用裸 SQL 完成 | 我的两次订正 | 绕过流程改库 |
| guard 备份未登记 `backup-index.tsv`（4 条） | 我的备份 | 规范漏做 |

**共同根因**：① 状态×动作无唯一出处；② 前端状态判断用字符串字面量且门禁抓不到；③ 台账变更缺正式入口；④ 规范动作（备份登记）靠自觉。

## 2. 四块范围、顺序与判据

| 块 | 内容 | 前置 | 判据（做完怎么验证） |
|---|---|---|---|
| **1** | 后端 `AllowedActionResolver`：按对象×状态×链路有效性算出 `allowedActions`，接口统一下发；服务端守卫在**同一处**校验；前端只按 `allowedActions` 渲染 | 无 | 新增状态/新规则只改这一处；任何页面不再出现状态条件；对失效/作废对象返回空动作集 |
| **3** | 台账变更一律走动作：为「随批作废」做正式入口（服务方法 + 权限点 + 写处置记录留痕）；存量订正用同一方法跑（幂等）；禁止裸 SQL 改台账 | 1 | 任何台账状态变化都能在「处置记录」里查到；不再需要手写 SQL |
| **2** | 前端补状态枚举（检验批/不良单/处置动作/工序类型）+ 门禁扩规则：把**字符串状态比较**纳入 `check:status-enums`，基线只减不增 | 1 | 今晚这类 `status === 'VOID'` 判断会被门禁当场拦下 |
| **4** | 备份登记补课（补 4 条）+ 提交自检（禁用 `git add -A`） | 无 | `backup-index.tsv` 覆盖全部 guard 备份；提交只含自己的文件 |

顺序理由：3 需要 1 的动作口径；2 必须在 1 收敛前端条件之后做（否则基线做两遍）。

## 3. 块 1 详细设计

### 3.1 参与对象与状态取值

| 对象 | 状态取值 | 备注 |
|---|---|---|
| 检验批 `quality_lot` | PENDING / INSPECTING / JUDGED / CLOSED + **是否已失效（superseded）** | 失效 = 存在后继复检版本，属**派生**属性，不是状态 |
| 不良单 `quality_ncr` | PENDING / DISPOSING / CLOSED / VOID | VOID = 随批失效或被撤销 |
| 处置动作 `quality_ncr_action` | PENDING / PROCESSING / DONE / VOID | PROCESSING = 返工在制 |
| 返工工序 `production_operation_execution(REWORK)` | 待执行/准备中/执行中/已暂停/已完成/已跳过/已取消 | 复用 ExecutionStatusEnum |
| 工单 `production_order` | 现有 ProductionOrderStatusEnum + 完工阶段（PENDING_SUPPLEMENT 等派生阶段） | 028 已有阶段投影 |

### 3.2 状态 × 动作总表（唯一出处的正文）

**检验批**（失效批一律只读，只留打印/查看）
| 状态 | 允许动作 |
|---|---|
| PENDING / INSPECTING 且未失效 | 录入、判定 |
| JUDGED 且未失效 | 复检 |
| CLOSED 且未失效 | 重开（重开后可复检） |
| 已失效（任意状态） | 仅查看/打印 |
| 有未处置不良 | 不做批级动作，引导去不良台账处置 |

**不良单**
| 状态 | 允许动作 |
|---|---|
| PENDING / DISPOSING（且来源批未失效） | 处置（返工/让步接收/报废） |
| PENDING / DISPOSING 但来源批已失效 | 仅查看（提示"来源批已失效，请对最新版本操作"） |
| CLOSED | 仅查看处置记录（撤销按动作状态判定） |
| VOID | 仅查看 |
| 处置动作 DONE=报废 | 撤销（需 `quality:ncr:revoke`，按 022 已落地） |
| 处置动作 PROCESSING=返工 | 看返工进度；达到"已回收"后系统自动收口 |

**返工工序 / 返工链**
| 环节 | 允许动作 |
|---|---|
| 无返工任务责任人 | 不允许登记返工（登记时 fail-closed，033 已实现） |
| 返工工序 待执行 | 开工（负责人已派工后可报工） |
| 返工工序 执行中 | 报工/补报、完成工序 |
| 返工报工 待审批 | 审批通过 → 自动建"返工复检"批（033 已实现） |
| 返工复检批 已判定 | 走确认入库=回收；判定即收口处置动作（033 已实现） |

**工单**
| 阶段 | 允许动作 |
|---|---|
| 生产中 | 报工/补报 |
| 待补产（良品<计划、无未处置不良） | 补产（按缺口预填，028 已实现） |
| 待不良处置 | 去不良台账处置 |
| 待完工确认 | 完成工单（要求所有工序已完成/已跳过） |
| 待入库处理 | 重试完工入库 |

### 3.3 契约（实现形态）

1. **后端投影**：`AllowedActionResolver.resolve(对象类型, 对象, 上下文)` → `List<String> allowedActions`（取值用枚举，如 `LOT_JUDGE`、`LOT_REINSPECT`、`NCR_DISPOSE`、`NCR_REVOKE`、`REWORK_START`、`ORDER_COMPLETE`）。
2. **下发**：列表 VO 与详情 VO 都带 `allowedActions`（任务树已有同名机制，沿用同一命名与语义）。
3. **守卫同源**：接口入口（处置/判定/复检/重开/开工/完成/撤销）统一调用同一 Resolver 校验，禁止各写 if。取不到动作 → 返回明确文案（含对象名与原因）。
4. **前端**：按钮/入口一律 `v-if="allowedActions.includes(X)"`；**不再出现任何状态条件**（也顺带解决裸 ID：展示字段由 VO 提供）。

### 3.4 明确不做

不引入工作流引擎；不改状态机本身与库存口径；不把入库/出库单纳入本期（并行会话正在改 `InventoryInboundServiceImpl`）。

## 4. 块 3：随批作废的正式入口

- 服务方法已有雏形（`voidOpenDispositionsBySupersededLot`），本次把它升格为**正式动作**：加权限点（如 `quality:ncr:void-superseded`）、写处置记录/台账留痕、幂等；复检换代时自动调用（已接）。
- 存量订正（NCR260923002 等）**用同一方法**重跑，替代手写 SQL；订正结果可在「处置记录」里看到。
- 禁止裸 SQL 改 `quality_ncr` / `quality_ncr_action`（除 guard 备份恢复）。

## 5. 块 2：门禁与枚举

- 新增前端枚举：检验批状态、不良单状态、处置动作类型、工序类型（REWORK/NORMAL）；标签与颜色集中定义。
- `check-status-magic-values.mjs` 扩规则：识别 `xxxStatus === 'XXX'`、`['VOID','CLOSED'].includes(status)` 这类**字符串状态比较**；存量入基线、**只减不增**（`--write-baseline` 仅允许收窄）。
- 门禁跑通后，把今晚这类判断从代码里改为枚举比较。
