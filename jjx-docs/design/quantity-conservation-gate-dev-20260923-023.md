## 1. 为什么做

现有门禁只覆盖"账账一致"（汇总↔批次↔流水、入库明细↔检验批↔流水），**查不出"业务口径被绕过"**：
- 2026-09-23 实证：复检换代把已判报废量洗回良品（库存虚高 2 件），当时三本账门禁**全绿**；
- 同理"换代不重算工单完工数"（工单 200 / 有效 100）也不会被账务门禁发现。

→ 三期把这些**业务守恒关系**变成可执行巡检，接进 `npm run validate`，让"绕过入口手动改数"在提交前就暴露。

## 3. 五条新增校验（④~⑧）

| # | 校验 | SQL 要点 | 期望 |
|---|---|---|---|
| ④ | **判定数量守恒** | 已判定批：`pass + fail = inspected ≤ lot_quantity` | 0 |
| ⑤ | **不良台账守恒** | 批 `fail` = Σ`quality_ncr.defect_quantity`（同批）；且未作废（`status<>'VOID'`）处置量 ≤ NCR 不良量 | 0 |
| ⑥ | **可判上界合规** | 有效批（无后继版本）：`pass ≤ lot_quantity − 该批自身 SCRAP(DONE) − 让步未确认` —— **与 `-021` 判定护栏同口径** | 0 |
| ⑦ | **工单完工口径** | `production_order.completed_quantity` = 有效批合格累计（防 `-018` 复发） | 0 |
| ⑧ | **放行不超合格** | `quality_lot.stored_quantity ≤ pass_quantity` | 0 |

**⑥ 的口径说明（重要）**：按**有效批自身**聚合，**不按整条批链**。原因：本系统是"整批重判（差额）"模型 —— 每次复检都会重新声明整批的不良构成，链级聚合会**重复计入**（实测：同一物理 2 件在两次复检里各记一次报废，链级合计 4 件）。链级/件级守恒需要更细的追溯字段（不良件序列号），列为**待议**（见第 6 节）。

## 5. 边界与误报

1. **存量历史数据**：若历史上存在真实不一致，`--strict` 会拦住提交；可用 `JJX_LOTID_CHECK_SINCE=YYYY-MM-DD` 设基线（沿用既有变量）；
2. **⑥ 与 021 的关系**：应用层已挡（判定时拒绝），巡检是**防绕过/防回归**的第二道；
3. **调拨/盘点产生的 ADJUST**：④~⑧ 不涉及库存流水方向，不受影响。

## 6. 待议（不在本期）

1. **链级/件级数量守恒**：需要"不良件序列号 / 返工件身份"级别的追溯字段，才能判定"同一物理件是否被重复报废或复活"。当前模型（整批重判 + 差额）在链级会重复计入 —— 这是**模型固有**，不是数据错；
