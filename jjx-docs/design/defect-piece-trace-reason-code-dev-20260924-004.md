## 0. 一句话结论

不良现在只对齐到**「批 + 数量」**，原因也只是一段手打文字：能说"这批坏了 2 件、原因是外观颜色"，答不了"是**哪 2 件**、**哪项检验不合格**、**实测多少**"。
本方案做三件事：①**不良件级发号**（一物一号，正常品一律不动）②**原因取自检验单本身**（一级 = 检验项目，二级 = 不合格分级 CR/MA/MI，不再另起全局原因字典）③**逐件实测值落库**（把检验单里已有的"逐件实测"按件拆开，件号才带内容）。
三件事都落在**同一个判定/处置弹窗**里，所以并成一批做。

### 4.3 原因口径（v2 修订：**不建全局字典**）

- **一级：检验项目** —— 直接取 `quality_lot_item.check_item`（FQC 项目由质量模板给出、页面不可编辑；已有 216 行真实数据可直接统计）。
- **二级：不合格分级** —— `CR`（致命）/ `MA`（严重）/ `MI`（轻微），取 `quality_lot_item.cr/ma/mi_quantity` 的口径，业内同构（金蝶/用友缺陷等级、SAP 缺陷代码分组）。
- **兜底**：检验项目里没有的情况，允许「其他 + 文本说明」（沿用 `defect_reason` 文本框，但降级为补充说明）。
- **不做**：不新建 `quality_defect_reason` 全局字典（v1 §4.3 作废）；不做"检验项目下的缺陷代码子字典"（R1 选 A，B 留待将来确有需要时再评估）。
- **统计能力**：台账/报表可按「检验项目 × 分级」分组汇总（例：外观-MA 占报废 70%），这是原来手打文本给不了的。

## 5. 流程与状态机

```
① 检验录入：按检验项录 standard / 实测值 / CR·MA·MI      ← 已有（quality_lot_item）
② 判定：检验数量 / 合格 / 不良数量 + 【选不合格检验项目（多选）+ 分级】+ 补充说明（文本，可空）
        └─ 同事务按件发号并落件（v2）：
             件号 NCR…-D001…D00N（N = 不良数量，不限数量）
             每件带：check_item（所选项）、defect_level、actual_value（sample_values 按 | 拆）、sample_index
             幂等：uk(ncr_id, seq_no)；重复判定不重复发号
③ 处置：选件（默认全选，可部分 / 按状态 / 按区间）→ 校验件数 = 处置数量
        ├─ 返工 REWORK     件 → REWORKING → 复检合格回收 → RECOVERED（入良品库存）
        ├─ 让步 CONCESSION 件 → CONCEDED（客户确认后转良品库存）
        ├─ 报废 SCRAP      件 → SCRAPPED（口径A：无库存扣减）
        └─ 退货 RETURN     件 → RETURNED（成品侧入口后续开，来料侧已用）
④ 撤销（受控）：报废撤销 → 件 SCRAPPED → PENDING，处置单 DONE → VOID（与 045 §2 撤销流一致）
⑤ 随批作废（022）：复检换代 → 未处置/未完处置件随单 → VOID（禁止再处置）
⑥ 补产 / 补料（002 已实施）：不动件级（补产是"新做的件"，不属不良件）
```

**逐件实测值解析规则（v2 新增）**：
- 解析源：被判为不良的那个检验项目的 `sample_values`（按竖线分隔的样本值串）拆分；
- 段数 = 不良件数 → 一一对应（`sample_index` = 段序）；段数 < 件数 → 缺的件 `actual_value` 留空 + 页面提示"实测值不完整"；段数 > 件数 → 只取前 N 段 + 提示；
- 不做格式强校验、不阻断判定（沿用"先录数、后纠错"的既有风格）；复检换代时件随单作废，不跨版本搬运。

## 9. 验收（一期）

1. 判定 2 件不良 + 选「外观 / MA」→ 生成 `NCR…-D001 / D002`，状态 `PENDING`，且每件带 `check_item=外观`、`defect_level=MA`；重复判定不重复发号。
2. 逐件实测：该检验项 `sample_values` 有 2 段 → D001/D002 各带对应实测值；段数不足时有提示且不阻断。
3. 处置 D001 返工、D002 报废 → 件状态 `REWORKING` / `SCRAPPED`；`piece_count` 与件数一致；件数守恒 0 差。
4. 原因必选：不选检验项目/分级直接提交被拒；台账能按「检验项目 × 分级」汇总（同一原因可统计）。
5. 撤销报废 → D002 回 `PENDING`，处置单 `VOID`（与 045 撤销流一致）。
6. 大批量：判定 500 件 → 提示"N 个件号待生成"、列表分页、处置全选一次通过、门禁聚合口径正确。
7. 回归：库存五项 / 检验批九项 / 数量守恒八查仍全 0；工单缺口与补产链（002）不受影响。

| 展示 | 件列表**分页**（默认 20/页）+ 状态筛选 + 懒加载；详情只在展开时拉取 |
| 处置 | 支持**全选 / 按状态选 / 区间选**（D001~D200）；后端一次校验守恒（聚合，不逐件循环） |
| 校验 | 门禁第 ⑩ 查按 NCR **聚合汇总**，不逐件扫描 |
| 极端量 | 判定弹窗先提示"N 个件号待生成"；N ≥ 5000 时列表只给摘要 + 导出，避免浏览器卡死 |

## 12. 建议（供采纳，非本期强制）

1. **发号开关化**：`sys_config` 加 `quality.defect-piece.enabled`，出问题一键回退到数量口径。
2. **检验项目（含分级口径）的维护归口明确到质量模板**：既然原因取自检验项目，模板里项目清单的准确性直接决定统计质量；建议模板维护设专人（品质主管），并给"项目命名规范"一句约束（不用同义词、不带日期）。
3. **件号做成后续所有质量动作的 join key**（处置 / 退货 / 召回 / 客诉 / 报废单），一次做对。
4. **三期报废单直接用业内命名**（报废单 / 不合格品处理单），替掉"台账 + 处置记录两处拼"。
5. **`defect_reason` 保留为补充说明**，不废弃、不清洗历史数据。
6. 以后同类业务（质量 / 库存 / 生产交界）默认先对齐**金蝶 / 用友 / SAP 的形态**再落设计，本方案即按此写。

## 13. 风险与依赖

| 风险 | 影响 | 处置 |
|---|---|---|
| 判定处发号增大判定事务 | 大批量判定变慢 | §11 分批插入 + 提示 |
| 逐件实测值格式依赖（`\|` 分隔、段数与件数不齐） | 件上实测值缺失或错位 | §5 解析规则：不齐则留空 + 提示，不阻断；`sample_index` 保留可追溯 |
| 检验项目命名不统一（同义不同名） | 统计口径碎片化 | §12 建议 2：模板维护归口 + 命名约束 |
| 与复检换代 / 随批作废一致性 | 件挂着失效批 | 在 022 的 VOID 路径同步置件 `VOID` |
| 门禁转 strict 误拦历史数据 | 提交被拦 | 两步上线：先提示 5 个工作日再 strict |
| 五期成本缺数据源 | 无法算金额 | 先查物料单价 / 工时费率是否存在再开工 |
