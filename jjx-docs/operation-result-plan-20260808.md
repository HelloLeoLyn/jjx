# 操作结果展示方案对比（DEV-731 · 2026-08-08）

> 背景：DEV-731「操作结果组件优化」——现有 OperationResultDialog（4 视图结果弹窗）仅样品单接入。
> 本文档对比两版方案，供决策。**结论先行：推荐方案 B（ERP 惯例版），且按"不大改动"原则实施。**

---

## 一、方案 A：现设计（4 视图结果弹窗）

**形态**：每次操作成功弹窗，含 4 种视图（标准卡 / 快递单 / 聊天通知 / Markdown 登记）+ 一键复制。

**优点**
- 信息展示丰富，操作后"仪式感"强
- 样品单链路已跑通，有参考实现

**缺点（偏离 ERP 惯例）**
- 成功也弹大窗：打断操作流，高频操作（确认/取消/审核）会烦
- 快递单视图与 A4Canvas 打印页职责重复；聊天视图与通知铃铛重复
- 视图多 → 每个新模块接入都要组装一堆字段，样板代码多
- 无失败态：操作失败/部分失败没有对应展示
- 状态字段靠页面手拼 → 易漏（调拨"状态为 null"就是这么暴露的）

**成本**：改造组件 + 每个接入页面写组装逻辑；维护 4 套视图。

---

## 二、方案 B：ERP 惯例版（推荐）

**形态**：`成功 = 轻提示 + 状态刷新`；`失败/部分成功 = 结构化明细弹窗`。

| 场景 | 反馈方式 | 对应 ERP 惯例 |
|---|---|---|
| 成功 | toast（ElMessage）+ 列表刷新 + 状态标签更新；仅当有"下一步指引"才弹结果卡 | SAP 过账返回凭证号、用友单据状态推进 |
| 失败 | 弹窗显示**具体原因**（错误码 + 明细，如"第 3 行物料 M-01 库存不足：可用 10 需 15"） | SAP S/W/E/A 消息体系 |
| 部分成功（批量） | 弹窗显示汇总：成功 N / 失败 M + 失败明细列表（可下载） | ERP 批量导入结果报告 |
| 关键操作 | 预览后执行（OperationPreviewDialog 已有，✅ 不动） | SAP 模拟过账 |
| 审计 | 操作日志/流水留痕（已有，✅ 不动） | ERP 标配 |

**实施范围（不大改动）**
1. **组件小改**（OperationResultDialog，约半天）：
   - 加 `type: 'success' | 'fail' | 'partial'`（默认 success，不破坏样品单）
   - fail/partial 渲染"原因 + 明细列表"视图；标题 ✅/❌/⚠️ 动态
   - 现有 4 视图保留不删（样品单继续用），只是新接入不再依赖它们
2. **接入收敛**：
   - 新接入模块（调拨/生产/出入库/审核）只走"toast + 失败明细"，**不接 4 视图大弹窗**
   - 优先接调拨（用户实测场景）：确认调出/调入/取消
3. **字段兜底**（小）：docNo/状态缺失显示 `-`，杜绝"null"外露
4. **可选二期**：注册表自动装配（fromStatus/toStatus 前后端对齐），防漏字段——机制价值，不急

**优点**
- 符合主流 ERP 操作习惯，高频操作不被打断
- 失败反馈质量是当前最大短板，方案 B 直接补上（还对接 DEV-726/727 导入失败明细）
- 改动面小，不重构、不删功能、不推全模块接入

**成本**：组件小改 + 调拨 1 个模块试点接入；后续模块按模板复制。

---

## 三、对比一览

| 维度 | 方案 A（4 视图弹窗） | 方案 B（ERP 惯例版） |
|---|---|---|
| 成功反馈 | 大弹窗 | 轻提示 + 状态刷新 |
| 失败反馈 | 无 | 结构化原因/明细（核心价值） |
| 批量结果 | 无 | 成功/失败汇总 + 可下载 |
| 符合 ERP 惯例 | 低 | 高 |
| 接入成本 | 高（每页组装字段） | 低（模板化） |
| 改动面 | 大（含删减取舍） | 小（加 type + 兜底 + 试点接入） |
| 风险 | 影响样品单现有体验 | 低（默认 success 不破坏现状） |

---

## 四、决策项

- [ ] 采用方案 B（推荐）
- [ ] 一期范围：组件加 type（fail/partial 明细视图）+ 字段兜底 + 调拨接入试点
- [ ] 二期（可缓）：注册表自动装配，前后端状态对齐
