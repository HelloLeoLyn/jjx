## 5. 多 agent 协作规则

现实：同一个仓库同时有 **OpenClaw / Hermes / Codex / 用户手动** 在改。今天实测到的冲突面：同文件多会话同时改（AGENTS.md、CONVENTIONS）、一个文件混着多个任务的改动、提交时误带别人 staged 内容、别人删/移文件（迁移 101~106、assets）。

| # | 规则 | 状态 |
|---|---|---|
| 1 | **任务即锁**：动手前在 `sys_task` 登记任务 + 在任务描述里写**白名单文件**；同一文件同时只允许一个任务在改 | ✅ 已进 CONVENTIONS §11 |
| 2 | 开工先跑 `bash scripts/agent-preflight.sh`（闸门/库版本/只读账号/门禁/工作区） | 🟡 规则已有，非强制 |
| 3 | **提交纪律**：commit 前看 `git diff --cached --stat`；同一文件多任务改动时用 `git add -p` 精确挑 hunk；别人 staged 的先 `git restore --staged` | ✅ 已进 CONVENTIONS §11 |
| 4 | **禁改清单**：`AGENTS.md`（需用户批准）、`jjx-docs/sql/`、`jjx-docs/standards/` 禁删禁移；别人的 M/D/?? 一律不还原 | ✅ 已进 CONVENTIONS §11 |
| 5 | **归属只认基线**：任务开始前的 M/D/?? = 别人的；开始后才冒出来的 = 越界嫌疑（还原前也要问用户） | ✅ 已进 CONVENTIONS §11 |
| 6 | 讨论≠执行：只有用户说"做/执行/改/写/建/你来"才落盘（CONVENTIONS §9） | ✅ 已有 |
| 7 | **可见性缺口**：现在没有"谁在跑什么任务"的视图 → 建议加一个查询/看板（任务号 + 白名单 + 状态） | ⬜ 待做 |
| 8 | 冲突仲裁：**谁先提交谁算**，后来者 rebase/让；真有冲突交中立方处理 | 🟡 口头规则 |
