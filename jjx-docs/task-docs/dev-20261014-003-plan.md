## 3）组件设计（本卡主体）

### 3.1 参数（全部可选；**参数即查询条件**）

| 参数 | 语义 | 不传时 |
|---|---|---|
| `sourceType` | 来源类型（`inquiry`=询价单、`quotation`=报价单…，取 `AttachmentEnum` 中文对照） | 不出"本单"这一段 |
| `sourceNo` | 来源单号（如 `INQ261014001`）；与 `sourceType` 成对 | 见下 |
| `sourceId` | 来源内部 id；与 `sourceType` 成对，`sourceNo` / `sourceId` **二选一** | 见下 |
| `traceId` | 链路标识 | 不出"同链路"这一段 |
| `productId` | 产品 id | 不出"产品"这一段 |
| `columns` | 要显示的列（默认 10 列 key） | 用默认列 |
| `title` | 列表标题（默认「文档」） | 「文档」 |
| `includeLegacy` | 是否启用本单老通道历史查询；显式 true 才启用 | 空（undefined），不自动赋 false |

**至少给一个查询条件**（`sourceType`+单号/ id、`traceId`、`productId` 之一）；一个都没给 → **不发请求**，显示「未指定查询条件」。

### 3.2 取数与合并

1）三个取数单元按参数启用，各自独立请求，最后**按 `attachmentId` 去重**（同一份文件多段命中只显示一行，保留首次出现的段）：
   - 本单段：`sourceType` + (`sourceNo` 或 `sourceId`) → `GET /refs`（带来源单号时由后端解析成 id）；
   - 同链路段：`traceId` → `GET /attachment/by-trace/{traceId}`；
   - 产品段：`productId` → `GET /attachment/refs/product/{productId}`。
2）**段级容错**：某段无权限 / 单据不存在（后端会抛"业务来源不存在或不唯一"）→ 该段置空并给一行提示（如「来源不可见或不存在」），**不整块报错、不影响其他段**。
3）不写库、不缓存到 localStorage；组件卸载即丢弃。
4）includeLegacy 留空或 false 不启用独立历史查询；true 时复用本单老接口。接口限制：老接口只接受 sourceId；sourceNo 查询有引用时使用返回引用的 sourceId，无引用可解析时显示历史段提示，不猜ID、不改老接口。链路与产品端点保持原语义。

### 3.3 列（默认 10 列，从字段清单生成）

1）默认列（顺序固定）：原文件名（点名字预览）/ 来源类型 / 来源单号 / 一级类型 / 二级类型 / 大小 / 上传人用户名 / 上传时间 / 状态 / 操作（下载）。
2）每列取数：原文件名←`fileName`（后端 refs 回填）；来源类型←refs 行 `sourceType`（转中文）/ trace 行 `bizTypeName`；来源单号←refs 行 `sourceNo` / trace 行 `sourceNo`（老通道行无 → `-`）；一级/二级类型←`documentType` 两级对照（仅 refs 行有）；大小←`formatSize(fileSize)`；上传人←`createBy`（trace 段无 → `-`）；上传时间←`formatTime(createTime)`；状态←行 kind；操作←下载。
3）状态取值：本单引用=`已绑定`、同链路=`同链路`、（`includeLegacy` 时）老通道=`历史`。状态相关展示必须用现有枚举/常量，**禁止裸字面量**（见根 `AGENTS.md` 状态枚举铁律）。
4）列定义改动只能改 `attachmentFields.ts`（加列/删列/改列名/调宽度 = 只改一处）；默认集用只读场景集合表达。

### 3.4 交互

1）点原文件名＝预览（复用 `useAttachmentPreview`：图片进查看器，其他开新窗）；
2）操作列**只有下载**：refs 行 `/system/attachment/refs/{refId}/download`；同链路行 `/system/attachment/download/{id}`；
3）无勾选、无行内编辑、无按钮组；
4）空态：查不到 → 「暂无文档」；无查询条件 → 「未指定查询条件」。

### 3.5 后端改动（唯一必须项）

1）`GET /system/attachment/refs` 增可选参数 `sourceNo`（与 `sourceType` 配对；与 `sourceId` 二选一）。
2）`AttachmentSourcePolicy`：每个来源补一条"按单号查 id"的 SQL（`SELECT inquiry_id FROM sales_inquiry WHERE inquiry_no=? AND deleted=0` 之类）。**单号均为唯一键，已核对**：`sales_inquiry.inquiry_no`、`sales_quotation.quotation_no`、`sales_order.order_no`、`purchase_order.order_no`、`production_order.order_no`、`purchase_payment.payment_no`、`sys_task.task_code`。
3）**权限顺序必须**：先按单号解析出 id → 再判来源权限（沿用现有 `sales:inquiry:view` 等前缀）→ 无权限按"该段空"处理；**不得先返回内容**（否则可拿别人单号探测存在性）。
4）解析不到 / 单号已删 → 视为空，不抛业务异常给前端。
5）同链路段、产品段**复用现接口**，不改。
