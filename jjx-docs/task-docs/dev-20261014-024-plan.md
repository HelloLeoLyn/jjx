## 0）速览

一句话：操作确认弹窗里的"证据附件"上传，从老通道挪到公共附件组件。

现状：`jjx-web/src/components/OperationPreviewDialog/index.vue:268` 直接拼 `/system/attachment/upload`；该弹窗是**通用**的——来源类型/单据 ID 由各个调用方传入。

**这一项的特殊性**：范围不由这一个文件决定，而是由**调用方的来源**决定 ⇒ 先盘调用方，再定范围。

## 1）目标

1）盘点所有用该弹窗上传证据附件的调用方，列出每个调用方对应的来源（如询价/报价/订单/付款…）；
2）来源已在白名单里的 → 换公共附件组件；不在白名单里的 → 记录清楚、**不要硬塞到别的来源**（另立卡扩来源）；
3）删除语义改成"解除引用"。

## 2）范围与必读

改：`jjx-web/src/components/OperationPreviewDialog/index.vue` + 上一步盘出来的调用方（逐个）。
必读：`components/attachment/AttachmentCenter.vue`（入参）、样板 `git show b75a3f5c`、白名单 `AttachmentSourcePolicy.java`。

## 3）约束

1）**先交调用方盘点清单再动手**（清单要含：调用方文件、传入的来源类型、来源是否在白名单、是否需要后端）；
2）归属按表内字段判定（本轮口径）；
3）删除=解除引用；不考虑旧数据；
4）弹窗的既有交互/校验/提交流程不动。

## 4）验收

**行为**：各调用方在确认弹窗能上传证据附件；确认后在其对应单据（详情/附件区）能看到、可预览/下载/解绑。
**反例**：① 只改弹窗没改调用方传参 ⇒ 传上去挂错单据；② 把不在白名单的来源硬塞成别的来源 ⇒ 归属错位；③ 没做盘点就动手 ⇒ 漏掉调用方。
**命令**：`cd jjx-web && npx vue-tsc --noEmit && npm run check:status-enums && npm run check:docs`（如涉后端加 `mvn -o -q compile`）。
