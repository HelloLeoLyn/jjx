# dev-20261014-029 任务卡（实现 019 方案B：公共上传/建引用支持图纸元数据）

> 任务码：dev-20261014-029 ｜ 2026-10-14 ｜ plan（**实现卡，可直接派人**）
> 模板真源：`jjx-docs/guides/agent-task-brief.md`
> 来源：`dev-20261014-019` 已出卡并拍板**方案B**；本卡是其实现，落地后解锁 `dev-20261014-016` 第 3 项（工程图纸迁公共组件）

## 0）速览

一句话：让**公共附件链路**（temp 上传 → 建引用）能写 `sys_attachment` 既有的**图纸元数据列**，这样工程图纸迁进公共组件时字段不丢。

现状（019 卡已核实）：图纸元数据（图种 / 图纸编号 / 图纸名称 / 版本 / 原稿-打印件）**只在 `sys_attachment` 的列上**；老写走 `/system/attachment/upload-product`；公共路径 `AttachmentCenter → useAttachmentRefs`（temp 上传 → 建 ref）**不带也不写这些列**。

## 1）目标

按 **方案B** 实现：在公共上传/绑定的 DTO 与落库处**增加可选的图纸元数据**，落库仍写 `sys_attachment` 既有列；图纸库的读取口径**不变**（不搬列、不新增表）。

## 2）范围与必读

范围：后端上传/绑定 DTO + Service 落列（配 `SysAttachmentRefController`/`AttachmentRefService` 的既有端点）。
必读：
- `jjx-docs/task-docs/dev-20261014-019-plan.md`（方案B 原文与三条候选）
- 老写路径：`jjx-web/src/views/engineering/drawing/components/EngineeringDrawingLibrary.vue:246`（`uploadProductFile(..., {drawingNo,drawingName,version,fileRole})`）
- 元数据编辑：`PUT /system/attachment/{id}/drawing-metadata`
- 公共路径：`jjx-web/src/components/attachment/AttachmentCenter.vue` + `useAttachmentRefs`

## 3）约束

1）**不改图纸库现有读列口径**：图种分类 tab、图纸/版本分组、原稿 vs 打印件唯一性、元数据编辑都必须照旧；
2）**不新增表**（方案C 已否）、**不把图纸列搬到引用表**（方案A 已否）；
3）归属按表内字段判定（本轮口径）；不考虑旧数据；
4）不动其它来源的附件行为。

## 4）验收

**行为**：图纸经公共组件（`AttachmentCenter`）上传后——图种 / 编号 / 名称 / 版本 / 原稿-打印件**能写能读**；图纸库的分类分组、同图纸同版本唯一性、元数据编辑**不受影响**；引用表里有该产品的引用行（产品维度可见）。
**反例**：① 只写引用不写图纸列 ⇒ 图纸库分组/唯一性失效；② 把图纸列搬到引用表 ⇒ 老读取少字段；③ 上传不带 `product_id` ⇒ 产品维度的引用列表查不到。
**命令**：`cd jjx-server && JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64 mvn -o -q compile`（并跑相关测试）；`cd jjx-web && npx vue-tsc --noEmit && npm run check:status-enums && npm run check:docs`；页面点击实测未做须写"未验证"。
