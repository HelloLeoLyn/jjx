## 0）速览

一句话：让"采购发票"成为公共附件（引用表 `sys_attachment_ref`）认可的一种**来源**，并把发票页的文件上传从"发票自己的临时文件通道"换成**公共附件组件 + 临时上传 + 校验时随事务建引用**。

**为什么改动面大（先说清，这不是过度设计）**：
1）来源白名单里没有"采购发票"这一种 ⇒ 后端必改（照 018 给收货票据新增 `purchase_receipt` 的同款做法）；
2）发票文件是"先临时上传、校验(verify)通过才算数"的语义 ⇒ 需要"临时上传 → 校验时建引用 → 按来源查"三件套（018 就是新写了 133 行的 `PurchaseReceiptAttachmentService`）；
3）前端上传/列表/删除/下载整段要换公共组件写法（行数多，大半是删老代码）。

**想要少改**：发票文件挂"采购订单"来源（零后端）——**不采用**，因为发票是独立单据、有自己的发票号，挂订单会让归属错位（本轮口径：归属按表里字段判）。

## 3）约束

1）**归属按字段判**（本轮用户口径）：引用行按 `product_id`/`source_id` 等表内字段判定与过滤，不做并集、不做分层、不做兜底。
2）**不动发票业务逻辑**：只换附件通道；校验(verify)的状态流转、金额、单据编号一律不动。
3）**随事务绑定**：引用必须在 verify 的**同一事务**内建立（照 018），不许"先返回成功再异步补"。
4）**删除=解除引用**（042 P4），不真删文件。
5）老临时文件接口先**保留**（历史行还要能看），但发票页不再新增老通道数据；等历史行清零后再另立卡退役。
6）**不考虑旧数据**（用户 2026-10-14 定）：老行不在新列表里出现，不做存量迁移。

## 4）验收与验证

**行为**
1）发票页选订单 → 上传文件（可多张）→ **校验通过后**在发票详情里能看到这些文件；
2）发票列表/详情的文件可预览、下载、解除引用；
3）同一发票的多次上传互不串（按发票 ID 归属）；
4）无权限账号（缺 `purchase:invoice` 读权限）看不到附件。

**反例（看似通过其实错）**
1）只在"新建"时建引用、verify 时不建 ⇒ 校验后文件丢；
2）引用建在事务外 ⇒ verify 失败回滚了、引用却留下（脏引用）；
3）把发票文件挂到 `purchase_order` 名下 ⇒ 订单凭证列表被发票文件污染；
4）忘了给来源配"按单号查"或权限前缀 ⇒ 挂上后查不到/无权限被拒。

**命令**
- 后端：`cd jjx-server && JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64 mvn -o -q compile`，并跑 018 同款测试
- 前端：`cd jjx-web && npx vue-tsc --noEmit && npm run check:status-enums && npm run check:docs`
- 页面点击实测由执行者补；未做必须写「未验证」
