# dev-20261013-043 — S5「明细行上传附件」方案（**已定案：方案 2**）

> 任务码：dev-20261013-043（续 dev-20261013-042「M5 附件存储统一到 refs」）
> 日期：2026-10-13 ｜ 状态：**已定案，可开工** ｜ 范围：**报价单、询价单**的明细行

---

## 一、目标

- **现状**：报价/询价的附件只在「单据级」区域整单上传；**明细行无法针对某个产品单独传附件**。
- **目标**：在**明细行**提供上传入口，让附件"跟着产品走"；要点：**操作员无感知**、**不产生任何多余数据行**、**行级精确**。

---

## 三、方案 2 技术明细

- **加列**：`sys_attachment_ref.product_code VARCHAR(64) NULL`（内部字段，界面不可见）——**加的是列，不是数据行**。
- **绑定**：行内上传/绑定建引用时，把**该行产品编码**写入 `product_code`（未保存时先进草稿队列，保存后绑定）。
- **聚合**：产品详情「业务流转附件」按 `ref.product_code = 该产品编码` 精确匹配（替换原"按 product_id / 来源单据兜底"）。
- **不建档**：产品表 `product` **一行都不新增**。
- **落库形态**：未保存 → 只有 `sys_attachment`（TEMP）；保存后 → 多一条 `sys_attachment_ref`（带 `product_code`）。

## 四、为什么选方案 2（对比）

- **vs 方案 1（按需建档）**：方案 1 会在产品表**多出数据行**（违背"不多余数据行"）；方案 2 **不建任何产品档案**。
- **vs 方案 3（只挂单据级）**：方案 3 做不到按行——同一单据里 A、B 两个产品会**互相看到对方附件**（多露）；方案 2 **按行精确**。
- **成本**：只加**一列**（列 ≠ 数据行），一次小迁移；顺带把 #046 的展示口径一并解决。

## 五、未保存兜底清理（**不在本卡**，另立小卡）

- 现状：未保存的 TEMP 附件落 `sys_attachment`（`upload_state=TEMP`，保留期 7 天），**系统不自动物理删除**（V1-A 起禁用自动删除：`trg_attachment_v1_no_delete` + "recycle auto-deletion is disabled"，清理只走管理员人工预演）。
- 决定：**S5 不引入自动删除/清理**（保持安全边界，避免破坏 V1-A）。这层**另立小卡**处理（若日后要放宽删除守卫，需单独拍板）。

## 六、实施步骤（分步、各自静态自查）

- **S5-1（后端·迁移）** 新增迁移：`sys_attachment_ref` 加列 `product_code`。
- **S5-2（后端·绑定/聚合）** `AttachmentRefDTO` + `AttachmentRefService.create` 写入 `product_code`；产品详情聚合改按 `product_code` 匹配。
- **S5-3（前端·报价单）** 明细行加文字按钮「上传附件」（移除行内「产品资料」），弹窗复用公共附件中心，按行携带产品编码；未保存走草稿队列。
- **S5-4（前端·询价单）** 同上。
- 验证：`vue-tsc --noEmit` / `mvn -o compile` / 门禁（`check:status-enums`、`check:docs`）；**不做 E2E**，运行态由用户验证。

## 七、风险 / 注意

- "加一列"需走迁移（用户手工备份后执行 `scripts/db-migrate.sh`）。
- 产品详情改为"按编码精确"后：**老的、无编码归属的整单附件**将不再出现在产品详情（符合"收紧"；如需兼容，另行讨论）。
- 明细行需稳定 key（用**产品编码**；空编码行不给入口）。
