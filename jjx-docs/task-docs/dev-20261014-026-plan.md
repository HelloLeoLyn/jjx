# dev-20261014-026 任务卡（质量模板上传接入公共附件）

> 任务码：dev-20261014-026 ｜ 2026-10-14 ｜ plan（**交接包**）
> 来源：未接公共上传组件清单 第 13 项

## 0）速览

一句话：质量模板的模板文件上传换成公共附件组件。

现状：`jjx-web/src/views/production/quality-template/index.vue:87` 仍用老上传组件 `AttachmentUploader`（`:96` 引入；老通道 `bizType='quality_template'`，带 `:version`），上传成功后回填模板的 `file_id`。

**需要后端**：来源白名单里没有 `quality_template`。
**先要定的一件事**：模板表已有 `file_id` 指向 `sys_attachment`（见 `QualityTemplateRegistryServiceImpl.fillHasFile`）——迁移时要先定：`file_id` 继续保留（引用只是补充），还是改成"只认引用"。**先给结论再动**。

## 1）目标

1）新增来源 `quality_template`（照 018/022 先例：权限前缀建议沿用 `production:quality-template:*`；单号 SQL 取模板记录号）；
2）模板文件上传换成公共附件组件，`file_id` 回填逻辑与新链路一致（按上一步的结论）；
3）删除语义改为"解除引用"。

## 2）范围与必读

改：`jjx-web/src/views/production/quality-template/index.vue`（:87 上传块、:96 引入）、后端 `AttachmentSourcePolicy.java`（+ 若改 `file_id` 语义则涉 `QualityTemplateRegistryServiceImpl`/`fillHasFile`）。
必读样板：`git show b75a3f5c`、`jjx-docs/task-docs/dev-20261014-022-plan.md`。

## 3）约束

1）`file_id` 与新引用的关系**先定口径**（保留 or 替代），别同时维护两个真源；
2）归属按表内字段判定；删除=解除引用；不考虑旧数据；
3）打印/预览模板文件的既有行为不变（`fillHasFile` 的有效性校验如涉及，需同步说明）。

## 4）验收

**行为**：上传模板文件 → 模板列表/详情能看到并有文件 → 打印/下载正常 → 换文件后旧文件不再作为模板文件使用。
**反例**：① `file_id` 与引用两套并存且互相不同步（第二真源）；② 只在新建时写引用、编辑时没换 ⇒ 换文件不生效；③ 权限点选错导致无权限用户看不到模板文件。
**命令**：`cd jjx-server && JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64 mvn -o -q compile`；`cd jjx-web && npx vue-tsc --noEmit && npm run check:status-enums && npm run check:docs`。
