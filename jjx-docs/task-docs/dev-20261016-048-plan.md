3）组件与会话契约

A) 上传入口

复用 AttachmentTempUploader 的选文件、校验能力。通过外部会话执行上传，入口不各建一份队列。请求发起时固定归属上下文，切换产品或单据不能改变进行中上传的归属。

B) Session

由调用方单据编辑容器创建并显式共享，不能用全局单例或仅靠 localStorage 拼接多份内存状态。统一维护待保存附件、已绑定引用、编辑差异、上传及保存状态。订单级产品为空，产品级支持正式 product_id 和待解析的稳定临时行标识；产品编码可展示但不得作为唯一身份，数组下标也不行。已绑定行以 refId 标识，同一文件的不同引用不得互相覆盖。

对调用方暴露完整编辑数据及 dirtyCount、uploadingCount、saving。上传完成、信息编辑、移除成功、保存结果都应及时同步；必须区分“编辑变化”与“后端保存成功”。筛选只改变显示范围，不能丢失隐藏行的改动。

C) Manager

独立管理组件，不内置上传。提供统一列表、归属筛选、信息编辑、详情、预览下载和即时移除。公共组件只接收调用方提供的归属、查看范围、权限、锁定及动作，不判断报价或订单业务状态。只读/无权限不得产生写副作用。

默认隐藏行内保存和批量保存，二者可独立配置。保存范围契约固定：行内=当前行；批量=勾选行中的改动；调用方全部保存=完整会话（含筛选隐藏行）。接口可采用 saveChanges(changes): Promise<结果> 与 validate/getChanges/acceptSaved 或等价的类型化设计；本卡固定并测试契约，049 接通完整保存流程。

本卡如提供可见保存入口，必须接通真实可用的保存处理：等待成功再回填，失败保留改动；不能展示点击无效的按钮，也不能仅 emit 即提示成功。无处理器时不开放该入口。用注入的异步处理器证明成功、失败及范围语义，不要求本卡改后端。

D) 即时移除

沿用已确认口径，无需再次确认：草稿移除草稿/队列项，已绑定解除引用，均不删文件。成功后同步共享会话、待改项和选中状态；失败保持原行及改动。移除后的迟到上传响应不能把附件重新加回。保存与移除应有同一套操作互斥约定，供049沿用。

E) Center 兼容

允许内部组合 Manager/上传入口，保留真实调用方在用的参数、事件、暴露方法及保存行为。新 Manager 默认隐藏保存按钮，不能因此改变旧 Center 调用方原有保存入口。不能保留两套可变状态再互相同步，也不在048做全站调用方迁移。RefList 现有直接请求逻辑需与新共享状态边界协调，不能使新 Manager 的信息编辑偷偷即时提交；旧兼容行为与新通道须明确。
