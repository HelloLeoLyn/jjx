## 1. 放什么（四类，四选一）

1）任务分析（analysis）——动手前的现状核查 / 影响面 / 方案对比
2）任务方案（plan）——打算怎么做（以任务为单位的实施方案）
3）任务完成报告（completion）——做完了的实施记录与自查结果
4）任务验收报告（acceptance）——对某个任务产物的逐项验收（PASS/FAIL/BLOCKED）

## 2. 命名（扁平，不建子目录）

`dev-YYYYMMDD-NNN-<类型>.md`，`<类型>` 只能是 `analysis` / `plan` / `completion` / `acceptance`。

例：`dev-20261012-041-acceptance.md`

## 3. 规则

1）登记 `task-docs/INDEX.md`（一个文件一行；`README.md`、`INDEX.md` 自身免登记）。
2）UTF-8 **带 BOM**。
3）门禁：`cd jjx-web && npm run check:docs`（R5 已登记 INDEX / R6 带 BOM / R7 命名与类型）。
4）正文第一屏建议保留 5 行头信息：`状态` / `任务` / `被取代或取代` / `什么情况看这篇` / `最后复核`。

## 4. 与既有目录的分工（避免一稿两家）

1）本目录：**以任务为单位的四件套**，按任务码集中。
2）`history/`：历史实施记录 / 一次性核查 / 存量报告（2026-10-12 之前的产物留在原处，**不迁**）。
3）`design/`：长期有效的设计（"为什么这么设计"）。
4）`modules/`：模块**现行真相**（不带日期）。

> 判据：文档是"某个 task 的分析/方案/完成/验收"→ 这里；不是 → 按上表回 `history/` 或 `design/`。
