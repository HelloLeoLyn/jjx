## 1）定位与授权边界

1）本方案按“不受现有源代码及数据兼容约束”的假设设计，保存为未来整体重构的备选。以下目录、文件名、接口及数据职责都是建议，不能视为当前实现清单。
2）用户本次只授权保存方案并关联任务。未授权修改业务代码、数据库结构、数据或服务；不创建新的实施任务。本方案不替换主分析中针对现有系统的收窄方案A，也不代表用户已接受关联文档分区展示。
3）目标：查看、编辑分开，上传独立，业务页面组合；不再提供带panel/dialog/upload-only/readonly四模式的万能中心。
4）若未来选用，需另行明确接口契约、后端存储与授权、草稿绑定时机、页面范围及验收，再登记实施任务。假设无兼容约束不等于授权清库、删历史或破坏既有证据。

## 2）组件与数据职责

1）对外三个组件：AttachmentViewer负责查询、查看、预览、下载；AttachmentEditor负责本单引用管理；AttachmentUploadButton只上传并返回结果。页面或弹窗容器由业务页面提供。
2）内部共用AttachmentTable等展示部件。表格不取数、不写数据、不决定业务权限；编辑器通过插槽提供编辑控件和操作，查看器提供只读操作。避免将职责独立的上层组件重新合并成万能表格。
3）文件、业务引用、历史证据分层：文件表示字节资源；引用表示单据使用关系及展示名、分类；历史证据固定某次动作或轮次当时使用的附件。解除引用不等于删除文件，后续引用变动不能改变历史证据。这是概念模型，不规定必须新建三张表。
4）待绑定文件独立显示为上传队列；其他单据的同链路附件在“关联文档”查看区展示，不混入本单可编辑列表。
5）查询范围显式选择本单、关联文档或历史证据；不得由零散参数隐式扩大范围。上传、改名、分类、解绑能力分别判定，后端最终校验权限和业务状态。
6）上传中、待绑定、绑定失败属于上传队列；已绑定属于正式引用，避免共用含义混杂的状态字段。具体状态和转换在实施前定案并纳入项目枚举体系。

## 4）文件名、功能、使用位置及约束

组件目录内路径相对 components/attachment/；API及枚举使用src相对路径。

| 文件名 | 功能 | 用在哪 | 其他 |
|---|---|---|---|
| AttachmentViewer.vue | 查询展示、预览下载 | 单据详情、关联文档、历史证据 | 明确查询范围；不启动编辑或上传逻辑 |
| AttachmentEditor.vue | 管理本单引用，组合上传、队列及编辑表格 | 单据新建、编辑、资料维护 | 关联文档另用Viewer；不修改历史证据 |
| AttachmentUploadButton.vue | 选择文件、上传并返回结果 | 独立上传入口、操作弹窗 | 不擅自绑定业务单据 |
| table/AttachmentTable.vue | 列、排序、空状态及选择交互 | Viewer、Editor | 不查接口、不写数据；操作通过插槽提供 |
| table/AttachmentNameCell.vue | 文件名、预览入口、省略提示 | 公共表格 | 展示名与原文件名含义明确 |
| table/AttachmentTypeSelect.vue | 资料分类选择 | 编辑表格、队列、批量编辑 | 只返回选择，不自行保存 |
| upload/AttachmentUploadQueue.vue | 进度、待绑定、失败与重试 | Editor及需要进度的上传场景 | 与正式引用列表分开 |
| dialogs/AttachmentMetadataDialog.vue | 编辑备注等低频字段 | Editor | 改名、分类优先行内操作 |
| dialogs/AttachmentBatchEditDialog.vue | 批量分类或名称规则 | Editor | 弹窗不嵌入表格主体逻辑 |
| preview/AttachmentPreview.vue | 图片等预览内容及错误提示 | Viewer、Editor | 消费预览结果，不裁决权限 |
| composables/useAttachmentQuery.ts | 范围查询、刷新、加载错误、过期请求处理 | Viewer、Editor | 本单、关联、证据使用明确查询类型 |
| composables/useAttachmentUpload.ts | 校验、上传进度、重试、临时文件队列 | UploadButton、Editor | 队列实例独立；不维护业务引用；Editor与其上传入口共享同一队列实例 |
| composables/useAttachmentEditor.ts | 绑定、改名、分类、解绑及刷新 | Editor | 按草稿隔离；绑定时机由业务契约明确，正式数据以后端结果为准 |
| composables/useAttachmentPreview.ts | 获取预览地址、切换文件、资源释放 | Viewer、Editor | 引用及历史证据走对应授权入口 |
| attachmentColumns.ts | 字段名、列宽、默认列集合 | 公共表格 | 读写共享字段定义，可选不同列 |
| attachmentFormat.ts | 大小、时间等格式化 | 表格、队列 | 纯函数，不依赖页面 |
| types.ts | 文件、引用、证据、上传项、查询范围类型 | 附件模块 | 不把上传队列与正式引用塞进万能行类型 |
| api/system/attachmentFile.ts | 上传和文件资源接口封装 | 上传、预览逻辑 | 不承担业务绑定 |
| api/system/attachmentRef.ts | 引用查询、绑定、维护接口封装 | 查询、编辑逻辑 | 解除引用与删除文件分开 |
| api/system/attachmentEvidence.ts | 历史证据查询及授权访问接口封装 | 历史记录Viewer | 无普通历史证据编辑接口；后端契约待设计 |
| enums/system/AttachmentEnum.ts | 文件及上传状态等领域枚举 | 组件、逻辑层 | 遵循项目统一枚举规范，不写页面局部状态映射 |

## 5）页面组合

| 场景 | 组合 | 行为 |
|---|---|---|
| 单据新建、编辑 | AttachmentEditor | 草稿队列隔离，业务保存成功后按契约绑定 |
| 单据详情 | AttachmentViewer | 查看本单附件 |
| 同链路关联文档 | 单独AttachmentViewer | 独立标题和查询范围，仅只读 |
| 审核历史、样品历史轮次 | AttachmentViewer | 指定动作或轮次的证据快照 |
| 操作弹窗凭证上传 | AttachmentUploadButton | 业务提交成功时关联引用或证据 |
| 弹窗维护附件 | 业务弹窗容器 + AttachmentEditor | 不另造附件弹窗模式 |

编辑页建议分“本单附件”“待绑定文件”“关联文档”三区；详情页展示本单及关联文档，历史记录展示当时证据快照。

## 6）采用条件与实施顺序（尚未启动）

1）先确认是否选用整体设计、是否接受分区展示，以及本单/关联/证据三类查询的范围与权限；定义后端契约和数据生命周期，再估算实施成本。
2）首期优先三个对外组件、公共表格，以及查询/上传/编辑逻辑分离。低频弹窗及单元格组件按实际复杂度抽取，不为目录完整而预先创建空壳。
3）不以删文件数量或模式数量作为验收。重点检查：查看器不产生上传/绑定副作用；无权限不得获取附件；草稿互不串队列；业务保存失败不得错误绑定；切换单据不显示旧结果；解除引用不破坏历史证据；编辑和查看列口径一致。
4）本次交付只验文档、索引及任务关联。上述代码、接口、业务行为、浏览器和运行态均未实施、未验证。
