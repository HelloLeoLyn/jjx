## 0）速览

一句话：把附件来源白名单的**扩展成本与不一致**收敛掉，让"新增一个来源只改一处"。

四个已确认的问题：
1）**扩展点散**：`purchase_receipt`/`purchase_invoice` 不在通用表里，是常量特判，且"按单号反查 ID""取链路号"两个方法各有一处 if ⇒ 加来源要改四处，漏一处就"能传不能查"。
2）**来源名与实际表脱钩**：`purchase_receipt` 的 ID 其实是**入库单** ID、`purchase_invoice` 的 ID 是**采购单据表**（document_type='invoice'），看名字猜不到。
3）**两套权限范式没有判据**：一类写权限 `:edit`（订单/报价/样品），一类 `:doc` + `:add`（收货票据/采购发票/送货回签件）。
4）小的两条：`task` 来源**无权限点**（登录即可读写）；来源清单有**两处**（后端白名单 + 字典 `ext_data.sources`），改一处不会自动同步。

## 1）目标

1）把 receipt/invoice 的特判并入统一结构（一个来源 = 一份声明式配置），**扩展点收敛到一处**；
2）给两套权限范式**写清判据**（"凭证/受控文件"类用 `:doc`+`:add`，"单据附件"类用 `:edit`），并让新来源按判据选；
3）给 `task` 来源补权限点（或写明为何不补）；
4）来源清单**同源**（或加一致性校验，防两处漂移）。

## 2）范围与必读

改：`jjx-server/src/main/java/com/jjx/system/service/AttachmentSourcePolicy.java`（+ 必要的统一结构）；如补 task 权限点则含菜单/权限迁移。

## 3）约束

1）**等价收敛**：不改既有来源的对外行为与权限判定结果（改前改后逐条一致，`AttachmentSourcePolicyTest` 必须全过）；
2）**不加新来源**（那是 023/025/026 的活）；
3）归属按表内字段判定；不考虑旧数据。

## 4）验收

**行为**：新增一个来源只需改一处（同一份声明）；现有来源的权限判定与单号解析结果与改前逐条一致；来源清单不再两处各写一份（或有一致性校验）。
**反例**：① 收敛时改了某个来源的权限前缀或单号 SQL ⇒ 线上权限/查询行为变了（必须逐条对比）；② 只把常量挪个位置、没真正收敛扩展点 ⇒ 本卡白做。
