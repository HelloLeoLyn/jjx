## 3）约束

1）**三条硬前提**（2026-10-14 讨论定下，必须遵守）：
   a) 上传**必须同时带 `product_id`**：引用表按产品查是 `product_id = ? OR (source_type='product' AND source_id = ?)`；只落产品编码、`product_id` 为空的行**查不出来**（现网询价引用行就踩过这个坑）。
   b) **二级类型要能选**：唯一分类口径是一级「客供资料」下的四个二级 —— 客户承认书 / 客户图纸 / 客户技术要求 / 客户样品资料；老上传只写了「客供稿」这一层，没有二级。界面上给下拉（或定一个明确默认值），不许自造类型。
   c) **读取一起换**：老读是「客供归集（跨询价/报价/订单/样品）+ 产品文件库」两路合一；换引用表后要改成按产品查引用，否则新传的看不到。
2）**老数据不纳入考虑**：老行换读后不再显示，不做存量迁移、不写迁移脚本。
3）**第 3 项的图纸元数据是本次唯一可能碰后端的点**：引用表没有「图纸编号/名称/版本/用途」这些列（见 `sys_attachment_ref` 表结构）。执行者**先给结论再动手**：是放进 `display_name`/`remark`，还是保留在附件表列上？若确需改后端 → 停下来交回证据、另立卡。
4）权限沿用产品来源：`product:view` / `product:edit`（老上传接口现在查的也是 `product:edit`，口径一致）。
