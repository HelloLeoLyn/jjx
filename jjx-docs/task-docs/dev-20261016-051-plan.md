3）接入方式与约束

A) 一份会话、多个上传入口

在报价编辑容器每实例创建一次Session，显式传给整单Upload、各产品行Upload以及一个Manager。不要把每次打开行上传弹窗当成创建新Session的时机。行上传可以保留弹窗壳，但其中只有上传入口，不再附带第二个管理列表。

Session来源使用quotation，响应式接入quotationId、draftId、权限、锁定等现有上下文；Upload不再单独接一套source props。整单用orderOwnership；行级用productOwnership({rowKey,productId,productCode})。rowKey使用可随草稿快照恢复的稳定身份，不能用数组下标/可变编码；新建产品尚无ID不应因此禁止上传。临时身份仅前端承接，不冒充数据库product_id。

B) 一个管理区、实时变更

Manager显示本报价单全部附件，支持订单级/产品归属筛选。默认隐藏行内和批量保存；类型/备注/排序编辑即时反映到共享会话，调用方可获取getChanges与dirtyCount/uploadingCount/saving。不能只监听文件数或只等点击保存才取得信息改动。筛选后隐藏行仍属于完整会话；行内数量展示如保留，应来自同一会话。

移除沿用即时生效，成功才清队列/引用、选择及待改差异；失败保留，物理文件不删。产品行删除不得默默把附件转为整单：调用方应阻止有附件行直接删除或明确让用户处理关联附件；原有数据不自动改归属。

C) 草稿、生命周期与旧队列

沿用useAttachmentDraftInstance的新增、恢复、放弃流程，梳理原有draftId::r:productCode与flushStoredQueue路径；新会话不能与旧行队列同时重复绑定同一附件。历史本地队列必须能被识别与处理，不能切换后静默丢弃；跨编码/产品ID回填后的归属映射要保持稳定。

回归新增、编辑、复制、关闭重开、刷新恢复、放弃草稿、切换报价、产品行修改/删除及多实例隔离。首次保存回填ID或替换items数组不能提前清空尚未确认的附件差异；关闭/切换期间的异步回包不得写入另一张单。保存失败不调用acceptSaved或清草稿。
