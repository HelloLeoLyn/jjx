## 0）速览

一句话：采购订单详情弹窗的凭证区，从老通道挪到公共附件组件（`AttachmentCenter`，写引用表 `sys_attachment_ref`），并把"删文件"改成"解除引用"。

**这不是纯迁移——现在就有真缺陷**：付款凭证已经迁到引用表了（付款单页用公共组件），而本弹窗仍按老字段读付款凭证 ⇒ **在付款单传的凭证，在采购订单详情里看不到**。

| # | 位置 | 现状 |
|---|---|---|
| 1 | 订单凭证（上传/列表/删除） | 老接口 `attachmentApi.upload/list`（bizType=`purchase_order`） |

| 3 | 删除 | `attachmentApi.remove`（**真删附件本体**） |

## 3）约束

1）**不动后端**：`purchase_order` / `purchase_payment` 都已在来源白名单里，权限点 `purchase:order:view|edit`、`purchase:payment:view|edit` 都已存在 ⇒ 纯前端改动。若执行中发现确需后端改动，**停下交回证据、另立卡**。
2）**删除语义**：默认按"解除引用"实现（042 P4：公共组件只解除引用，真删收敛到受控入口）。若业务上必须保留"删掉文件本体"，**先交回证据再动**，不要自行保留真删。
3）**不考虑旧数据**（用户 2026-10-14 明确）：老行换读后不再显示，不做存量迁移。
4）本弹窗是"详情（只读为主）+ 上传"混合，`readonly` 语义按现有权限位判断，别把只读详情变成可编辑编辑。

## 4）验收与验证

**行为**
1）在付款单页传的凭证，打开采购订单详情能看到（这是本卡要修的缺陷，必须先复现再验）；
2）订单详情能上传凭证 → 列表立刻可见 → 预览/下载正常 → 解绑后刷新不再出现；
3）本文件里老通道调用点（`attachmentApi.upload/list/remove` 且 bizType 与采购相关）清零。

**反例（看似通过其实错）**
1）只换订单凭证区、没换付款凭证段 → 付款单传的仍看不到；
2）上传时只带业务单号不带 `order_id`（引用表按来源查要 `source_id`）→ 列表查不到新行；
3）保留真删 → 与"只解除引用"口径冲突，且删除后无法审计。
