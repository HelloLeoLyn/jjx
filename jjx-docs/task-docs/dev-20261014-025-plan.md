# dev-20261014-025 任务卡（质量档案上传接入公共附件）

> 任务码：dev-20261014-025 ｜ 2026-10-14 ｜ plan（**交接包**）
> 来源：未接公共上传组件清单 第 12 项

## 0）速览

一句话：质量档案页的「回传扫描件」与「查看附件」一起换成公共附件组件（**必须一起改**）。

现状：
- 上传：`jjx-web/src/views/production/quality-archive/index.vue:91` 仍用老上传组件 `AttachmentUploader`（`:117` 引入；`category='quality_archive_scan'`，老通道 bizType/bizId）
- 列表的「已回传/未回传」判定在后端：`QualityArchiveMapper.java:19-20` 用 `EXISTS(sys_attachment WHERE biz_type/biz_id)`——**按老字段算的**
- 「查看附件」弹窗已在 `dev-20261014-008` 换成只读公共组件

**需要后端**：来源白名单里没有 `quality_archive`；且 `archived` 判定也要改按引用表算。

## 1）目标

1）新增来源 `quality_archive`（照 018/022 先例：权限前缀沿用该页现有权限点 `production:quality-template:view` 或另立 `production:quality-archive:doc`，**先给结论**；单号 SQL 取档案记录号）；
2）「回传扫描件」改成公共组件的上传，「查看附件」保持只读公共组件——**两处口径必须一致**（同一次上传必须两边都看得到）；
3）`archived`（已回传/未回传）改按引用表判定，与页面上看到的附件一致。

## 2）范围与必读

改：`jjx-web/src/views/production/quality-archive/index.vue`（:91 上传块、:103-107 查看附件）、后端 `QualityArchiveMapper.java`、`AttachmentSourcePolicy.java`。
必读样板：`git show b75a3f5c`、`jjx-docs/task-docs/dev-20261014-008-plan.md`（本页上一轮改造，含"半迁移就会传上去看不到"的教训）。

## 3）约束

1）**上传口径与查看口径必须同一次改完**——只改一处 = 传上去看不到（008 的既定教训）；
2）`archived` 判定跟着改，否则列表状态和附件对不上；
3）归属按表内字段判定；删除=解除引用；不考虑旧数据；
4）档案记录号（record_no）语义不变，不改档案业务本身。

## 4）验收

**行为**：回传扫描件 → 列表变「已回传」→ 「查看附件」能看到刚传的 → 预览/下载/解绑正常；刷新后状态与附件一致。
**反例**：① 只换查看不换上传（或反过来）；② `archived` 仍按老字段算 ⇒ 状态与实际不符；③ 权限点选错 ⇒ 无权限用户看到"已回传"却打不开附件。
**命令**：`cd jjx-server && JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64 mvn -o -q compile`；`cd jjx-web && npx vue-tsc --noEmit && npm run check:status-enums && npm run check:docs`。
