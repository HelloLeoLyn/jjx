## 1）目标

让附件挂载只有**一套**（`sys_attachment` + `sys_attachment_ref`）：老字段路径全部退役；非单据来源（付款凭证等）也纳入 refs；多产品单据的 `product_id` 有明确归属。

**当前行为**：新通道上传不写 `biz_type/biz_id`，所有按老字段查的地方看不到新附件（附件中心"历史附件"段、产品详情"业务流转附件"、质量档案、状态流转弹窗、付款凭证）；下载/预览、重复检测各有两套路径。
**期望行为**：只有 refs 一条链；老路径无残留调用；多产品归属可预期。

## 3）约束

1）不动 refs 唯一性与绑定语义、不动落库口径。
2）**权限不得弱化**：保留"TEMP/ORPHAN 仅上传人可读且未过期"与"有 ref 且来源可读即放行"；只有"无 ref 附件"的兜底分支随老通道一起消失——**前提**是这类附件都已纳入 refs（产品/凭证/图纸），未纳入前不得删分支。
3）真删不再由各模块直接调用；管理入口要有明确权限位。
4）产品侧（产品文件库/工程图集/归档）**不在本卡**，见 041；本卡只做口径与单据侧 + 来源扩充。
5）多产品：上传时选产品**可留空**；保存回填**只回填用户显式选了产品的行**。

## 4）验收

**行为**
1）单据侧附件只有 refs 一条链；老字段不再写、老查询不再被调用（残留调用 = 失败）。
2）付款凭证走 refs（`purchase_payment` 来源），能上传、能看、能解除引用；权限按 `purchase:payment:view/edit`。
3）老下载/预览、老重复检测路径退役后**无残留调用**。
4）多产品单据：选了产品的行 `product_id` 正确；没选的为整单级；保存不会把整单附件统一指向同一产品。
