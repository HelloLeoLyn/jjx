## 3）约束

1）不动 refs 唯一性与绑定语义、不动落库口径。
2）**权限判定不得弱化**：第 2 项现在依赖老字段；收口时必须给**等价能力**（建议改按 refs 判定），并保持"未绑定的 TEMP 附件不可被他人读"的既有口径。
3）**非单据类上传路径**（付款凭证、产品/图纸）要么一并收口、要么明确保留并在卡里记明，不能默默漏掉。
4）老数据不追改（若 `036` 已清测试数据，则无存量映射问题）。
5）**多产品未拍板前不动代码**（见补充）。

## 补充（拍板项：先定，再动手）

**拍板一：老通道（`biz_type/biz_id`）怎么处理？**

| 选项 | 含义 | 代价 |
|---|---|---|
| A（建议） | **退役**：附件一律走 refs；老字段只留历史 | 要逐条改造 §2 表里 7 个依赖点 |
| B | 只读保留：不再写新数据，老查询保留 | 新旧仍并存，"看不到新附件"长期存在 |
| C | 双写：新上传同时写 refs 与 biz_type/biz_id | 两套数据要继续同步，等于养两个真源 |

**拍板二：多产品单据（报价/订单）的附件 `product_id` 归属？**

| 选项 | 含义 | 备注 |
|---|---|---|
| A | 整单级（`product_id` 空） | 最简单；改名规则的 `P` 段恒为 `P0` |
| B（建议） | 上传时**选产品**（下拉=本单明细产品，可留空=整单级） | 后端已支持（唯一键含产品位）；需要前端入口 |
| C | 按资料类型强制（如"客户图纸"必须选产品） | 规则最强，但要先维护"哪些类型属产品"的清单 |

**回填口径（无论选哪个）**：多产品单据**不能统一回填**——保存时把某个产品 id 回填给该单全部附件是错的；只有用户显式选了产品的行才写。
