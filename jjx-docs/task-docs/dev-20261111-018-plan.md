## 已定规则与最终实现

1）一个 BOM（bomId）只允许一个编辑实例，含同账号的另一窗口和另一弹窗。Redis TTL 90 秒，心跳 30 秒；获取、续租及保存均核对登录账号归属。其他账号即使提交同 clientId 也不能获取他人 token。
2）每个前端编辑实例在内存生成独立 UUID，不复用可被新窗口复制的 sessionStorage。复制窗口与页面内两个实例都不能共用身份；刷新后旧租约最多等待 TTL 或由授权管理员解除。
3）已有 BOM 未取得租约、申请期间、失去编辑权或 Redis 不可用均只读。保存还必须带 editToken 与服务端 contentRevision；服务器在父行锁和明细锁内核对内容指纹，旧内容返回 409，不覆盖新内容。新建草稿首次保存后取得新 bomId 的租约。
4）关闭、取消、卸载释放自身 id/token；保存成功保持租约。关闭/切换/重新申请后，旧 acquire/renew 的迟到响应不得恢复旧 token 或污染新 BOM。未完成 acquire 在关闭后若成功，按原 BOM/token 补释放。
5）普通与制造 BOM 表单和明细输入真正禁用；普通物料选择器在只读时换成文本，失去编辑权后原选择器卸载；拖拽禁用并有只读回调保护。正式页面布局不改版。
6）强制解锁需要 engineering:bom:edit:force-unlock；现有超管通配权限覆盖，普通 edit 不覆盖。先持久写 sys_oper_log 请求审计，再按 Redis 原始值原子删除，不误删新租约；审计失败拒绝解锁。跨 Redis/MySQL 不宣称分布式事务：审计记录动作请求，竞争导致未删除时补记未生效，不能把请求审计解读为解锁成功。
7）保存、提交、审批、行审核都保留内容冲突校验；批量行审核维持每行 REQUIRES_NEW，成功后滚动指纹。批量 HTTP 200 的 failed 列表中含 BOM_CONTENT_STALE 时前端回读内容和指纹。
8）保留既有图锁、防环、审核权限、版本指针。制造服务 private detail 仅从事务 save/update 调用；普通 getBomDetail 已有只读事务。生产 BomEditSessionService 必须注入，旧手工测试夹具的 null 分支不能用于证明租约契约通过。
