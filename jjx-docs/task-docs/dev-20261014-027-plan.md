## 决策（2026-10-14 逐项讨论定，用户拍板）
- 结论（用户 2026-10-14 定）：工序图标**当「资产」处理** —— **不进引用表**，只把上传通道收口到受控入口（理由：同一图标会被多个工序共用，引用表的解绑语义会把共用图标带走）。

## 结论与实现（dev-20261014-027 落地）

**结论：工序自定义图标 = 资产，不迁公共附件（引用表）。** 与卡片决策一致。

证据（图标被多处共用，引用表的解绑语义会误伤）：
- 字典 `engineering_jjx_icon` 的 `item_value` 存图标名或 `/system/attachment/download/{id}`；工序表 `engineering_standard_process.icon` 只存该值 —— 一个值可被多条工序行引用。
- 消费方（只读渲染）：`standard-process/index.vue`、`StandardProcessPreviewDrawer.vue`、`StandardProcessFormDialog.vue`（`SvgIcon :name` / 网格 `img :src`）。
- 若把图标塞进 `sys_attachment_ref`（挂 `product`/`material`），解绑一处会让共用同一图标的其它工序一起失效 —— 正是卡片反例①。

**实现（收口上传通道，不动引用表）：**
- 前端 `jjx-web/src/components/JJXIcon/index.vue`：图标上传不再走老通道 `/system/attachment/upload`（`bizType=engineering_jjx_icon` 不在来源白名单，早已 fail-closed），改走公共**受控上传入口** `/system/attachment/refs/temp`（`attachmentRefApi.tempUpload`）；仍只在字典登记 URL，**不建引用**；选图/搜索/预览/清除不变。
- 未新增来源、未动 `AttachmentSourcePolicy.java`、无权限迁移（卡定资产路线，故 "若新增来源" 分支不适用）。
- 未改 URL 拼法（仍 `attachmentApi.downloadUrl(id)` = `/api/system/attachment/download/{id}`），渲染处无需同步（避卡片反例②）。
- 未使用 `AttachmentCenter` 组件：图标是无单据上下文的全局资产，组件的"引用/待绑定/解除"UI 与资产语义不符（且会造引用）；故只复用其受控上传链路。

**遗留（供另立卡）：**
- 受控上传入口产的是 TEMP 附件（保留 7 天；`erp.attachment.cleanup.enabled` 默认 false，现网不受影响）。图标是长期资产，**永久化**（受控入口 / 受控静态资源）建议另立卡明确。
