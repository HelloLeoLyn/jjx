## 0）一屏速览

**一句话**：产品详情「业务流转附件」原来把**该产品相关单据的引用全量并集**显示（含同单据里**别的产品**的行级附件 → 串号）；本卡改为**分层**：主区只显示**明确归属本产品**的引用，另设**可折叠的「本单据整单级资料」**兜底（无产品归属的整单级附件），既不多露也不漏。

| # | 口径 | 定论 |
|---|---|---|
| 1 | 主区 | tier=**product**：`ref.product_id=本产品` 或 `(product_id 空 且 product_code=本产品编码)` |
| 2 | 兜底区 | tier=**doc**：来源单据命中本产品、且引用行**无产品归属**（product_id 空 + product_code 空）的整单级附件 |
| 3 | 丢弃 | tier=**other**：来源单据命中、但引用行挂了**别的产品** → 丢弃（治"多露"） |

**禁做**：改来源单据匹配口径；动老数据；碰其它面板（客供资料/文件库）。

---

## 1）背景与证据

- 前端：`views/product/list/components/ProductDetail.vue`「业务流转附件」走 `productApi.bizAttachments(productId)`，按来源单据分组展示。
- 后端：`ProductServiceImpl.getBizAttachments`（:73）——先按 `product_id/product_code` 找命中本产品的来源单据（询价/报价/订单），再读引用：`ref.product_code=? OR ref.product_id=?` **OR** `ref 属于那些来源单据`（`inClause`）。第二部分会把同单据里**别的产品**的引用也带出 → 单产品视图串号。
- 触发：S5（dev-20261013-043）落行级附件后，多产品单据的行级引用已明确 product_id，串号问题显性化。

## 2）改动清单（已落地）

**后端** `ProductServiceImpl.getBizAttachments`：
- SELECT 增 `r.product_id`；按行计算 `tier`（product / doc / other，见 §0）；`refRows.removeIf(tier==other)`（收紧）。
- 分组键改为 `sourceType:sourceId:tier`，组内 `tier` 一并返回。

**前端**：
- `api/product/index.ts`：`ProductBizAttachmentGroup` 增 `tier?: 'product' | 'doc'`。
- `ProductDetail.vue`：`mainGroups`（tier≠doc）渲染主区折叠；新增**可折叠**「本单据整单级资料」（docGroups，含计数）兜底；空态判定改 `mainGroups||docGroups` 均空。

## 3）验收

1）单产品视图不再出现"同单据别的产品"的行级附件（不再串号）；
2）无产品归属的整单级附件仍可见（落在次要折叠组）；
3）产品专属引用正常显示在主区。
- 反例：把整单级也丢了（漏）；或仍全量并集（多露）。
- 命令：`cd jjx-server && mvn -o -q compile`；`cd jjx-web && npx vue-tsc --noEmit`（均过）。
