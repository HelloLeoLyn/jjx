# 订单确认 → 生产完成 业务流程（修复后目标态）

> 版本: v1.0 | 日期: 2026-08-10 | 状态: 目标态设计（基于问题修复后的理想流程）
> 关联任务: dev-20260810-019 ~ 034
> 适用: 销售订单（标准订单）从客户确认到生产交付完成的完整链路

---

## 一、流程总览

```
客户下单 → 订单确认 → 全局齐套检查 → 成品预留+原料占用 → 生产计划/拆批
→ 工单开工 → 多次领料(含替代料) → 工序执行/报工 → 完工质检门 → 成品入库
→ 分批发货出库 → 订单完成闭环
```

七个关口，每一关都校验"量的承诺"：

| 关口 | 校验内容 | 修复任务 |
|---|---|---|
| ① 接单确认 | 全局需求汇总 vs 可用库存 | 019 |
| ② 预留占用 | 成品预留 + 原料占用 | 019/020 |
| ③ 开工领料 | 可用量 + 累计领料 ≤ BOM需求 | 033/034 |
| ④ 完工质量 | 工序完成 + 质检通过 | 031 |
| ⑤ 入库 | 完工量 → 库存 + 订单进度回写 | 020/031 |
| ⑥ 发货 | 出库扣库存 + 分批交付 | 020/021/025 |
| ⑦ 完成 | 全部交付 → 自动闭环 | 024/025 |

**核心原则：全链路统一"可用量"口径（可用量 = 总量 - 预留），每个关口校验累计量。**

## 二、核心数据口径（全链路统一）

### 2.1 可用量
```
可用量 = total_quantity - total_reserved        （inventory_stock.available_quantity 生成列）
```
- 低库存预警、齐套检查、领料预检、出库预检 **全部用可用量**，禁止用总量（027）
- 预留来源：成品预留（销售订单确认）、原料占用（新增）、其他单据预留

### 2.2 物料需求
```
物料需求 = Σ(订单量 × BOM用量 × (1 + 损耗率/100))
```
- 单订单检查与全局汇总检查共用同一套 BOM 展开算法（抽公共方法）

### 2.3 在途采购量
```
在途 = Σ(采购单未收货量)    仅统计 approval_status ∈ (待审批, 已批准) 的单
```
- 排除草稿、已取消、已拒绝（023）
- 取消/拒绝采购单时必须同步刷新在途口径

### 2.4 收货校验
```
单次收货量 > 0 且 累计收货量 ≤ 订单明细数量      否则拒绝（030）
```
- 重复收货、超收一律拦截

## 三、阶段详细流程

### 阶段 ① 订单确认（4 已审核 → 6 已确认）

**触发**：客户确认订单（前端"确认订单"操作）

**步骤**：

1. **单订单齐套检查**（保留现有）
   - 按本订单 BOM 展开物料需求，对比可用量+在途
   - 缺口生成 `order_shortage` 预警（order_no 维度）

2. **全局汇总缺料检查**（新增，019）
   - 汇总所有在途订单（状态 ∈ {4已审核, 6已确认, 7生产中}）的物料需求
   - 对比可用量 + 在途采购
   - 缺口生成 `demand_shortage` 预警（物料维度，order_no 置空）
   - 消息示例：`物料[X] 在途订单3个合计需求100，可用75，在途0，实际缺口25，建议补货25`
   - 幂等：先清该物料旧未处理预警再插入

3. **成品库存预留**（保留现有，DEV-578）
   - 可用量足够 → 预留全部；不足 → 预留部分，缺口转生产
   - FIFO 批次占用 reserved_quantity

4. **原料占用**（新增）
   - 按 BOM 展开对原料做占用（扣减原料可用量），避免多订单"各自都够、合计超卖"
   - 订单取消/完成时释放占用

**校验/异常**：
- 全局缺口 > 0 → 预警不阻断确认（业务可人工决策：接单/催料/改期）
- 成品预留异常 → 记录日志，不阻断主流程

---

### 阶段 ② 生产计划与拆批

**触发**：订单确认后，生产计划员创建生产计划（PLAN）

**步骤**：

1. 创建生产计划（PLAN）：产品、总数量、计划起止日期
2. **大单拆小单**（已有能力，补校验）：
   - `convertPlanToWorkOrders` 一个计划转 N 个工单，每个工单数量/日期自定义
   - **新增校验**：Σ子工单数量 ≤ 计划数量，超出拒绝（防超量）
3. 各工单独立排产：独立开工、独立领料、独立完工入库
4. 订单交付计划（020）：分批交付时，每批对应子工单 + 后续分批出库

**说明**：拆批是"分批生产"的载体，配合阶段③的多次领料，实现大单分批制造。

---

### 阶段 ③ 工单开工与多次领料（033）

**触发**：工单开工（startOrder）

**步骤**：

1. **领料预检**（保留，DEV-651 改造）
   - 按本次领料数量（非全量）检查可用量
   - 可用不足 → 允许"部分领料 + 缺料预警"，不再直接拦开工（033）

2. **生成领料单**（改造：去幂等）
   - 单号改为 `PICK-{工单号}-{批次序号}`，一单可多张
   - 每次领料：填本次数量，默认=BOM 剩余需求
   - 累计领料校验：`Σ本次领料 ≤ BOM 需求`（防多领）

3. **材料替换**（034）
   - 首选物料可用量不足时，按 `substitute_json` 优先级尝试替代料
   - 替代料用量换算：`替代料需求 = 原需求 × (替代料单价/原单价)`（或按配置损耗差异）
   - 替换留痕：领料单明细记录"原物料→替代物料、替换人、替换时间"
   - 替代料也不足 → 提示 + 人工确认（可强制领或改期）

4. **领料单确认**（confirm）
   - 按 FIFO 扣减库存（先扣已占用，再扣可用）
   - 扣减后刷新库存汇总、释放原料占用
   - 同步工单 `materialStatus`：0未领料 / 1部分领料(新增) / 2已领料

5. **追加领料**
   - 生产中随时按剩余需求再创建领料单（回到步骤 2）
   - 工单领料状态在"部分领料"时允许继续领

**校验/异常**：
- 累计领料超 BOM 需求 → 拒绝（防超领）
- 领料单未确认前可撤销（释放占用）

---

### 阶段 ④ 生产执行与报工

**触发**：工单开工后，按工艺路线逐工序执行

**步骤**：

1. 工序执行记录（已有）：投料 → 产出 → 合格/不良数量
2. 首检/巡检（已有）：FAIL 自动暂停工序
3. 报工完成 → 汇总合格数量 → 更新工单 `completedQuantity / remainingQuantity`

**校验**：无新增，沿用现有执行/质检逻辑。

---

### 阶段 ⑤ 完工质检门（031）

**触发**：工单完工操作（completeOrder）

**步骤**：

1. **完工校验（改造，全部满足才允许完工）**：
   - 工单状态 = 生产中（保留）
   - 全部工序执行记录 = COMPLETED（新增）
   - FQC 质检单已生成且质检通过（新增）
   - `completedQuantity ≥ plannedQuantity`（新增，防未做完就完工）
   - 任一不满足 → 拒绝完工并提示原因

2. **完工联动**（保留）：
   - 自动创建 FQC 质检单（若无）
   - 自动生成成品入库单 `FINISH-{工单号}`（DEV-579）

3. **入库单确认**（改造：失败不再静默）
   - 入库确认 = 库存 + 成品可用量
   - 入库失败 → 工单完工回滚或置"待入库"状态，前台可见可重试（不再仅 warn）

4. **订单进度回写**（020）：
   - `produced_quantity += 入库量`
   - 生产状态（prod_status）随完成比例推进

**校验/异常**：
- 质检 FAIL → 工单不能完工，转返工/报废流程
- 入库失败 → 工单状态"已完工待入库"，可手动重试

---

### 阶段 ⑥ 分批发货出库（020/021/025）

**触发**：成品已入库，销售发起发货

**步骤**：

1. **创建发货单**（020 新增接口）：
   - 一订单可创建多张发货单，每张填本次发货数量
   - `Σ已发数量 ≤ 订单数量`（校验）

2. **创建销售出库单**（改造 createFromSales）：
   - 去掉 `SHIP-{orderNo}` 唯一限制，允许多张
   - 出库单号加序号：`SHIP-{orderNo}-{序号}`
   - 明细数量 = 本次发货数量

3. **出库确认（confirm）= 扣库存**（021 修复，关键）：
   - approve 只做状态流转，confirm 执行库存扣减（现有设计，保证 confirm 必被调用）
   - 先释放该订单对应成品预留，再 FIFO 扣减
   - 扣减后刷新库存汇总

4. **订单状态流转**（025 修复）：
   - 首次发货 → 订单 7生产中 → 8已发货
   - `shipped_quantity += 本次发货量`（020 回写）

5. **全部交付 → 自动完成**（020/024）：
   - `Σ发货量 = 订单量` → 自动置订单 COMPLETED（9）

**校验/异常**：
- 库存不足 → 出库确认失败，提示差多少（不静默）
- 部分发货后剩余数量可继续发下一批

---

### 阶段 ⑦ 订单完成闭环（024/025）

**触发**：全部数量交付

**步骤**：

1. 统一状态机（024）：订单状态唯一枚举
   - `1草稿 2待审核 3审核中 4已审核 5已驳回 6已确认 7生产中 8已发货 9已完成 10已取消`
   - 删除旧枚举，全部代码切到新枚举
2. 全部发货 → 自动 COMPLETED（020 联动，无需手工点完成）
3. 完成时校验：`shipped_quantity == total_quantity`（防漏发）
4. 取消订单 → 释放成品预留 + 释放原料占用 + 联动取消未完成工单（已有）

## 四、贯穿全链路的统一规则

| 规则 | 内容 | 任务 |
|---|---|---|
| 可用量口径 | 一切检查用 available_quantity，不用 total | 027 |
| 在途口径 | 排除草稿/取消/拒绝采购单 | 023 |
| 超收拦截 | 收货 ≤ 订单量，重复收货拒绝 | 030 |
| 批次一致性 | 库存批次号 = 单据批次号（统一生成规则） | 029 |
| 成本口径 | BOM 标准成本 = Σ(用量 × 单价)（修正） | 032 |
| 状态机唯一 | 销售订单/工单/出库单各自单一枚举 | 024 |
| 预警类型 | safe_stock / max_stock / expiry / obsolete / order_shortage / demand_shortage | 019 |

## 五、异常与补偿场景

| 场景 | 处理 |
|---|---|
| 确认时全局缺口 | 预警提示，人工决策（接单/催料/改期），不阻断 |
| 开工时料不足 | 部分领料开工 + 缺料预警 + 采购联动 |
| 生产中途缺料 | 替代料自动兜底 → 仍不足则补料/暂停 |
| 质检不过 | 工单不可完工，转返工/报废 |
| 入库失败 | 工单置"待入库"可重试，前台可见 |
| 发货库存不足 | 出库确认失败并提示缺口 |
| 订单取消 | 释放预留/占用，联动取消工单 |

## 七、验收要点（修复完成后验证）
