# JJX ERP 自动化测试标准

> 版本：v1.0
> 适用范围：所有 Playwright E2E 测试

---

## 一、核心理念

每个测试用例必须验证 **操作结果 + 下游数据 + 跨模块联动**，三条缺一不可。

---

## 二、测试用例格式

每条测试用例必须包含以下结构：

```
## [模块] TC-XXX: 测试标题

### 前置条件
- 系统已登录
- 依赖数据已就绪（客户/产品/订单等）

### 测试步骤
1. 执行操作 A
2. 执行操作 B
3. ...

### 验证点（必须全部覆盖）

#### ✅ 操作验证
- [ ] 页面操作成功（成功提示 / 无报错）
- [ ] 截图保存

#### ✅ 数据验证（查数据库或页面）
- [ ] 新增操作 → 列表页能查到该记录
- [ ] 修改操作 → 字段值已更新
- [ ] 删除操作 → 列表已无该记录

#### ✅ 状态验证
- [ ] 业务状态流转正确（如：草稿→审核中→已审核）
- [ ] 状态标签/颜色渲染正确

#### ✅ 流程验证（如有）
- [ ] 审核流水已生成（审核记录表）
- [ ] 订单跟踪有数据
- [ ] 看板（jjx-kanban）任务已创建或状态已更新
- [ ] 通知消息已派送（如有）

#### ✅ 截图
- [ ] 每小步完成后截图
- [ ] 截图命名：`{模块}-{编号}-{功能描述}.png`
```

## 三、5 个测试维度

### 维度 1：功能完整性
每个 CRUD 操作能正常完成，页面不报错。
- 测试覆盖：列表加载、新增、编辑、删除

### 维度 2：业务流连贯性
ERP 核心价值——数据在模块间不断链。
```
客户 → 报价 → 样品订单 → 生产工单 → 领料 → 完工入库 → 发货
```
- 每个下游环节能正确引用上游数据
- 例：订单审核通过后 → 看板出现工单

### 维度 3：状态机正确性
业务对象（订单/工单/入库单）有严格的生命周期：
```
草稿 → 审核中 → 已审核 → 生产中 → 已完成 → 已发货
                 ↖ 退回修改
```
- 不允许跳过状态（如草稿直接到已审核）
- 不允许逆向操作（已审核的不能变回草稿）

### 维度 4：数据一致性
- 同一笔订单金额，在订单列表和详情页一致
- 库存扣减后不能为负
- 审核通过后数据锁定，不能再编辑
- 上下游关联数据正确（订单→工单→出库）

### 维度 5：异常容错
- 空数据页面正常渲染，不崩
- 必填项未填不能提交
- 搜索无结果则空表格 + 提示信息
- 快速连点/并发操作（如同时审核同一单）不产生脏数据

## 四、截图规范

| 规则 | 说明 |
|------|------|
| 时机 | 每完成一个小功能操作后立即截图 |
| 命名 | `{模块}-{TC编号}-{功能描述}.png` |
| 存放 | `tests/screenshots/` 目录 |
| 格式 | 全页截图（fullPage: true） |
| 发送 | 每次测试完发截图，不堆叠，按步骤逐一发送 |

---

## 五、业务流程测试顺序

按实际业务流转顺序执行测试，不可跳跃：

```
Phase 1 — 基础数据准备
  新增客户 → 新增产品 → 新增 BOM → 新增工艺路线
  ├─ 验证：列表可查 + 详情正确
  └─ 截图

Phase 2 — 销售流程
  报价 → 样品订单 → 提交审核 → 审核通过/退回
  ├─ 验证：状态变化 + 审核流水 + 看板派工
  └─ 截图

Phase 3 — 生产流程
  工单 → 派工到工序 → 执行工序 → 质检 → 完工入库
  ├─ 验证：看板状态 + 库存更新 + 通知消息
  └─ 截图

Phase 4 — 库存流程
  领料 → 入库 → 出库 → 库存盘点
  ├─ 验证：库存数量正确 + 流水记录
  └─ 截图

Phase 5 — 采购流程
  采购申请 → 采购订单 → 收货 → 入库
  ├─ 验证：上下游数据一致 + 看板可见
  └─ 截图
```

---

## 六、禁止事项

1. ❌ 不准用虚假数据（`测试客户_XXX`、`SAMPLE-XXX`）
2. ❌ 不准跳步测试（必须先有客户才能建订单）
3. ❌ 不准一次跑多个用例而不截图
4. ❌ 不准忽略失败——失败必须先修再继续
5. ❌ 不准不验证下游结果（新增了要查列表，审核了要看流水）
