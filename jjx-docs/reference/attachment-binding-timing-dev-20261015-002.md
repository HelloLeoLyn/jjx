# 附件挂载时机对照表（业务侧）

状态：生效（2026-10-15）
任务：dev-20261015-002（业务侧：各单据挂附件的时机口径）
被取代或取代：无（与 dev-20261015-001 配套：那份是组件口径，这份是业务口径）
什么情况看这篇：新增/改造某个单据的附件上传时，判断该"上传即挂"还是"保存/确认时挂"
最后复核：2026-10-15

---

## 1）结论：只有两类

1）**提交/确认时挂**：页面上有"保存 / 确认"动作的单据。附件先上传成临时件（`TEMP`），单据保存或确认成功的那一刻才建立正式引用；**采购收货、采购发票是后端在同一事务里建引用**，表单类（询价/报价/订单/样品）是保存成功后由前端建立。
2）**上传即挂**：页面上没有"保存"动作、本来就长在某个已存在的单据/产品/档案上的区域（各资料区、详情区、回签件），上传完成即建立正式引用。

判据一句话：**这个页面上有没有"保存/确认"按钮** —— 有就是第一类，没有就是第二类。

## 2）对照表（2026-10-15 实测）

| 单据 / 入口 | 挂载时机 | 证据 | 备注 |
|---|---|---|---|
| 采购收货（收货票据） | 确认收货时，**后端同一事务**内建引用 | `PurchaseReceiptAttachmentService`（`refs.create`，sourceType=`purchase_receipt`）；dev-20261014-018 | 弹窗内先落临时件；取消不绑、失败保留可重试 |
| 采购发票（发票文件） | 新建/核销提交时，**后端同一事务**内建引用 | `PurchaseInvoiceAttachmentService`（sourceType=`purchase_invoice`）；`PurchaseDocumentServiceImpl` 核销段；dev-20261014-022 | 新建时暂存的附件 + 核销携带的临时附件同事务建引用 |
| 询价 / 报价 / 销售订单 / 样品（表单面板、弹窗） | 保存成功后由前端建引用 | `useAttachmentRefs.bindPending`；本次实测 27 个使用点里的 panel/dialog 类 | 上传落临时件、保存后批量绑定 |
| 产品资料 / 客供资料 / 产品图纸 / 菲林图纸 / 质量档案 / 质量模板 | **上传即挂** | 27 个使用点里 sourceId 已存在的 `panel` / `upload-only` 类；前端直接建引用（如工程图纸库上传段） | 来源权限决定可写 |
| 操作证据弹窗（多调用方复用） | 弹窗内上传即建引用，操作提交时把引用号一起提交 | `components/OperationPreviewDialog`（`@bound`、`boundRefIds`，注释标 dev-20261014-028） | 待核实：弹窗取消时正式引用是否残留（见 §4） |
| 销售送货回签件 | **上传即挂** | 前端 `mode="panel"`（`views/sales/delivery`，sourceType=`sales_delivery`）；后端未发现事务内建引用 | 两个入口（详情抽屉 / 收货弹窗）共用同一来源 |
| 工序自定义图标 | **未接入公共组件** | 字典 + 老上传通道；见 dev-20261014-027（P3 待处理） | 接入后按本表归类 |

## 3）与组件口径的关系

- 组件只出能力（上传 / 待绑定 / 绑定 / 只读），**不决定何时挂**：见 dev-20261015-001 §8。
- 第一类要保留"临时件 → 正式引用"的两段式（`TEMP → BOUND`）；第二类上传即落 `BOUND`，不产生 `TEMP`。

## 4）待办与待核实

1）**待核实**：操作证据弹窗属于"上传即挂"，但引用号要到操作提交才用得上 —— 若用户取消操作，正式引用是否残留成垃圾引用？核实后决定是否改成"上传落 `TEMP`、提交时绑定"。
2）**待登记**：工序自定义图标（dev-20261014-027）接入公共组件后，本表补一行。
