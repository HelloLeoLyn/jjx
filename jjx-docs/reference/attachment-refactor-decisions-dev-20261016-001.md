## 1）原则

1）公共组件**只做增删改查（CRUD）**，**不带业务概念**。
2）显示哪些动作、能不能点、按钮文案、要不要「保存」按钮 —— **全由调用方传参**决定。
3）`productId` **单向传参**：组件只读、**不回写**；产品变化由调用方 / 后端处理。
4）**边界情况组件不判断，由调用方决定**。

## 2）归属模型

1）**两层对象**：文件 `sys_attachment`（`upload_state`：`TEMP`/`BOUND`/`LEGACY`/…）× 引用 `sys_attachment_ref`（**归属 + 上下文元数据**：资料类型、展示名、备注、排序）。**业务上的「附件」= 引用**。
2）**归属 = 来源对象（单据 / 产品档案）+ 产品** —— **同时属于，不是二选一**。
3）**关联一律用 `product_id`**（不用 `product_code`；code 是业务值、会变 → 失联）。
4）**保存前 = 无归属**（临时件，两侧都不可见）；**保存成功 = 落定**（**原子**：单据 + 产品建档 + 引用，同一事务；任一步失败整单回滚）。
5）**补 / 改产品 → 保存时同步**（以单据当前产品为准；变更由**流水**留痕）。
6）**报价单**：同一单内**产品不重复** → **不需要「行标识」**。
7）**「移除」= 两个业务动作**（组件不自己判断）：未绑定行 = 丢队列；已绑定行 = 解除引用。**都不删文件**；删文件只在**管理端回收站**。

## 3）界面（第一阶段 · 前端）

1）默认列**去掉「展示文件名」** → 列 = 原文件名 / 来源类型 / 来源单号 / 产品编码 / 一级类型 / 二级类型 / 状态 / 操作。
2）**展示名由后端按命名规则统一生成**（§5-1）→ 前端**撤「改名」**（批量改名 + 行内改名）。
3）**去「重试」**：没有「绑定」概念；失败 = 保存失败，再点「保存」即重试。
4）**表格上方加「保存」**：**统一提交「附件信息类」改动**（二级类型等）。
5）**「移除」/「批量移除」= 原有逻辑，不动**（即时）。
6）操作列 = `下载 / 详情 / 移除`；上传入口 = `上传`（按钮或拖拽落区）。

→ 功能按钮共 **7 个**：**上传 / 保存 / 批量改类型 / 批量移除 / 下载 / 详情 / 移除**。

## 4）分阶段

**第一阶段（前端）**：只改组件；**不传 = 现状**（行为零变化）；调用方**陆续接**。

**第二阶段（后端 + 存储）**：
1）**草稿键进库**：ref 加 `draft_key`；
2）**上传即建草稿行**：`ref_state=draft`、`source_id` 空；
3）**状态列 `ref_state`**：`draft` / `active`；
4）**上传接口一次写完**：同事务落「文件 + 草稿行」；
5）**保存单据** → 补 `source_id`、`ref_state: draft→active`（原子）。

## 5）规则与连带

1）**命名规则**（后端统一生成展示名）：`来源类型编码-来源Id-P产品id-一级码-二级码-二级名`（来源如 `INQ/QT/SO`；一级 `BIZ/CUS/ENG/GEN/QUA`；**无产品时 P 段为 `P0`**；**除产品 id 外各要素必须齐，缺任一不生成**）。
2）**报价单「同单产品不重复」校验**：前端拦 + 后端保存校验 + **库唯一约束** `(quotation_id, product_id)`；⚠️ 加约束前**先清存量重复**。
3）**行级视图保持「不显示同链路」** —— 判据从「有没有 `product_code`」换成「**调用方有没有传行 / 产品**」。
4）**解绑 = 保持现状**：引用**软删**（`deleted` / `deleted_by` / `deleted_at`）；文件进 **30 天保留期**（`UPDATE sys_attachment SET expires_at = NOW() + 30 DAY`）。
5）**`autoBind` 取消**：统一走「保存」。
6）**`draftId` 按实例**（不再用「每用户 + 来源」的共享键）→ 修 `dev-20261015-038`（串队列）。

## 6）矩阵（保存前/后 × 产品）

- **A1** 产品未建档 + 未保存 → 无归属；`product_id` 无；两侧不可见
- **A2** 产品未建档 + 保存成功 → **原子**（保存 = 产品同时建档）→ 挂 **单据 + 产品**；两侧可见
- **B1** 产品已建档 + 未保存 → 无归属；草稿里带 `product_id`；两侧不可见
- **B2** 产品已建档 + 保存成功 → 挂 **单据 + 产品**；两侧可见
- **C1** 没产品 + 保存成功 → 挂 **只单据**（整单级）；产品侧不可见

**总规则**：保存前 = 无归属；保存成功 = 单据 +（当时单据的产品）；补 / 改产品 → 保存时同步。

（报价单的「行内操作」只是「调用方传的是哪一行的 `product_id`」，归属模型仍是「单据 + 产品」。）
