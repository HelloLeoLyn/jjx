# JJX ERP 试运行前系统级测试计划

- 日期：2026-09-03
- 定稿：大黄起草，Leo 批准（21:00）
- 定位：系统级首测——全模块功能就绪但从未真实跑过、0 业务数据；不是回归测试

## 一、测试目标

试运行前把**核心业务闭环跑通 + 功能稳定性验证**。追求可用性，不追求覆盖率数字。

## 二、总体策略

- **数据先行**：按 TC 依赖造"真实感"数据（主数据=真实品类可沿用；客户/供应商=拟真标注待替换；单据=按 TC 场景的量）
- **用例驱动**：以测试工作台 TC + task-mapping 映射为执行清单，任务→TC 关联已进看板（sys_task.test_cases，1320）
- **问题闭环**：发现即登记看板（带 TC 号），每轮结束问题清零再进下一轮
- **分工**：大黄=造数/执行 TC/定位修复/回归；Leo=业务判定/验收

## 三、测试轮次（4 轮）

### 第 0 轮 · 数据地基（=1232/1323）
- 造真实感主数据：真实品类产品 5-8 个 + BOM/工艺路线；拟真客户/供应商；期初库存；设备台账
- 顺手清理孤儿数据
- 产出：可测数据 + 主链路字段/状态机/事件首轮暴露（造数即测试）

### 第 1 轮 · 核心闭环功能测试（最重要）
按业务链逐条跑 TC：
- 销售链：客户→询价→报价→订单→评审→确认→收款→发票→发货→退货→对账
- 生产链：转生产→工单→工序任务→报工→质检→完工→入库
- 库存链：采购入库/领料出库/盘点/调拨 + 安全库存预警
- 采购链：询价→采购单→收货→付款
- 工程链：样品打样→会签 ECN→升版
- 产出：问题清单（登记看板）→ 修复 → 回归

### 第 2 轮 · 专项与交叉
- 打印体系（QR 全模板）、移动端/PDA、事件通知、四部门会签、权限矩阵
- 交叉场景：订单取消联动、部分退货、单据引用、逾期预警定时
- 产出：第 1 轮修复回归 + 专项问题

### 第 3 轮 · 试运行演练（UAT）
- 真实剧本连跑 2-3 天（每天：下单→生产→发货→对账日常）
- 产出：试运行放行结论
