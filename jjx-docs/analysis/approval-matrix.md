# 生产报工审批矩阵（2026-08-28 定稿）

> 决策来源：dev-20260827-011（选项 C：保持现状 + 文档化）
> 代码：WorkReportActionServiceImpl.checkApprover（:285-303）

## 规则

- 报工审批人 = **直接父任务执行人**（parent_task_id 对应的 assignee_id）
- First Task（parent_task_id = NULL）的 assignee 恒为 NULL（无代码赋值），
  因此其直接子任务（深度2）的报工没有可用的父执行人 → 由
  **生产管理角色（production:all）审批**
- 深度3+ 任务（有父执行人的任务）报工 → 由直接父任务执行人审批
- 生产管理角色可审批全部报工（豁免）

## 可达性矩阵

| 任务层级 | 示例 | 审批人 |
|---------|------|--------|
| 深度2（First Task 直接子任务） | 管理者→车间主任 | production:all（生产管理） |
| 深度3+ | 管理者→车间主任→组长→工人 | 直接父任务执行人（如组长报工由车间主任批） |

## 说明

- First Task 本身无人能报工（无 assignee，submit 校验提交人=执行人），
  "第一层任务报工由生产管理审批"分支实际不可达。
- 一层派工模式（管理者直接派给工人）下，全部报工由生产管理审批；
  多层派工下审批权跟随责任树逐级下沉。
- 该矩阵为现状（选项 C），若现场一层派工变多、管理岗审批量大，
  再评估选项 A（首次派工强制 First Task 挂 assignee）。
