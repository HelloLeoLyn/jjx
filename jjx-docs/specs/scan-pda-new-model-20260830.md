## 一、业务目标

车间工人通过 **扫码枪 / 手机（PDA）** 完成生产工序的执行闭环：扫码定位 → 开始工序 → 完工报工（数量/质量/不良原因）→ 任务流转。

## 三、新模型适配分析（核心）

旧派工模型（production_dispatch）已废弃，新基线 = `ProductionOperationExecution` → `ProductionTaskNode` 树 → `WorkReport`。**逐一映射后结论：后端能力已基本齐备，主要缺口在前端移动端页面。**

### 扫码 B（手机 H5 扫码操作页）→ 适配度 90%，缺前端

| 需求（旧方案） | 新模型现状 |
|---|---|
| 手机扫工单码 → /m/scan 移动页 | ❌ 无移动端页面（/m/scan 路由未建） |
| 我的派工任务（旧：production_dispatch.operators） | ✅ **已内置**：ProductionTaskController「我的生产任务」（assignee_id=当前登录人，按 execution 聚合） |
| 一键开始/完成 | ✅ 已有：`PUT /execution/{id}/start`、`/pause`、`/complete` |
| 报工（数量/合格/不良/原因） | ✅ 已有：WorkReportController `POST /`（SUBMIT，数量上限=Task.remaining 校验）+ `/mine` + 审批 |
| 报工单号 | ✅ 已有（DEV-1169 report_no） |

**缺口**：前端移动端 H5 页（扫码 → 登录 → 任务列表 → 开始/报工），可复用现有接口，纯前端工作。

### 扫码 C（设备码防错校验）→ 适配度高，设备字段已具备

- `production_operation_execution` 已有 **equipment_id / equipment_code / equipment_name**
- `production_work_report` 也带 equipment 快照
- **实现**：设备贴牌二维码（内容=设备编号，可复用标签打印技术）→ 开始工序前扫设备码 → 与 execution.equipment_code 比对：
  - 一致 → 放行开始
  - 不一致 → 拦截（可选：记录实际设备后放行，按管理策略定）

### 扫码 D（派工授权码轻鉴权）→ 需业务决策

- 旧方案：production_dispatch.auth_code 6 位码，凭工单号+授权码获取临时 token
- 新模型：`work_report` 有 **proxy_id/proxy_name（代理报工）**，但那是"有账号的人代报"，不是"无账号工人"场景
- **决策点**：车间工人是否每人分配系统账号？
  - 有账号 → 直接登录（现有账号体系），**扫码 D 可以不做**（授权码场景消失）
  - 无账号 → 保留轻鉴权（工单号+6 位码），但需要重新设计 token 粒度（限定工单范围）
- 建议：**先走账号登录**，D 作为备选不做，除非有明确的无账号需求

## 四、技术路线（沿用原方案结论）

1. **扫码枪**：零配置最稳（模拟键盘），已落地 A 系列——车间主力
2. **手机摄像头**：`getUserMedia` 仅 HTTPS/localhost 可用 → 局域网 HTTP 被拒
   - 推荐：nginx + **自签 HTTPS**（mkcert）内网部署，一次配置解锁手机扫码 + PWA
   - 兜底：扫码枪 / 手动输入
3. **部署拓扑**：车间 Wi-Fi → nginx(HTTPS 自签) → 前端静态页 + /api 反代 → 后端 8080
4. **移动端形态**：响应式 H5（现有 Vue3 工程加 /m/ 路由）或独立轻量页，首推前者（复用接口/登录/权限）
