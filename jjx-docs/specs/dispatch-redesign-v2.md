# 生产派工管理 重新设计方案（v2.0）

> 版本：v2.0（重新设计稿）
> 编写：2026-08-19
> 状态：讨论稿，待拍板
> 背景：v1.0（2026-08-12）落地后概念混乱（指派/改派/转派语义不清、链存 JSON 不结构化、列表难读），本稿推倒重设计，不背现状包袱。

## 一、设计目标（对应四条要求）

| # | 要求 | 本方案怎么答 |
|---|---|---|
| 1 | 工作要能逐级下派 | 引入**派工链**模型：一条任务一条链，每一级一个节点，深度不封顶，逐级往组织树下层派 |
| 2 | 逐级下派链条要清楚 | 链**结构化存储**（每级：谁、谁派的、何时、什么状态），列表/详情完整可视，不再依赖 JSON 字符串和流水文字 |
| 3 | 指派/改派到底是什么意思 | 重新定义四个动作：**指派=首次建立链、下派=链加一级、改派=同级换人、退回=回退一级**，语义互斥，UI 按钮一一对应 |
| 4 | 列表信息展示清楚些 | 列表按工单聚合展示工序+完整链+当前待办人+状态，一眼看清"活现在在谁手上" |

## 二、核心概念定义（先回答"指派/改派"）

**统一术语，四个动作，语义互斥，不允许一个接口干三件事：**

| 动作 | 英文 | 语义 | 链的变化 | 谁能做 |
|---|---|---|---|---|
| **指派** | Assign | 把任务**第一次**派出去，建立链的第 1 级（负责人） | 从无到有（链长=1） | 超管/生产负责人/有源头派工权的人 |
| **下派** | Transfer | 链上某级的人把活**派给手下**，任务往下走一级 | 链加一级（原级→监督中） | 当前待办级的人（只能派给自己的手下） |
| **改派** | Reassign | 链上**某一级换人**（同级替换，如第 1 级张三→李四） | 链长度不变，换人 | 当前待办级的人/其上级 |
| **退回** | Reject | 当前级把任务**退回上一级**，说明原因 | 链回退一级（末级弹掉） | 当前待办级的人 |

**一句话记忆**：
- 指派 = 开头建链
- 下派 = 往下长（变深）
- 改派 = 原地换人（不变）
- 退回 = 往回退（撤销末级）

> ⚠️ v1.0 的问题根源：一个 assign 接口同时干"新建/追加级别/换设备/换第1级"，前端"改派"按钮实际只换第 1 级、"转派"又叫"改派"，用户根本分不清。v2.0 把动作拆开，接口、按钮、术语一一对应。

## 三、逐级下派模型（派工链）

### 3.1 两条核心表

```
production_dispatch（派工单头）——一道工序一张
├── dispatch_id
├── order_id / order_no         工单（冗余编号）
├── execution_id                工序执行记录（保留联动）
├── process_name / process_order 工序（冗余）
├── equipment_id / equipment_name 设备（工序级属性，指派时定，改派不动）
├── status                      整体状态（见 §5）
├── assigned_by / assign_time   源头主管
├── re_dispatch_count           改派次数
└── remark / 审计字段

production_dispatch_node（派工链节点，新增表）——链上一级一行
├── node_id
├── dispatch_id
├── level                       级别序号（1,2,3…不封顶）
├── user_id / user_name         这一级的人
├── parent_node_id              谁派给我的（上级节点；第1级=NULL=主管直派）
├── status                      节点状态：ACTIVE待办 / TRANSFERRED已下派(监督中) / DONE完成 / REJECTED已退回
├── assigned_by / assigned_at   谁派的、何时派
└── handled_at                  本级处理完的时间（转派/完成/退回）
```

### 3.2 链的不变量（保证"链条清楚"）

1. **一条链有且仅有一个 ACTIVE 节点**，且它一定是链的末级 = 当前待办人
2. 其余节点状态 = TRANSFERRED（已下派，角色=监督）
3. 下派操作：ACTIVE 节点 → 状态改 TRANSFERRED，新建子节点（level+1, parent=自己）→ ACTIVE
4. 改派操作：指定级别节点换 user_id，链结构不动
5. 退回操作：末级 ACTIVE 节点 → REJECTED，其 parent 节点 TRANSFERRED → 回到 ACTIVE；若退回的是第 1 级 → 整单回到"待派工"
6. 深度不封顶（自然受组织树深度约束，一般 2~4 级）

### 3.3 链与组织树的关系

- 链 = 组织树上的一条下行路径：主管 → 车间主任 → 班组长 → 操作工
- 下派只能派给**自己的手下**（负责部门 + 下级部门成员），由组织树天然约束，不需要"被派工过才能派"这种绕弯规则
- 派工单头不再存"班组"（班组 = 末级执行人所属部门，由链推导，避免冗余矛盾）

## 四、链条展示（要求 2）

### 4.1 列表里的链（紧凑）

```
张三 ＞ 李四 ＞ 王五 ★
```
- 每级一个人名，`＞` 分隔，末级加粗绿色 + ★（当前待办/实际干活）
- 中间级灰色小字标"监督"，鼠标悬停提示"第N级 由XX指派"
- 无链显示"未派工"

### 4.2 链详情弹窗（完整）

时间线式，每级一张节点卡：
```
[第1级] 张三  （由 主管-王主管 指派 08-19 09:00）
   ↓ 已下派给下级（监督中）
[第2级] 李四  （由 张三 指派 08-19 10:20）
   ↓ 已下派给下级（监督中）
[第3级] 王五 ★（由 李四 指派 08-19 11:05，当前待办）
```
每张卡显示：级别、人、**谁派的**、**什么时候**、状态、备注；底部保留操作流水时间线。

## 五、状态机（整体）

砍掉 v1.0 的"已派班组"（班组概念已不存在，状态名名不副实）：

| 状态 | 含义 | 进入方式 |
|---|---|---|
| 0 待派工 | 无链，等待首次指派 | 工序生成 / 第1级被退回 |
| 1 已派工 | 链存在，末级待开工 | 指派 / 下派 / 改派完成 |
| 2 执行中 | 末级开始干活 | 开始 |
| 3 已完成 | 末级干完 | 完成 |
| 4 已退回 | 末级退回上一级，等待上级重新下派/改派 | 退回 |

节点状态机：ACTIVE → TRANSFERRED（下派）｜ACTIVE → DONE（完成）｜ACTIVE → REJECTED（退回）

## 六、列表信息展示（要求 4）

### 6.1 列表视图：按工单聚合

```
┌ 工单 SO-20260819-001 ｜ 产品：XXX ｜ 数量：5000 ｜ 派工进度：3/5 道已派 ┐
│  序 工序      设备    派工链            当前待办  状态    指派时间  操作  │

│  2 冲型     冲床3    未派工            -        待派工  -         指派  │
│  3 组装     不限     张三＞王五★       王五      已派工  08-19 10:00 开始 │
└──────────────────────────────────────────────────────────────────┘
```

### 6.2 列定义

| 列 | 内容 |
|---|---|
| 工序 | 序号 + 工序名 + 大类标签（印刷/冲型…） |
| 设备 | 设备名 / 不限 |
| 派工链 | 完整链（§4.1），点击弹详情 |
| **当前待办人** | ACTIVE 节点的人，高亮（新增列，核心信息） |
| 状态 | 五态标签（§5） |
| 指派时间 | 最近一次指派/下派/改派时间 |
| 操作 | 按"我是谁"动态显示（§7） |

### 6.3 筛选

工单号 / 工序关键字 / 状态 / **当前待办人**（谁手上有活）

## 七、权限与操作可见性（简化）

- **源头派工权**（可指派第 1 级）：超管 + 生产负责人
- **对某张派工单的操作权**：当前 ACTIVE 节点的人（下派/改派/退回/开始/完成）；第 1 级（负责人）另有改派权
- 操作按钮按登录人身份动态渲染：不是你的活，不显示操作按钮；你的活，显示你该有的动作
- 砍掉 v1.0"被派工过（LIKE 匹配 JSON）就能派工"的绕弯规则

## 八、接口设计

```
GET  /production/dispatch/page             列表（工单聚合，含链节点+当前待办人）
GET  /production/dispatch/{id}             详情（含完整链）
GET  /production/dispatch/{id}/logs        操作流水
POST /production/dispatch/assign           指派（建链第1级）
POST /production/dispatch/transfer         下派（末级→其手下，加一级）
POST /production/dispatch/reassign         改派（指定级别换人）
POST /production/dispatch/{id}/reject      退回（原因必填）
POST /production/dispatch/{id}/start       开始
POST /production/dispatch/{id}/complete    完成
GET  /production/dispatch/underlings/{uid} 手下（组织树，下派候选）
GET  /production/dispatch/my-persons       自己+手下（指派候选）
```

assign / transfer / reassign 三个接口各自校验、各自记流水，互不混用。
