# JJX ERP 字典维护规范

> 版本：v1.0
> 最后更新：2026-08-01
> 用途：明确哪些字段走"管理员动态维护字典"、哪些走"静态枚举"，防止误用

---

## 一、核心原则

**状态码 ≠ 字典项**：
- **状态码**（`*_status`）是程序状态机的一部分，代码里有 `switch/if` 分支判断 —— **必须静态枚举**，禁止动态增删（否则代码逻辑断裂）
- **字典项**是"业务选项"，业务人员可能增删 —— 才走 `sys_dict` 动态维护

**判断标准**：问一句"这个值如果被业务人员加了新的，代码要不要改？"
- 要改 → 静态枚举（状态码/类型分支）
- 不用改 → 动态字典

---

## 二、必须用静态枚举的（禁止动态维护）

| 字段 | 理由 |
|---|---|
| 所有 `*_status`（订单/样品/报价/生产/库存/审批状态）| 状态机逻辑，代码分支依赖 |
| `sales_quotation_status`（0-9 含改单/已完成）| 状态流转校验 |
| `sales_sample_order_status`（1-10）| 样品状态机 |
| `production_order_status`（0-11）| 生产状态机 |
| 工序执行状态、审批状态等 | 同上 |

**这些字典（sys_dict 里已导入的 *_status）只作为"展示用参考"，不作为维护入口。**

---

## 三、建议走动态字典的（管理员可维护）

> ⚠️ 以下为建议清单，**当前部分尚未接入动态字典**（页面仍是静态），接入时机按需。

| 候选字段 | 归属模块 | 理由 | 现状 |
|---|---|---|---|
| 币种 currency | 销售/采购 | 可能新增币种 | 页面写死（CNY/USD/EUR/JPY/HKD）|
| 付款方式 payment_method | 采购 | 可能新增 | 枚举 |
| 供应商类型 supplier_type | 采购 | 可能新增 | 枚举 |
| 客户等级/类型 customer_type | 销售 | 可能新增 | 枚举 |
| 物料类型 material_type | 库存 | 可能新增 | 枚举 |
| 工序类型 process_type | 生产/工程 | 可能新增工艺 | 枚举 |
| 预警级别/类型 alert | 库存 | 可能调整 | 枚举 |
| 单位 unit | 全局 | 可能新增 | 枚举 UnitEnum |

**接入方式**（按需，不做全量）：
1. 首次进入页面时拉取一次对应 dict_code 缓存（前端 useDict 缓存层）
2. 缓存全局复用，不重复请求
3. 管理后台（系统管理→字典管理）维护

---

## 四、保障机制（防误用）

1. **新增状态/类型字段时**：先判断"状态码还是业务选项"（见原则），状态码必须建枚举+前端枚举，禁止直接塞字典
2. **字典管理页面只维护业务选项**：字典分组 `common/business`，`*_status` 类字典标记为"只读参考"（is_active 可保留但页面提示不可改）
3. **代码评审点**：任何 `sys_dict` 的增删改，检查是否有代码 `switch` 依赖 —— 有则拒绝
4. **前端下拉**：状态类用 `enums/` 枚举，业务选项类才用 useDict 缓存
