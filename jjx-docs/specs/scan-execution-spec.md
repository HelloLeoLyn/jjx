## 一、背景

生产工单的工序执行（开始/结束）目前只能页面按钮操作。车间场景需要更快的操作方式，接入**扫码**：

- 扫码枪（车间 PC 终端）
- 手机扫码（移动端操作）
- 设备码防错（确保在派工指定的设备上操作）
- 授权码（无账号工人轻鉴权）

**现状**：系统无二维码基础设施（无 zxing 依赖、仅一个空壳 ScanLoginDTO）、无扫码枪接入、无移动端页面。

## 三、一期方案 A 详细设计（扫码枪 + 工单二维码）

### 3.1 二维码生成

**方案选择**：前端 `qrcode.js`（纯前端、无后端依赖、几行代码），在**生产随工单打印页**（ProductionWorkCard / print.vue）右上角渲染二维码。

- 内容：`工单号`（如 `WPO260812001`），格式简单、扫码枪直接输出工单号
- 后端无需改动（不引入 ZXing）

### 3.2 扫码枪识别（核心技术）

扫码枪 = HID 键盘设备，扫描结果 = 字符串 + 回车。前端**全局监听**：

```ts
// 全局扫码监听（main.ts 或独立 composable）
let scanBuffer = ''
let lastKeyTime = 0
window.addEventListener('keydown', (e) => {
  if (e.key === 'Enter') {
    const code = scanBuffer.trim()
    scanBuffer = ''
    if (isWorkOrderNo(code)) handleScanWorkOrder(code) // 匹配工单号格式 → 定位
    return
  }
  if (e.key.length === 1) {           // 单字符
    const now = Date.now()
    if (now - lastKeyTime > 100) scanBuffer = ''  // 间隔>100ms 视为手工输入，清缓冲
    lastKeyTime = now
    scanBuffer += e.key
  }
})
```

关键点：
- **间隔判定**：扫码枪字符间隔 <50ms，手工键盘 >100ms，用时间差区分扫码与手工输入
- **格式匹配**：工单号正则（如 `^(WPO|PO)\d{8,}$`）命中才响应，避免干扰正常输入
- **防误触**：仅在车间执行相关页面启用（路由守卫或页面内开关），或全局启用但只响应匹配格式

### 3.3 扫码后流程

```
扫码枪扫工单码 → 前端匹配工单号
→ 已在该工单执行页：直接高亮/提示
→ 在其他页面：跳转 生产订单列表并定位该工单（或直达执行页）
→ 执行人点 开始/完成（现有 startExecution/completeExecution 接口，已含派工联动）
```

## 四、二期方案 C（设备码防错）

- 设备管理（production_equipment）页面/设备贴牌生成二维码（内容=`EQ-{equipment_id}`）
- 工序执行**开始前**增加"扫设备码"步骤：
  - 扫到设备码 → 调校验接口 → 若该工序有派工单且指定了设备 → 校验一致才放行；未派工则记录实际设备
  - 校验接口：`GET /production/execution/verify-device?executionId=&equipmentId=`
- 移动端（三期）同样支持手机扫设备码

## 五、三期方案 B（手机扫码移动端）

- 现有前端加移动端路由（`/m/scan` 等），响应式布局
- 手机扫工单码 → 打开移动页 → 登录（账号体系）→
  - "我的派工任务"：从 production_dispatch 取 `operators` JSON 里 userId=当前用户的待办工序
  - 一键开始/完成（调现有接口）
- 二维码内容需带 URL 前缀（`http://host/m/scan?orderNo=xxx`）——工单码与 PC 扫码枪共用一个码，PC 识别工单号、手机识别完整 URL

## 六、四期方案 D（授权码轻鉴权）

- 派工单（production_dispatch）加字段：`auth_code CHAR(6)`（班组长指派时自动生成，随派工信息展示）
- 手机端操作未登录/无账号工人：输入 工单号 + 授权码 → 后端校验（工单号+授权码+该工序执行人名单匹配）→ 临时令牌操作
- 后端接口：`POST /production/dispatch/verify-auth-code` → 校验通过返回短期 token

### 9.3 摄像头扫码的 HTTPS 限制（⚠️ 关键）

浏览器安全策略：`getUserMedia`（摄像头）**只在 HTTPS 或 localhost 下可用**。局域网 `http://192.168.x.x` 会被 Chrome/Safari 直接拒绝开摄像头。

| 路线 | 可行性 | 说明 |
|---|---|---|
| 摄像头实时扫码（BarcodeDetector / html5-qrcode） | ⚠️ HTTP 下不行 | 必须 HTTPS 或 localhost |
| **自签 HTTPS 内网部署**（推荐） | ✅ 一劳永逸 | nginx + mkcert 自签证书；iOS 装描述文件、Android 装 CA，一次性配置；顺带解锁 PWA |
| **扫码枪**（USB/蓝牙） | ✅ 零配置最稳 | 扫码枪=模拟键盘，聚焦输入框扫一下即可，不碰摄像头权限；车间最常见，需买硬件 |
| 拍照上传识别（input capture） | ⚠️ 兜底 | 不依赖 getUserMedia，体验差（拍一张解一张） |

**推荐两步走**：先扫码枪/手动输入跑通流程（零成本）→ 再部署一次内网 HTTPS 解锁手机摄像头实时扫码。

### 9.4 报工数量录入缺口

现有 `complete` 接口**无数量入参**，完成时默认：产出=投入数、合格=产出数、不良=0。
- 需要：`complete` 加 合格数/不良数/不良原因 入参（或新增 `report` 接口）
- 报工记录落 `production_operation_record`（COMPLETE 类型，quantity/quality_data 字段已有）
