# 🔄 状态机统一规范

> 版本: v1.0 | 最后更新: 2026-08-01
> 适用范围: 所有业务单据的状态机设计（后端枚举 + 前端枚举）
> 目的: 防止"两个业务共用状态"、前后端枚举漂移、语义混淆

---

## 一、核心原则

1. **每个业务独立状态机**：一个单据类型一套状态枚举，禁止跨业务复用状态码段
2. **状态码 = 程序逻辑**：代码里 switch/if 分支依赖状态，禁止把状态当字典动态增删
3. **前后端必须对齐**：后端 Java 枚举 ↔ 前端 enums/ 目录（createEnum 工厂）一一对应
4. **语义唯一**：每个状态码一个明确含义，禁止"一个码两种解释"

---

## 二、状态机设计四要素

每个状态机必须定义：

```
1. 流转图    — 状态间合法跳转（谁→谁）
2. 终态      — 不可再流转的状态（如 已完成/已关闭/已作废）
3. 拒绝路径  — 审核拒绝/退回走哪（区分"可改重提"和"终态退回"）
4. 回退路径  — 允许回退的状态（如 改单 8→9）
```

### 示例：样品单状态机（10 态，已落地）

```
1 创建(CREATED)
  → 2 待审核(SUBMITTED)         提交审核
2 → 3 工程打样中(ENGINEERING)   审核通过
2 → 1 创建(CREATED)             审核驳回（可改重提）✅ 拒绝路径
3 → 4 待送样(READY)             标记完成
3 → 2 待审核(SUBMITTED)         工程拒单
4 → 5 已送样(SENT)              送样登记
5 → 6 已确认(CONFIRMED)         客户确认OK
5 → 9 客户退回(REJECTED)        客户退回（工程重打）✅ 与驳回区分
6 → 7 已转量产(TRANSFERRED)     转量产
7 → 8 已关闭(CLOSED)            终态
9 → 3 工程打样中                重新打样（restart）✅ 回退路径
10 已作废(CANCELLED)            终态
```

**关键教训**：曾用状态 9 同时表示"审核驳回"和"客户退回"，语义冲突 → 拆分为"驳回→1可改重提"、"退回→9工程重打"（DEV-443/445）

## 三、命名规范

### 后端枚举
```
枚举类名: {业务}StatusEnum    如 SampleOrderStatusEnum / QuotationStatusEnum
常量名:  大写语义名          如 ENGINEERING / CONFIRMED / TRANSFERRED
构造:    (code, name, description, editable, terminal)
```

### 前端枚举
```
文件:    jjx-web/src/enums/{模块}/{业务}Enum.ts
工厂:    createEnum([{ value, label, color?, desc? }])
导出:    枚举 + 工具函数（getLabel/getColor/options）
```

### 状态码编码规则（按业务段分配）
| 业务 | 段 | 状态 |
|---|---|---|
| 报价单 | 0-9 | 0草稿/1已发送/2已确认/3已拒绝/4过期/5待审核/6已审核/8改单/9已完成 |
| 样品单 | 1-10 | 1创建/2待审核/3打样中/4待送样/5已送样/6确认/7转量产/8关闭/9退回/10作废 |
| 销售订单 | 0-9 | 0草稿/1待审核/2审核中/3已确认/4生产中/5已完成/6已取消 |
| 采购单 | 1-5 | 1草稿/2已取消/3待审批/4已批准/5已拒绝 |
| 生产工单 | 0-7 | 0草稿/1待排产/2已排产/3生产中/4已完成/5已取消/6已暂停/7已关闭 |

⚠️ 新业务申请状态段前，检查是否与已有业务冲突

## 四、前端枚举同步规范

1. **状态展示一律用枚举**，禁止硬编码映射表
2. 后端改状态 → 必须同步前端 enums/ 对应文件（同一次提交）
3. 新状态颜色：
   - 进行中 = primary/warning
   - 成功/完成 = success
   - 拒绝/取消/作废 = danger
   - 草稿/待处理 = info
4. 枚举缺值显示：`getLabelSafe` 返回"未知"，不报错不显示空

## 五、新模块状态机过审清单（Checklist）

开发新状态机前对照：

- [ ] 状态码段不与现有业务冲突
- [ ] 有明确流转图（谁→谁，每跳转有动作）
- [ ] 定义了终态（至少 1 个）
- [ ] 定义了拒绝路径（驳回/退回去向）
- [ ] 定义了回退路径（改单/重打去向，如允许）
- [ ] 后端枚举含 description + terminal 标记
- [ ] 前端枚举已建（createEnum + label/color）
- [ ] 操作日志能记录状态跳转（bizStatus）
- [ ] 每个跳转有 @Event 事件（如适用）
