# 补产主流程闭环与追溯修复（dev-20260926-001）

## 目标

将不良报废后的补产与“补报历史工序记录”明确分开，按可追溯、可派工、可复检的实际生产流程处理。补产仍复用原工单和原工艺路线，不新建工单；不改变现行“入库不是工单完工前置”的口径。

## 实施内容

- 报废补产申请校验不良单归属当前工单，并要求该不良单存在已完成的 SCRAP 处置；可申请量按已完成报废数量扣除尚未取消/驳回的替补申请，阻止重复或超量申请。NCR 已结案不再被“待处置量为零”错误排除。
- 申请补料时不创建生产任务。仅在出库确认、库存实际扣减成功的同一事务中，按原工单标准工序顺序为每道工序生成 SUPPLEMENT 任务；以补料单和工序作为幂等键，保留来源 NCR、出库单和补产组号。
- 补产报工只允许 SUPPLEMENT 任务；普通标准任务/已完成工序不再通过损耗额度入口补出新产量。补产组必须按工艺顺序完成前序后才能报下一道工序。
- 不良台账从已完成报废处置行发起时，将该报废行数量带入补产申请。页面明确说明申请、驳回不派任务；仓库确认发料后才出现补产派工任务。
- 工单对账的“已报工”按单道工序的最大累计量展示，不将串行工序重复累加；在制量按该口径扣除检验量。物料领用及补料对账仅计入已完成出库单，避免草稿/待审申请冒充实际发料。

## 后续验证边界

当前实现尚需在测试环境以报废 1 件的 NCR 做完整 UI 验收：申请后确认任务未生成；仓库确认出库后生成全路线任务；前道完成后后道才可报工；末道报工生成 FQC，合格后补足工单良品数。需特别检查已有工序均已完工时，SUPPLEMENT 任务可在对应工序执行记录上正常报工并创建最终 FQC。正式数据不做手工补写。
