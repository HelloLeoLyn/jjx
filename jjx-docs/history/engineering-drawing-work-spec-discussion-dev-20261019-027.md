## 1. 原始问题

用户在「产品作业规范 → 结构图」上传了一张新的结构图 B，发现不满意，想用回之前那一版 A。现在的操作路径是到「工程图集」里把 A 版设为现行，但作业规范里显示的结构图仍然是 B，换不回去。

一句话：作业规范的结构图无法回选历史版本。

## 2. 已核实现状

### 2.1 作业规范侧

- 结构图区域默认只读；点「编辑」后只能点图片区选择文件上传（`ProductWorkSpecPanel.vue:41-56`）。
- 上传成功后直接把 `structureFileId` 写成新附件 id（`StructureDrawingUpload.vue:204`）。
- dev-20261019-023 删除了原有的「选择这张规范单使用的图纸」下拉，并在测试中明确断言“无选择器”（`ProductWorkSpecPanel` 测试用例：默认只读、编辑后仅图片区可上传）。
- 后端本身支持选择已有附件：`ProductWorkSpecService.structure`（`ProductWorkSpecService.java:308-320`）只校验“该产品已关联 + 类型为结构图/STRUCTURE_DRAWING + 可预览”，不要求新上传。

### 2.2 工程图集侧

- 图纸按 `drawingNo + version` 合并为版本行（`EngineeringDrawingLibrary.vue:177`）；列表按 `drawingNo` 合并为图纸行（`190-209`）。
- 版本行操作只有「设为现行」「下发/撤回」（`34-35`），图纸行也重复提供同样操作（`75-78`）。
- 「设为现行」调用 `SysAttachmentServiceImpl.setCurrentAttachment`（`726-746`）：只写 `sys_attachment.is_current`，并清空该版本的下发标记；不写 `product.work_spec_json.structureFileId`。
- 「下发/撤回」调用 `setReleased`（`751-767`）：只写 `released / is_controlled / released_at / released_by`；只有现行版本允许下发（`757-759`），需要 `engineering:drawing:release` 权限（`SysAttachmentController.java:203`）。
- 作业规范纸张与在线预览读取的是 `work_spec_json.structureFileId`（`ProductSpecPreview.vue:105-106`），因此图集里设现行不会改变作业规范的图。

### 2.3 结论

图集里的“现行/下发”服务的是图集自身与文档集打印，不服务作业规范的选图。作业规范要回选旧版，必须把选定结果写回 `structureFileId`。

## 3. 已定方案（dev-20261019-025）

卡面要点（以 `sys_task.description` 为准，含第 7 段补充）：

1）结构图版本点「设为现行」时，同步把作业规范 `structureFileId` 指向该版本打印件（无打印件用可预览文件）；只对结构图类型生效；不自动下发、不自动发布规范；写前读取最新 work-spec 与 revision，冲突要明确提示。
2）图集常用操作简化（本卡前两项）：
   - 外层图纸行只留「新版本」/「补录关联」；设为现行、下发只在展开后的版本时间线出现。
   - 行内「新版本」选文件即上传，继承编号/名称/资料类型，版本自动递增；无法递增时回退现有弹窗。
3）图纸编号/名称规则（第 7 段补充，用户确认“相同就加序号”）：
   - 编号 = 产品编码-类型代码；同产品同类型第一张不加序号，第二张起 -2、-3。
   - 类型代码：ST 结构图、OUT 外形尺寸图、PNL 面板图、CIR 线路图、ASM 组装图、PKG 包装图、PRT 印刷指导图、CFM 确认图、FLM 菲林、MLD 模具、DIE 刀模参数图、ENG 工程图、DWD 刀模图。
   - 名称 = 产品名称+类型标签，同类型第二张起加同样序号；产品名称为空用产品编码。
   - 行内「新版本」继承原编号/名称，只递增版本；历史数据不改写；规则与作业规范结构图上传共用一套实现。
   - 界面不显示、不要求填写编号和名称。

5）图集使用的 `product()` 链路未回填 `source_no`，要显示“报价单 QT…”需补查询。

## 6. 术语澄清（讨论中反复出现的误解）

### 6.1 用途、版本、图纸身份是三件事

- 用途（`fileRole`）：这份文件是工程原稿还是预览打印件。
- 版本（`version`）：同一张图的第几版（A/B/C）。
- 图纸身份（`drawingNo`）：这是哪一张图。

只有用途和版本不够：同一产品两张面板图（正面/侧面）可以同时是“面板图 + A 版 + 打印件”，三个字段完全相同，但它们是两张图。没有图纸身份，设现行、打印选件、版本历史都无法区分。

### 6.2 展示文件名不能当图纸身份

展示名规则（`AttachmentDisplayNameService.java:108-120`）示例：`PROD-123-P123-ENG-SD-结构图-01`。

1）序号是“同一来源、同一单据、同一产品、同一类型下第几个文件”，不是“第几版”。
2）同一张图的原稿与打印件会得到 -01、-02，被当成两个文件。
3）换来源前缀变化：同一附件在产品下 `PROD-…`，在报价单下 `QT-…`。
4）删文件后 `renumber` 会重排序号（`176-205`），身份会漂移。

结论：展示名用于显示文件叫什么；图纸身份由 `drawingNo + version` 承担，界面可以不显示，但不能去掉。

### 6.3 后端限制要分类

1）账、权限、追溯（库存流水、硬引用、受控文件、权限）：必须后端守，前端拦不住直接调接口。
2）流程规则（同版本多文件、已下发追加等）：可以前端先放、后端后放宽，021 属于此类。
3）展示与聚合（图集显示哪些来源、怎么分组、编号规则）：应由前端/配置决定，后端只给数据。
