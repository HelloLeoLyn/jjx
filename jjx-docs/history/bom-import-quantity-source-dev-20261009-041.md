# 修复BOM导入实发数量间接覆盖应用料

- 任务：dev-20261009-041
- 日期：2026-10-09
- 执行人：Codex
- 用户授权：对已定位的实发数量间接覆盖应用料问题明确要求“修复”。

## 原因

dev-20261009-039只移除了应用料列的直接读取，导入器仍把单用量/实发数量/数量映射到quantity。BomItemEditor初始化时仅用quantity乘损耗系数，没有先按基数÷模数计算；只有手动修改基数或模数时才补算quantity。

实际文件YL1025BOM.xlsx首项模数6、实发数量515，没有应用料列；实发数量被当作quantity，在损耗0时应用料显示515。文件仅用于定位，未加入本提交。

## 修改

1. 导入器取消单用量/实发数量/数量的计算输入映射，基数、模数按原规则读取；quantity统一由当前基数÷模数计算。缺基数时仍使用原有默认1，未变更必填口径。
2. 模板移除单用量输入列，同步调整示例及提示；旧表保留相关列也会被忽略。其他导入列口径不变。
3. 新增前端共用calculateBomQuantity，导入及BomItemEditor共用。初始化、修改基数/模数、损耗等入口都先算quantity，再算应用料；四位小数与原手动计算一致。
4. 后端保存时有效基数、模数下也重新计算quantity，再按既有损耗公式计算应用料，避免旧客户端带入历史实发数量。用量变更日志使用同一计算值，避免与实际保存值不一致。
5. 为兼容旧档案，缺少有效基数/模数时不凭空补参数，保留原有用量并由已有审核校验处理；本次不迁移或批量订正历史BOM，不改领料/库存写入路径。
