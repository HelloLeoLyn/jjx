# 补产报工额度与旧入口安全收口（dev-20260926-002）

## 问题

旧补报分支绕过生产任务剩余额度，改由非BOM的固定/配置型5%上限控制；旧 `createSupplementTask` 入口只创建末道单任务，不能保证NCR、已完成报废量和发料来源校验。工艺路线补产任务被派工后，其子任务也未继承补产来源身份。

## 调整

- 所有报工统一受当前任务剩余额度限制；删除基于 `production.report.overrun-rate` 的补报硬上限及其5%缺省值。
- 补产任务创建及报工时验证：工单归属的不良单、已完成且关联同一NCR的报废补料单，以及该NCR已完成报废数量能够覆盖所有已确认补产申请量。
- 创建补产任务时锁定NCR行，串行化同一NCR的并发补料确认，避免合计补产量超过报废量。
- 移除旧的单末道 `createSupplementTask` 服务入口，只保留已确认发料后按标准工艺路线创建任务的入口。
- 派工生成的子任务继承补产类型、补产组、不良单和出库单来源，报工继续验证来源并按子任务剩余额度控制。
- 仅允许补产任务在执行中或已完成工序报工；未开始、暂停、跳过或取消的工序仍拒绝报工。

## 验证

- 后端定向测试12项通过：任务剩余额度、超量拒绝、旧入口移除、补产来源数量边界及既有补产额度/任务号测试。
- 未修改业务数据或数据库结构。

## 遗留

- 运行完整生产流程回归需部署后验证；本任务未变更正常生产工序的计划量口径，该问题由 dev-20260926-009 单独评审。
