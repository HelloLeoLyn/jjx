# 正常工序实绩超计划报工评估

## 现行系统与问题边界

- 工单计划量200建单时写入每道正常工序的 `input_quantity`，该字段代表工序计划投入，不是现场实测投入。
- 普通报工输入的是本次合格量和不良量；两者之和校验不超过当前任务剩余额度。初始任务量200，故某道工序“200合格+10不良”会被拒绝。任务拆分/派工也受父任务额度限制。
- 当前没有实测投入、工序间实物转移量或普通工序在制账。工序报工是经审批的产出事实，返工/报废是单独的质量处置事实；不能把报工量减FQC量称为实物在制。
- 串行工序同一批产品会在每道工序形成报工记录。工单层吞吐不能把各工序报工直接求和；应逐道展示，并以正常路线单道最大产出作去重后的吞吐参考，末道产出和有效FQC良品另列。报废是已判定不良的最终处置，不良报工量本身不等同报废。

## 建议定义与最小改造

1. 工单目标量：订单原计划量，代表需求目标，不因报工超产自动改写。
2. 工单授权生产上限：独立于BOM损耗率的每单授权量；如任务008批准计划200、上限210，则同一上限供全条正常工艺路线和任务树使用，不能每道工序再各加10。
3. 工序字段：保留“计划投入”作为计划值；标准报工继续记录审批通过的合格、不良和产出合计（合格+不良）。不良再由NCR分解为返工、让步、报废；已报废量只计完成的SCRAP处置，避免把同一件同时算作不良和报废两件。
4. 流转/在制：当前没有实物流转凭证，不新增伪造的“实际投入/转序/WIP”数字。首期只逐道展示计划投入与已审批产出，另列返工在制和有效FQC待检批次数。只有用户确实需要逐工序实物在制时，再单独建设工序转移/报废过账链。
5. 末道/FQC边界：末道实际报工可到授权上限；FQC按实际批次检验。最终合格超原计划部分能否入可用库存、如何标识，由任务008确定；在该决策前，不放开完成入库上限。

这样能够如实记录某工序处理210件，同时不会把两道工序的210+210误算成420；也不会用物料损耗率当成产品超产率。首期不增加逐件WIP台账或新的跨工序审批流程。

## 行业产品模式参考

Oracle Fusion Manufacturing 的工序事务以当前可交易/待流转数量控制数量，超完工容差配置在工单层，并仅允许在首个计数工序按该容差超出；其工单绩效分别展示工单、工序和事务层的完成、报废、拒收、Ready数量。此为可验证的商业ERP实现模式，支持“工单统一授权上限 + 工序逐道实绩 + 不跨工序累计”，不是宣称存在统一强制百分比。[Oracle工序事务规则](https://docs.oracle.com/en/cloud/saas/supply-chain-and-manufacturing/25c/faumf/how-you-report-operation-transactions.html)；[Oracle工单性能口径](https://docs.oracle.com/en/cloud/saas/supply-chain-and-manufacturing/25c/faumf/manufacturing-work-order-performance-real-time.html)

## 验收建议

- 计划200、未授权超产：工序累计产出201拒绝。
- 计划200、经批准上限210：首道报工210（例如200合格+10不良）可审批；第二道报工210后，工单吞吐显示210而非420。
- 报废10只在NCR的SCRAP完成后计入报废，不与该工序不良10重复相加；已批准的返工/让步按各自质量处置状态展示。
- FQC合格200、批次不良/待处置10时，完成与库存口径按现有质量守恒；FQC合格210的接收入库规则遵从任务008最终决策。
- 没有转序/投入凭证时页面不得显示“普通在制件数”。

本评审不改业务数据和规则；工序超额任务额度及超计划FQC入库必须等任务008授权边界确认后再实施。
