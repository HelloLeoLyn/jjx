# 工单超计划产出边界评审

## 现行系统核查

计划量200的普通工单，建单时将200写入各工序 `input_quantity`，并以200创建工序首任务。普通报工校验“本次合格+不良 ≤ 任务剩余额度”，任务额度又扣除已分配、待审批和已审批报工，因此正常路线当前不能如实累计报工210。补产任务是单独的NCR报废替补路线，不应拿来绕过普通生产额度。

FQC判定按批次量和质量处置量做数量守恒；判定之后，`QualityFinishServiceImpl.syncFinishInbound` 又阻止工单有效FQC合格累计超过计划量，并由此回写完工数和生成成品入库。也就是说，正常工单目前没有“计划200、实际合格入库210”的完整闭环。即使物理上多做了，系统既不能在普通任务如实报210，也没有超额成品的专门库存去向。

BOM损耗率计算的是物料应领基准（单耗×计划量×损耗率），不是成品超产比例，也不能自动推出“产品可多做5%”。

## 行业产品模式与建议

主流制造ERP会把订单计划量和超完工容差分开配置，而不是默认无限超产。Oracle Fusion 的离散工单可配置按数量或百分比的工单级超完工容差；其操作事务文档把超完工放在首个计数工序，并限制在工单容差内。这是一个产品实践示例，不是所有行业都必须采用同一百分比。[Oracle工单字段说明](https://docs.oracle.com/en/cloud/saas/supply-chain-and-manufacturing/25c/faumf/how-you-manage-a-work-order-header.html)；[Oracle工序事务规则](https://docs.oracle.com/en/cloud/saas/supply-chain-and-manufacturing/25c/faumf/how-you-report-operation-transactions.html)

建议口径：保留200为订单目标；若业务确认允许多做，则对每张工单单独登记经授权的“最高生产量/超产量”，不从BOM损耗率推导、不为每道串行工序分别叠加容差。标准报工、末道产出和FQC都受同一个授权上限约束。有效FQC合格超过200的部分必须有明确去向；建议在同一成品入库批次中作为“超计划产出”单独统计并可追溯，销售/订单交付仍以原目标200为准。若组织不希望多出的良品进入库存，则应选择明确拒绝超计划良品，而不是让检验事务报错回滚。

## 需要业务拍板的边界

1. 计划200、授权上限210、实际合格210时，是否允许210全部作为可用成品入库，同时把超出的10标记为超计划库存？
2. 工单超产上限按每单直接填写数量（建议，易理解、可审计），还是按百分比生成？谁有权批准上限？

在这两项确认前不改规则。此评审未改工单、报工、检验或库存数据，也未改入库结案口径。
