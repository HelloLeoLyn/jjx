## 页面操作方案

1. 底部固定显示“保存”“保存并关闭”“关闭”；“保存”为主要操作，长工序列表滚动时仍能找到按钮。
2. “保存”成功后停留在当前路线编辑界面；“保存并关闭”成功后刷新父列表并关闭。
3. 有真实未保存修改时显示“未保存”状态；成功保存后恢复已保存状态。页面初始化、数据加载、ID 回填不视为用户修改。
4. 保存期间防止重复提交，并保护关闭操作；校验不通过或接口失败时留在原界面，保留输入和未保存状态。
5. 沿用现有工艺路线校验、权限、审批及版本规则，不引入自动保存，不通过本任务重新定义版本升级条件。

## 变更判定

- 新增和修改均建立完整可编辑内容的基线：产品选择、路线编码／名称／版本、描述、备注，以及全部工序和作业项。
- 工序内容包括层级和顺序、关联工序、工时、说明、作业指导、备注及印刷色号、油墨编号、网框编号等工艺参数；参与保存的变更说明也纳入未保存判断。
- 复用现有工序快照的规范化能力；ID、时间等服务器回填字段不作为用户修改。空值和等价参数不产生虚假提醒。
- 用户修改后恢复原值，应恢复无变更状态。完整表单的未保存状态与现有用于版本处理的工序变更标记分别承担职责。

## 离开提醒

- 点击“关闭”、右上角 ×、按 Esc，以及通过应用导航离开页面时，若有未保存修改，展示“保存并离开 / 放弃修改 / 继续编辑”。应用标签关闭路径在实施时核查并纳入保护。
- “保存并离开”：使用同一套校验和保存逻辑，成功才执行原离开动作；失败或取消校验则停留。
- “放弃修改”：明确放弃本次尚未保存的修改并执行原离开动作。
- “继续编辑”：取消离开，保留全部输入；无修改时正常离开，不弹提示。
- 点击弹窗遮罩不应意外丢失输入：实施时禁用遮罩关闭，或统一接入相同离开保护。
- 浏览器刷新、关闭标签页或窗口时使用 `beforeunload` 原生提醒，仅在确有未保存修改时启用；浏览器控制提示文案和显示条件，不承诺自定义三按钮或强制显示。
- 防止一次操作重复弹出确认；保存与已确认离开后清理保护，组件卸载时移除监听。

## 保存后数据同步

- 新增成功后取得真实路线 ID，当前窗口切换为修改该路线；再次保存必须修改同一条路线，不能重复新增。
- 修改／版本升级成功后，以接口返回的实际路线身份和版本为准，再读取最新详情及真实父子明细 ID；不能继续使用保存前或临时 ID。
- 同步编辑器与完整表单后建立新基线，更新父列表；此后仅检测新增的用户修改。
- 若业务保存成功但详情回读失败，明确提示“已保存，重新加载失败”，阻止使用过期身份再次提交，并提供重新加载方式；不能将成功保存误判为失败再次新增。
