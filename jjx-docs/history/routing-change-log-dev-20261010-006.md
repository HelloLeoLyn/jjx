# 根治工艺路线修改流水误报与明细差异漏记

- 任务：dev-20261010-006
- 日期：2026-10-10
- 执行人：Codex

## 只读定位

路线1的日志在10:46、10:53、10:55连续记录“面板+面板背胶 新增作业项:面板/面板背胶”。数据库父明细86、子明细87/88的parent_id均为86，实际父子关系正常。

根因链路：EngineeringRoutingItemMapper.selectByRoutingId使用SELECT i.*，没有将detail_id别名映射为实体itemId。差异比较依赖父itemId查旧children，取不到旧子项就误报新增。前端RouteItemIconEditor组装组合父项时又借用第一个子项的ID，没有保留真实父项ID。

另外，旧比较用processId/名称作为单值Map键，同一工序重复出现会互相覆盖；仅比较增删和工时，漏掉备注、作业说明、印刷参数等。前端修改快照也未包含这些字段。

## 修改范围

1. 查询增加i.detail_id AS item_id，保留既有查询排序及明细字段，不改表。
2. 编辑器回填时保留父项自身数据和真实ID；组合项组装不再借用第一个子项ID。由组合变成独立项仍保留原父项身份，便于记录结构变化；新增组合的父ID留空占位，真实ID由后端保存回填。
3. 后端父项及子项均逐项匹配，优先为全部真实ID保留旧行，再对无ID客户端按大类、类别、工序身份及字段内容匹配，最后按出现顺序兜底。旧行只使用一次，不合并重复工序。
4. 记录真实新增/移除、关联标准工序、名称、大类/类别、人工/机器工时、说明、作业说明、备注、下标、前置依赖、可选属性及工艺参数变化。
5. 父工序顺序按saveItems实际保存的类别内序号和分组顺序比较；子作业顺序按实际持久化顺序比较。日志标签带类别和位置，区分同名重复工序。
6. 印刷参数分别记录印刷名称、色号、油墨编号、网框编号，其他参数逐键记录；JSON空白排版和键顺序不造成误报，数字按数值比较。旧非JSON参数仍按原文记录，不因解析失败丢掉整次变更。
7. 空白文字与空值、空工时与0、工时的小数位差异不产生无意义修改记录。比较新值复用buildItem的保存规范化，不比较临时ID或时间戳。
8. 前端修改快照递归纳入父子项备注、作业说明、说明、印刷参数等字段，工艺参数按键排序，空参数与空白字段统一；回填保留已有前置依赖和可选属性，避免保存时丢失。
