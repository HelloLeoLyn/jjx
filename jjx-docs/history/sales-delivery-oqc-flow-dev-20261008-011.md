# 销售发货 OQC 放行前置及签收流程修复

任务：dev-20261008-011；日期：2026-10-08；执行：Codex。

## 背景与证据

DL261008001的JST003MEOO签收被未完成OQC拦截。原流程在订单发货入口直接置发货单已发货，创建待检OQC，随后发布出库事件；签收才检查OQC。库存桥接捕获出库错误，可能造成已发货但未扣库存。
用户批准改为“创建待发货单 → OQC合格并放行 → 确认发货及出库 → 客户签收”。

## 实现

- 原订单发货入口改为创建待发货单，保留本次发货快照及OQC创建，不更新订单已发状态、不发布发货出库事件。前端按钮、弹窗、成功提示及引导同步改为“创建待发货单”。
- 复用既有SalesDeliveryStatusEnum/DeliveryStatusEnum的待发货值，无新状态或迁移。待发货、已发货、已签收数量计入建单占用，已拒收不占用；弹窗展示“已建单占用/可建单”，不把待检数量误称已发。
- 发货管理新增出货检验及确认发货。出货检验跳转已有OQC工作台，并通过businessNo筛选当前单据；切换单据时同步更新筛选。
- 新增POST /sales/deliveries/{id}/confirm-shipment，权限沿用sales:order:edit。确认事务锁定发货单及订单，校验待发货及订单生产中，拒绝重复确认；创建待发货单也使用同一订单行锁防并发超发。
- 每条明细按来源发货单/来源明细查最新OQC版本，要求合格、已判定或已关闭、已检数量大于零、批量覆盖本次数量；如已有审核状态，则必须已审核。使用既有检验结果、检验批状态及审核状态枚举。最新版本失败/待检时不接受旧版本合格。
- 当前发货明细、订单产品与数量必须匹配；累计实际已发及签收数量不得超订单数量。历史已发单缺明细或数量不完整时阻止继续确认，不推算或补造数量。
- 库存出库在确认发货同一事务内调用既有createFromSalesByDelivery；成功后才更新发货单已发、订单shipped_quantity及全发时的订单已发状态。库存异常、审批/确认返回false、状态更新失败均抛异常回滚。
- 本订单的实预留可计入其可发库存，其他订单预留仍扣除；同产品多行累计消耗可用量，不能逐行重复利用。实际扣减仍沿用现有InventoryStockMutationService及流水，不引入数量直写。
- 事务提交后保留order.delivering通知事件，payload注明inventoryPosted及outboundId，库存桥接跳过已过账事件，避免再次扣库存。旧事件兼容逻辑不改变。
- 仓库旧“按销售订单直接出库”HTTP入口明确拒绝并引导发货管理，避免绕过本次发货快照及OQC放行。
- 签收只允许已发货，登记客户实际收货，不再校验内部OQC。不允许待发货、已拒收或已签收重复签收；旧已发货单可以正常登记实际签收。拒收重算已发量时排除待发货占用。
