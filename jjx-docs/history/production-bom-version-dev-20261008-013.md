## 实现

- 计划转工单继承计划 bom_id。指定 BOM 必须存在、属于相同产品且已批准；工单产品与计划不同则在保存前拒绝。
- 新增 ProductionBomResolver，统一按工单绑定的已批准版本取数，不要求它仍是产品当前版本；缺失、产品不匹配、未批准或已作废时明确报错，不自动切换当前版本。
- 领料预览、补产数量预览、自动生成领料、剩余需求、确认发料后的缺口计算和已绑定工单的领料打印接入同一解析器。确认发料在扣库前解析版本，避免关联错误被原缺口计算的兼容 catch 吞掉。
- 历史未绑定工单的领料仍保留“产品当前已批准 BOM”兼容逻辑，不自动绑定父计划或回填 bom_id；旧打印继续将位号/模数留空，不把当前 BOM 冒充历史版本。该类工单仍存在换版漂移，需另行核对真实领料依据后处理。
- 沿用已有 BOM 版本机制：已批准 BOM 的普通编辑入口拒绝修改，可复制为新版本。此次保存的是版本引用，不新增完整内容快照，不改 BOM 审批/作废制度。
- 无表结构迁移、无历史业务数据修改、无库存数量或流水直接写入。任务状态登记是唯一数据库写入。
