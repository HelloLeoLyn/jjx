# BOM项目导入归位并支持未匹配名称原样保存

- 任务：dev-20261009-044
- 日期：2026-10-09
- 执行人：Codex
- 用户授权：确认项目/项目名称应落项目；未找到对应项目时用户填什么就保存什么，随后同意实施。

## 原因与字段

Excel导入器已识别项目/项目名称，却将其作为备注的备用值，没有填写processName。页面只绑定processId，无法输入或回显无标准工序关联的项目名称。

只读核实engineering_bom_item：process_id为bigint允许NULL，process_name为varchar(200)允许NULL。后端保存已接收这两个字段，提交校验仅在processId非空时检查引用；无需改表或后端。

## 修改

1. 项目/项目名称独立映射到processName，保留该单元格原文；备注仅读取备注列。
2. 项目选择框支持选择标准工序、输入自定义名称、清空和回显。选择标准工序时保存ID与名称，自填未匹配名称时ID为空、名称原样保存。
3. 使用现有启用工序全量查询接口，避免原分页只取200条而遗漏可匹配项目。导入初始化和选项加载完成均执行匹配，仅完整名称唯一匹配时关联ID，重名不擅自选第一个。
4. 自填项目作为独立选项回显；修改名称清除原关联ID再匹配，清空同时清除ID和名称。保存前检查名称200字符上限，不截断原文；类型注释同步实际业务含义。
5. 未批量改写历史BOM或备注，不创建标准工序，不改库存、用量计算或打印版式。

## 交接

按用户要求只做代码和源码差异审阅，不执行测试、编译、重跑、浏览器验证或服务生命周期操作。仅git diff --check检查差异格式。

用户验收：导入项目/项目名称与备注同时存在的Excel，各自进入对应列；唯一同名启用工序关联ID；未知名称按原文显示和保存，重新打开仍显示；手填名称、改选标准工序与清空不残留旧ID；超过200字符提示修改后再保存。

历史备注中的错误项目值本次不自动迁移。用户可在允许编辑的BOM中重新导入或手动修正并保存。
