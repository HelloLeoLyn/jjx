## 0. 一句话结论

002 转生产后"不预警材料采购"，根因是**齐套只看全厂共享的成品现货、没有订单归属，且一判"现货覆盖"就短路不展开 BOM**。修法分四段：**P1 只读口径止血（解耦 + 去短路 + 拆两个 gap）→ P2 把"占用"落成数据（治本核心）→ P3 材料层汇总与分摊 → P4 业内增强**。v4 方案骨架可用，但有一条**致命内部矛盾**（§4.1）必须先改，否则 P1 达不到它自己写的验收。

## 2. 根因（三个断点）

1. **读口径是共享池**：`getProductAvailable` = 总量 − 已预留，不扣别的订单的需求 → 谁先查谁用
2. **没有"下单占位"**：成品侧只有"入库后才预留"（`reserveForOrder` 按当前库存预留），没有"下单即占用（含未生产段）" → 001 的 100 件需求从没占住那 97
3. **判"现货覆盖"即短路**：`productAvailable ≥ 订单量` 就 `continue`，BOM 不展、材料需求不产生 → 002 材料采购预警天然缺失

**后果链**：001 实际只完工 95（差 5），002 又吃掉 97 里的 30 → 账面"97 现货"早就不够，但系统一路放行。

## 3. 业内对标（ATP / MRP）

**符合业内的部分**
- 净可用 = 供给 − 已承诺需求 → ATP（可承诺量）
- 不短路、按净需求展开 BOM → MRP 净需求
- 本单在制计入本单可用 → predicted supply
- 材料全厂汇总 + 按优先级分摊 → 共享池 + 分配规则
- 供给含在途 → scheduled receipts
- 实时重算、不自动撤已下 PO → 例外管理 / 变更管理

**偏离业内的部分（差距）**
1. **没有硬占用闭环**（承诺→硬分配→发货）；P1~P3 期间若"停写"会留下"承诺了但没占住"的空洞
2. **没有时间轴**（time-phased ATP，按日/周桶净算），只有"到货日 ≤ 某截止日"的粗过滤
3. **没有需求追溯 pegging**（供给挂到具体需求）
4. **没有安全库存**（可用量未扣 `safe_stock`）
5. **优先级用"审核时间"**（会随人工操作漂移）
6. **没有欠交台账 backorder**（未满足需求是瞬时值，不落记录）

**定位**：现有设计 ≈ 业内 ATP/MRP 的**简化版（约 0.5 阶）**，方向对、不完整。

## 4. v4-final-draft 复核结论

### 4.1 🔴 致命：2.3 与 2.4 用两个不同的 gap 展开 BOM（解耦没落到 2.3 上）
- **1.3 / 2.3**（单订单齐套，审核时跑）：`gap = max(0, 需求 − 有效可用)`（**含在制**）
- **1.4 / 2.4**（材料汇总）：`gap = max(0, 需求 − 现货可用)`（**不含在制**）
- 取 002 走 2.3：有效可用 = 0 + 30 = 30 = 需求 → **gap 0 → 不展开 BOM**
- 取 001 走 2.3：有效可用 = 97 + 5 = 102 ≥ 100 → **gap 0 → 也不展开 BOM**
- ⇒ **P1（改的正是 2.3）两单都不展开 BOM → 一条材料预警都没有**，与它自己第九章"第一阶段看 002 报缺 15"**直接矛盾**
- **修法**：2.3 拆两个 gap —— 成品行"要不要再投产"用 **effective gap**；**BOM 展开用 spot gap**（不含在制）

### 4.2 🟡 在途过滤取"全厂最近交期"——过保守
- 取值 = 所有有效订单里**最早**交期 → 只有到货日 ≤ 最早交期的在途才算供给
- 后果：**交期靠后的单系统性少算在途** → 缺料报大 → 可能多订
- **修法**：按**各单自己的交期**在分摊循环里过滤（谁的单用谁的截止日）；或明确标注"刻意保守"

### 4.3 🟡 材料预占"停扣不停写"
- v4 说 P1"停扣 `order_material_reserve`"，但**审核流程 `confirmReserve` 仍在跑**（无记录时会 `reserveForOrder(orderId,0)` 新建行）
- 后果：一边不读、一边还在写 → 旧账继续长大
- **修法**：P1 起一并停写（`confirmReserve` / 材料预占生成），或明确其只读化

### 4.4 🟡 验收数字不能写死"15"
- 实测 `RM001601` 现有库存 **9**（非 0），且无未收货采购单
- 按优先级：001 先拿 1.5 → 剩 7.5 → **002 实际缺 7.5**（数字随供给变化）
- **修法**：验收写作"**002 缺口 = 需求 15 − 分到的供给**"

### 4.5 小疤
- 4.4 把"材料**需求**"写成"材料**缺**"（有供给时两者不等）
- 现货 97 里 **2 件是让步接收**（`IN260930002` / FQC_CONCESSION），非 001 工单产出 → 用例现货来源不纯，应注明
- 材料可用量未扣**安全库存**
- 1.1 的"已确认/已审核/生产中"应写明枚举（`APPROVED=4 / CONFIRMED=6 / IN_PRODUCTION=7`）

## 5. 分阶段实施计划

> 原则：每段可独立验证、可回退；**P1 不停写**（避免"发货无硬占用"空洞）；**"停旧写"发生在 P2 占用上线那一刻**。

### P1 · 止血（只读口径）—— 0.5~1 天
- **目标**：002 报出材料缺口；不改模型、不碰写入路径。
- **改动范围**
  - `InventoryAlertServiceImpl.getProductAvailable()`（523）→ 净可用：只扣**优先级高于本单**的有效订单未满足需求；下限 0
  - `InventoryAlertServiceImpl.calculateOrderShortage()`（156）→ **去短路**；**拆两个 gap**：成品行用 effective gap（含在制），**BOM 展开用 spot gap（不含在制）**
  - 并入：**安全库存**（`inventory_material.safe_stock`）；在途**按本单交期**粗过滤；**独立优先级**（交期 + `is_urgent`）
  - **不动写入**：`reserveForOrder` / `confirmReserve` 照旧 → 发货仍有占用
- **验收**：SO260930002 报出 `order_shortage`（材料缺口 = 15 − 分到的供给）；SO260930001 不被 002 拖累
- **回退**：单文件为主，`git revert` 即可
- **风险**：低；P1 期间"齐套新口径 vs 旧预留"双账并存（**仅显示不一致，不影响发货**）

### P2 · 占用落数据（治本核心）—— 1.5~2.5 天
- **目标**：占用成为数据基座，齐套/发货都读它。
- **改动范围**
  - 表：`sales_order_stock_reserve` 加列（占用类型 软/硬、来源工单、截止日）+ 1 条迁移（`jjx-docs/sql/migrations/NN_*.sql`）
  - 后端：审核时落**软占用**（含未生产段）→ 齐套**改读占用**（不再现算）→ 成品入库钩子把"待生产"转**硬占用** → 发货读占用 → 取消/关闭/驳回**回吐**
  - **切换完成后**才停旧写（`reserveForOrder` / `confirmReserve`），一次性消除双账
- **验收**：002 显示"占用 30 / 还差 0（已排产）"；001 显示"占用 97 / 还差 3"；取消订单占用回吐
- **回退**：迁移前做表级 guard 备份；保留旧写入开关
- **风险**：中——动**审核 / 入库 / 发货**三条链路

### P3 · 材料层汇总 + 分摊 + 重算 —— 1~1.5 天
- **目标**：材料层看到"谁缺什么"，且随订单/供给变化更新。
- **改动范围**
  - 材料需求 = Σ(所有有效订单成品材料需求缺口展开的毛需求)（缺口用 **spot gap**）
  - 按优先级把供给依次分摊回各单（`demandMap[order.id]`），每单只背自己需求
  - 触发点：新订单审核 / 取消·关闭 / 发货 / 成品入库 / 采购到货 / 采购单取消 → 重算（短时间合并）
- **验收**：003/004 共用料场景正确；**各单缺口之和 = 全厂总缺口**；002 重算后仍有预警
- **回退**：新增逻辑，回退需清 alert
- **风险**：中，影响面扩大

### P4 · 业内增强（按需，排后面）—— 8~12 天
- 时间轴分桶（ATP by date bucket，`plan_end_date` / `expected_delivery_date`）
- pegging（占用表加"来源订单/工单"）
- 欠交台账（新表 + 生命周期 + 采购联动）
- 分配 run 批处理 + 人工干预界面
- CTP 产能可承诺（接 routing/产能）
- **风险**：高，动模型与多钩子
