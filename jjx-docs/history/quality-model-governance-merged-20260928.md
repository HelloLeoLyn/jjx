## 0. 最高优先级：建表设计规范（防"补丁表"）

**用户 2026-09-28 16:43 明确：新建表规范优先级要高，否则每个问题都会被加一张补丁表。**
（当天实证：IQC 处置按类型拆成 6 张 `inventory_iqc_*`；全库已 **124** 张表。）

### 0.1 默认拒绝 —— 以下一律不建新表
- 只是现有业务的**类型 / 状态变体**（让步/退货/返工/报废）→ 加 `action_type` 字段；
- 只是**汇总 / 派生值**（已处置量、合格量、余额）→ 由事实重算；
- **行数少、结构简单、基本不变**、只给人看 / 选 → `sys_config` / `sys_dict` / 现有表 JSON 属性（CONVENTIONS §14）；
- 只是**为了页面展示方便** → 不建表，后端出只读聚合；
- 与现有表**职责重叠 / 会成为第二真源** → 先合并。

### 0.2 允许建表 —— 必须同时满足 ≥4 条（少一条即拒绝）
1. **独立业务对象**：有**自己的生命周期 / 状态机**，且不是其他对象的类型或变体；
2. **会被引用**：会被业务单据外键引用，或会落进业务数据（不是纯配置）；
3. **关系承载**：一对多 / 多对多（类型字段或 JSON 装不下），或**需要库级约束**（唯一 / 外键 / CHECK / 区间）；
4. **规模与查询**：行数、索引、SQL 查询 / 报表需求**超出**配置 / 字典 / JSON 的承载（要 JOIN / 聚合）；
5. **治理需要**：需要**独立权限点 + 独立管理页 + 变更留痕**；
6. **不可复用**：能证明无法用现有表扩展（写清"为什么不能"）。

### 0.3 流程（缺一不可）
① 提案（模板：为什么不能复用 / 与现有表关系（主·附）/ 迁移与兼容 / 回滚 / 风险）
→ ② **用户拍板** → ③ 更新**表数基线**（当前 **124**，只许缩小，新增须写明理由并同步基线）
→ ④ 走 `scripts/db-migrate.sh`（强制先备份）。

### 0.4 门禁与反向指标
- **表数基线门禁**：脚本对比基线，新增即失败 / 告警（基线只许缩小）；
- **反向指标扫描**（出现即说明设计跑偏）：表名带类型后缀（`_scrap` / `_rework` / `_return`）；同一实体出现 ≥3 张同构表；页面按表拆 Tab；
- **落地位置**：`jjx-docs/standards/CONVENTIONS.md`（把 §14 扩成「建表闸」，或新增 §15）+ `scripts/` 门禁脚本。
- **对应任务**：**dev-20260928-020（P0）**。

## 2. 补遗（8 条）

1. **A1 报废处置不同步 NCR**：`handleQuarantine` 用 `if (!scrap)` 跳过 NCR 同步，设计上等报废单审批时由 `approveIqcScrap` 补记；但报废单原先无前端审批入口 → 缺口永久存在。实测：IN260928003-1 隔离剩余 0、NCR 待处置少 5、`quality_lot.disposed=5`（实际 10）。**迁移与对账必须包含"报废路径的延后同步"。**
2. **C2 处置动作操作日志**：`handleQuarantine` 原无 `@Log`，`sys_oper_log` 实测 0 条；**已由 dev-20260928-009 补 `@Log(IQC_QUARANTINE_DISPOSE)`**。清单里应标"已修"以免重复。
3. **C4 报废审批阈值口径**：NCR 侧有 `sys_config.quality.ncr.scrap.approval-threshold`（按额度触发审批），IQC 侧报废单**每单都待审批** → 两处口径需统一或明确差异。
4. **D3 明细 `update_time`**：`inventory_inbound_item` 原无该列（迁移 222 已加，请标注状态），且新增列要覆盖**所有写入路径**与并发覆盖问题。
5. **D7 `reject_reason` 口径**：检验侧不再要求处置方式，原因由检验项派生（`deriveIqcDefectReason`）；前端 `iqcRowRules` 与后端两处实现**必须同步**。
6. **已修项清单（避免重复开工）**：E1 大小写 `31e8e83d`；E2 报表恒 0；E3 CR/MA/MI 透传 `3be76282`；E4 洞 A/B `96319954`；E12 行金额舍入 `79c1c85e`（002）；E13 `createFromPurchase` 金额（008）。另：**老数据检验项 CR/MA/MI 分级缺失**（12:12 前提交），按"历史不补造"处理。
7. **检验批"永不 CLOSED"要露出**：采购确认入库不回写 `stored_quantity` → `closeIfSettled` 永不满足 → 来料检验批永远关不掉。修复后**页面要显示"完结 = 检验批 CLOSED"**（否则用户永远看不到"完结"）。
8. **页面层级/链路（见 §5）**：现有报告只说"不按表拆页面"，未定义层级；补：**采购订单 → 来料批次 → 材料 → 检验批 → 处置单**（含面包屑）。
