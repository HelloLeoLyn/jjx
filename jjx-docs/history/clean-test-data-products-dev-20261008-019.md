# 测试数据清理增加显式产品选项

任务：dev-20261008-019；日期：2026-10-08；执行人：codex。

## 问题与范围

现有清理脚本按 v14 规则保留产品资料，手动删产品容易留下产品库存身份。用户确认增加可选产品清理能力。本次仅实现和验证脚本，不执行实际清库或产品删除，不改变基础资料默认保留政策，也不修改政策文件。

## 行为

- 无参数仍只读预览，默认保留产品、产品分类、配置模型及选项。
- --include-products 仅适用于全量模式，不能与 --domains 混用；预览明确提示清空全部产品，不能区分正式和测试产品。它不是仅清理产品的独立模式。
- --include-products --execute 仍要求现有手工备份和终端输入库名确认；非终端/管道拒绝执行。
- 原 SQL 的四条产品清理语句使用专用注释标记，只有入口脚本激活开关才生成有效 SQL。预览和执行解析同一份临时计划，退出删除临时文件。
- 业务关联表先清理，再按 product_config_option → product_config_model → product → product_category 清理，最后执行原有的孤立 PRODUCT 库存身份 DELETE。原 DELETE 的来源及八类库存单据引用保护全部保留；MATERIAL 身份不清理。
- 产品库存身份预览按关联业务及产品清空后的完整计划计数，避免只显示当前孤儿，漏报仍有来源产品的身份。
- 从数据库元数据扫描未纳入 TRUNCATE 范围的保留表 product_id/product_code 引用；含已有悬空引用也阻断。产品相关 sys_tag_rel 关系亦阻断，不自动删除标签关系。人工确认后再检查一次。
- 查询出错展示数据库原始错误并中止，不忽略计数和覆盖率查询失败。
- 清理后核验四张产品表及全部 PRODUCT 库存身份均为零；残留返回失败。执行日志记 include_products/domains，保留失败后的执行痕迹。
