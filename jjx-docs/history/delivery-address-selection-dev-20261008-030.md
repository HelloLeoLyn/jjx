# 发货建单接入客户地址簿与公司地址

任务：2869 / dev-20261008-030；实施日期：2026-10-09；执行：Codex。

## 范围与现状

用户要求完成发货管理的收货地址候选及默认选择。合并发货重构（任务 020/021/024）已落地；客户地址簿（任务 029）已有表、查询 API 与公司地址配置。
发货建单弹窗原来仅显示订单合并后的地址输入框；多订单已有地址时输入框只读，客户地址簿和公司地址均无法选择。后端还把所选地址与每条来源订单的地址逐条比较，使多订单不能显式选用另一个统一收货地址。

## 实现

- 合并发货弹窗加载当前客户地址簿及 `company_address`，按订单地址、客户默认地址、地址簿其余地址、公司地址排序并按规范化显示地址去重。
- 默认选择上述顺序中的第一项；无候选时留空并提示手动填写。地址簿选项保留国家/省/市/街道/邮编 JSON 快照；公司地址沿用 InternationalAddress 序列化；订单地址维持原始快照。仍允许手动输入。
- 选择地址簿项时带出其联系人和电话；公司或自定义地址不沿用另一地址的联系人。
- 后端保留同客户/币种和来源订单彼此地址一致的合并约束；允许用户在建单时明确选择一个与共同来源地址不同的统一收货地址。最终选择存入发货单地址快照。
- 不改表结构、库存流水或既有数据。数据库只读核查显示 `sales_customer_address` 表存在但地址行数为 0；`ops.schema.applied` 最高 245、未登记 247。未重跑迁移或改迁移台账。
