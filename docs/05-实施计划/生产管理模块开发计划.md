### 核心问题

1. **工序执行前端使用 mock 数据**，未对接后端 API
2. **生产看板/质量/设备/路线/标准工序步骤** 只有前端页面骨架，后端完全缺失
3. **缺少生产工单下发功能**（计划→工单的转换）
4. **缺少生产追溯功能**
5. **缺少 Mapper XML 文件**（生产模块使用 MyBatis-Plus 自动映射，复杂查询需要 XML）

## 技术要点

### 1. 工序执行流程

```
工单下发 → 生成工序执行记录(按工艺路线)
                ↓
          工序1: 待执行 → 开始 → 执行中 → 完成(报工)
                ↓
          工序2: 待执行 → 开始 → 执行中 → 完成(报工)
                ↓
          工单完成(所有工序完成)
```

### 2. 关键数据关联

```
production_order (生产工单)
    └── production_operation_execution (工序执行记录)
            ├── product_standard_process (标准工序)
            ├── product_routing_item (工艺路线工序)
            └── production_operation_record (工序操作记录)
```

### 3. 需要新建的表

| 表名                                 | 说明         | 优先级 |
| ------------------------------------ | ------------ | ------ |
| `production_quality_inspection`      | 质量检验单   | 高     |
| `production_quality_inspection_item` | 检验项明细   | 高     |
| `production_equipment`               | 设备台账     | 中     |
| `production_equipment_maintenance`   | 设备保养记录 | 中     |
| `production_trace_log`               | 追溯日志     | 中     |

## 建议

1. **优先完成第一阶段**：工序执行是生产管理的核心流程，打通后可以跑通"工单→工序→报工"的完整链路
2. **第二阶段紧随其后**：工单下发是工序执行的前提，需要先实现
3. **质量管理和追溯可以并行开发**：两者数据关联紧密，建议一起设计
4. **设备管理和生产路线优先级较低**：可以先做基础 CRUD，后续再完善
