## ⚠️ 需改善项（按优先级排序）

### 1. 🔐 安全 — 不能直接上生产

**问题：** `application-dev.yml` 中硬编码了敏感信息：

```yaml
password: 123456                          # 数据库密码明文
jwt-secret-key: jjx-erp-system-secret-key-2024  # JWT 密钥硬编码
```

- JWT 密钥写在代码里，所有人都能看到
- 数据库密码生产环境不应该出现在源码中

**建议：**
- 创建 `application-prod.yml`，覆盖敏感配置
- 敏感信息走环境变量：`spring.datasource.password=${DB_PASSWORD}`
- 或使用配置中心（如 Nacos / Apollo）

---

### 2. 📦 Service 层过大

**问题：** 多个 Service 实现超过 500 行，违反单一职责：

| 类 | 行数 |
|----|------|
| `PurchaseOrderServiceImpl` | 1002 |
| `OrderReviewServiceImpl` | 898 |
| `ProductionOrderServiceImpl` | 775 |
| `InstanceLifecycleManager` | 787 |

**建议：**
- 按职责拆分为多个 Service（如 `OrderCreateService`、`OrderValidateService`）
- 或抽取 Helper/Util 类
- 原则：一个 Service 不超过 300 行

---

### 3. 🎯 TypeScript any 类型泛滥

**问题：** 298 处使用了 `any` 类型，放弃了类型检查：

```typescript
// 到处都是：
const getOrder = (orderId: number) => request.get<R<any>>(...)
const getOrderProgress = (orderId: number) => request.get<R<any>>(...)
```

**建议：**
- 定义具体返回类型替换 `any`
- 配合 `vue-tsc` 的类型检查（已有，但被 `any` 绕过了）

---

### 4. 🧪 缺少单元测试

**问题：** 整个项目 0 个有意义的单元测试。对于 ERP 这种涉及金额和库存的业务系统，风险较高。

**建议：**
- 优先给核心业务流程加测试：订单金额计算、库存扣减、BOM 成本核算
- 后端加测试即可，不用全覆盖
- 使用 Spring Boot Test + H2 内存数据库

---

### 5. 🐛 残留测试代码

**问题：** 存在无用的残代码：

```java
// TestInventoryController.java — 该删
@GetMapping("/api/test/inventory")
public Result<Void> a() { return Result.success(); }
```

**建议：**
- 清理此类死代码
- 检查是否有其他测试/调试用的遗留代码

---

### 6. 📦 单体应用

**注意点：** Spring Boot 单体应用，527 个 Java 文件编译成一个 jar。

**不建议拆微服务**（业务复杂度不够，且部署环境只有 2C4G），但可以：
- 将 `common` 和 `framework` 拆为 Maven module
- 业务模块之间通过接口依赖
- 为以后需要拆微服务时留好接口边界

---

### 7. 🐳 缺少容器化配置

**问题：** 部署方式仍为手动 `mvn spring-boot:run` + `pnpm dev`

**建议：**
- 加 `Dockerfile` / `docker-compose.yml`
- 数据库 + Redis + 后端 + 前端 一键启动
- 降低新环境搭建成本
